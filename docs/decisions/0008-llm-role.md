# 0008. LLM role: none in the MVP, advisory memo at most, never a number and never an order

**Status:** Proposed  ·  **Date:** 2026-09-25  ·  **Issue:** #52

## Context

The Phase 1 exit criteria ([roadmap](../roadmap.md)) require an ADR on the LLM role "even if the answer is none yet". None of ADRs 0001–0007 records one, so the question has stayed open into Phase 2. It has three parts in the handoff ([§12](../research/2026-09-24-initial-research-handoff.md) items 8–10): whether there is an LLM layer at all and with what **authority**; **model selection** (frontier, open-weight or point-in-time, pinning, fallback); and **evaluation** (post-cutoff scoring, calibration, sample size, counterfactuals, drift). This ADR decides authority and the gate to Phase 5, and fixes the constraints the Phase 5 spec must satisfy for the other two. It does not choose a vendor or a model: that is a separate ADR at Phase 5 start, per the "always requires an ADR" rule in [development-process.md](../ways-of-working/development-process.md).

This is about LLM components **inside** TradePartner at run time. The Claude Code agents that build the repo are out of scope ([agents.md](../ways-of-working/agents.md) draws that line).

**What is already fixed and this ADR cannot loosen:**
- Charter principle 1: any edge comes from strategy, data or discipline, not from using an LLM. Principle 3 and process rules 4–5: code computes numbers, LLMs never produce a number that feeds a decision, and no code path lets model output reach the broker without passing deterministic risk rules. Rule 5 leaves "LLM authority beyond that" to an ADR: this one.
- The charter defers the LLM analyst layer beyond the MVP (Phases 2–4), and the roadmap puts it in Phase 5, "only if an ADR says so", with the note that its first job, if any, is process discipline (a pre-mortem on owner overrides), not prediction.
- Spend by the running system is **$0/month** until the Phase 3 vendor ADR sets a ceiling for data, APIs and LLM calls together (charter, [ADR 0005](0005-objective-benchmark-stop-criteria.md)).
- [ADR 0005](0005-objective-benchmark-stop-criteria.md) ranks calibration second among objectives "once anything in the system emits probabilities" and says it becomes primary if the LLM layer enters scope. It also requires paper to track the backtest within `paper.tracking_k` × modeled cost at Phase 4 exit.

**What the research says** (handoff [§8](../research/2026-09-24-initial-research-handoff.md), sources graded there; nothing here is new evidence):
- *Document analysis:* the best models answer about 59–61% of held-out SEC-filing analyst questions (Vals Finance Agent v2, independent); the top models still fail about 40% of tasks and the ranking changes within weeks.
- *Forecasting:* frontier models reach parity with superforecasters only as engineered ensembles (ForecastBench, July 2026); good calibration (Prophet Arena calibration error ≤ 0.05) but an average return below break-even against the market.
- *Trading:* no consistent evidence that capability turns into P&L. Alpha Arena rankings inverted between seasons; StockBench (post-cutoff) found most models fail to beat buy-and-hold; Profit Mirage found Sharpe decay of 51–62% after the training cutoff for GPT-4o-based trading agents.
- *Contamination:* any backtest of an LLM on dates before its training cutoff is inflated by memorization, and instructions or masking do not prevent recall (Lopez-Lira, Tang and Zhu; MemGuard-Alpha; NumLeak). So an LLM component **cannot be backtested honestly**; it can only be evaluated forward, post-cutoff.
- *Point-in-time models* (ChronoGPT, DatedGPT, Kelly et al.) are leak-free by construction but are 1–4B parameters with IFEval around 25–31%; their results come from headline sentiment and embeddings, not multi-document memos.
- *Operations:* temperature-0 API calls are not reproducible (80 distinct completions in 1,000 identical requests in one test); vendors reprice, retire and silently re-route models; Fable/Mythos access was suspended for 19 days in June 2026; a memo on a 20K-token packet costs about $0.35 per call at list prices.
- *Gap* ([§11](../research/2026-09-24-initial-research-handoff.md)): no study exists of an LLM as a **veto** layer on a quant shortlist using post-cutoff data only. The one use the owner was most interested in has no evidence either way.
- *Risks* ([§10](../research/2026-09-24-initial-research-handoff.md)): prompt injection via scraped content, nondeterminism, silent re-routing, vendor outages, cost accumulation, contaminated evaluation, and persuasive but wrong reasoning.

The owner's original interest (handoff §2) was a hybrid: a quant strategy plus external data, "with an LLM helping make informed decisions". The forces to balance are that interest, the evidence that the help is unproven for prediction, the operational risks, and a $0 budget.

## Options considered

1. **None for the MVP.** No LLM call anywhere in the running system through Phases 2, 3, 4 and 6. Pro: matches the evidence and charter principle 1; $0; no prompt-injection surface; every decision in the journal is reproducible from stored inputs; nothing to pin or version. Con: the owner's hybrid interest waits; no calibration record accumulates, so the question "does a memo help" cannot be answered from our own data; Phase 5 stays an empty placeholder.
2. **Advisory memo only (Phase 5).** An LLM reads a fixed input packet that code assembles from the point-in-time store and writes a structured memo (thesis, bear case, a probability, invalidation criteria) shown next to the signal it comments on. No code path consumes the memo; its only reader is the owner. Pro: builds exactly the post-cutoff, forward evaluation record the research says is missing, with zero authority over the portfolio; the operational risks are bounded (a wrong or missing memo changes nothing the system does); calibration becomes measurable, which ADR 0005 already anticipates. Con: costs money, so it needs a budget ceiling above $0; a memo can still steer the owner through an override, a hidden channel from model output to orders; nondeterminism and re-routing make a memo non-reproducible; the record accrues at 12 rebalances a year, so it takes years to say anything about outcomes.
3. **Veto with logged counterfactuals.** The LLM may remove names from the code-computed shortlist; the removed names' outcomes are tracked as counterfactuals. Pro: the only option where the LLM affects P&L while still never producing a number or placing an order; counterfactual tracking makes it evaluable in principle. Con: a veto **is** a portfolio decision, so model nondeterminism, contamination, injection and outages all become portfolio risks; it cannot be backtested (contamination), so its only evaluation is live, and with a monthly cadence a discriminating test takes years; it breaks the ADR 0005 paper-versus-backtest tracking check by construction, because the backtest cannot contain the vetoes; and there is no evidence for it (§11 gap). Adopting it now would be building the one component the research explicitly could not assess.
4. **LLM as a signal source or order placer** (sentiment scores, "agentic" trading like Alpha Arena). Rejected outright by rules 4 and 5 and charter principle 3, and the trading evidence (Alpha Arena, StockBench, Profit Mirage) is against it. Listed so the rejection is on record; not considered further.

## Decision

We will take option 1 now, define option 2 as the **only** form the LLM layer may take when it enters scope in Phase 5, and keep option 3 closed until a further ADR cites forward evidence from option 2.

1. **Authority in the MVP: none.** Phases 2, 3, 4 and 6 run with no LLM call in the runtime. There is no `src/tradepartner/llm/` package, no `llm` config section and no LLM SDK among the runtime dependencies in `pyproject.toml` until the Phase 5 spec and the Phase 5 model ADR are accepted. A PR that adds an LLM client or an LLM SDK dependency before then is out of scope by this ADR, and `safety-reviewer` runs on it regardless (it touches LLM inputs). The build agents in `.claude/agents/` are not affected.

2. **The only authority ever granted without a new ADR is advisory.** "Advisory" means precisely: the memo's sole consumer is the owner, through the dashboard, next to the signal it comments on. No code path reads a memo to compute anything that feeds the decision, order or fill tables. The memo table is written by the LLM module and read only by the dashboard and the scoring job. The memo's probability is **scored, never consumed**: it is a forecast to be calibrated, not an input. This keeps rules 4 and 5 true by construction, not by review.

3. **The hidden channel is logged, not denied.** An owner override that follows a memo is still an owner override (rule 8): it is logged with a reason, and the journal row records the id of every memo the owner had on screen at the time. "Overrides after a memo" is then a query, and a process metric under ADR 0005 objective 1. The first Phase 5 deliverable is the use the roadmap names: a **pre-mortem on an owner override**, generated when the owner opens the override screen, shown before the override is confirmed, and logged with it. The per-signal memo on a fixed input packet is the second deliverable. The Phase 5 spec orders the two, and may ship them together; it may not ship the per-signal memo without the override linkage in point 3.

4. **Constraints the Phase 5 spec must satisfy** (handoff §12 items 8–10, decided here at the level of rules; the spec fills in the mechanics):
   - *Input packet:* assembled by code from the store as of the rebalance timestamp T using the as-of API only, so the memo cannot see anything the strategy could not. Any free text in the packet (a filing excerpt, later a news item) comes from the point-in-time store with its `known_at`, never from a live fetch at memo time, and is wrapped and labelled as untrusted data in the prompt. Prompt injection can then at worst corrupt a memo, which has no authority; `safety-reviewer` checks the wrapping.
   - *Output schema:* structured and validated; the probability is a number the model wrote about the future, displayed and scored, never a number the system computes with (rule 4 is about numbers that feed decisions, and this one feeds none).
   - *Point-in-time:* a memo is a stored fact with `known_at` = its generation time (rule 6). Memos are generated **forward only**, at or after the rebalance they comment on. Historical memos are never backfilled, and the backtest engine and trial registry have no memo input, so no memo can ever appear in a backtest. This is the "post-cutoff-only evaluation" the roadmap's Phase 5 exit requires, made true by construction.
   - *Every memo row logs:* model id as returned by the API (not as requested, so a silent re-route is visible), prompt template version, a hash of the full input packet, the full input and output text, token counts and cost. Nondeterminism is accepted and measured: a **drift probe** re-sends a stored packet on a schedule the spec sets and records the distance between outputs.
   - *Calibration:* Brier score of the memo's probability at the cadence horizon (one month, [ADR 0006](0006-universe-and-cadence.md)), plus reliability by bucket, on the review page. Per ADR 0005 this becomes the primary objective for the LLM layer. The spec states the minimum number of scored memos before any calibration figure is reported as more than provisional, and registers that number before the first memo is generated.
   - *Fallback:* a missing memo (outage, cost cap reached, validation failure) changes nothing: the run proceeds and the dashboard shows "no memo". An LLM failure is **not** a system fault under [ADR 0007](0007-clock-failures-halt-path.md) and never enters the halt path, because nothing depends on the memo.
   - *Cost:* a monthly cap from config; the cap is at most the LLM share of the ceiling the Phase 3 vendor ADR sets; when reached, memos are skipped, not queued.

5. **Model selection is deferred to a Phase 5 ADR, with these bounds.** Because the memo is advisory, reproducibility is a logging requirement, not a correctness one, so a hosted frontier or open-weight model is acceptable if pinned and logged as in point 4. Point-in-time models are **not** candidates for the memo role: their instruction-following is too weak for it. They stay a candidate for a news-text *signal*, which is a different deferred item in the roadmap with its own ADR, where their leak-free property is the point. The model ADR also decides local versus hosted against the budget ceiling, and names a fallback model or "skip", never a silent substitute.

6. **Entering Phase 5 requires all of:** Phase 4 exit criteria met (the memo needs a journal and an override log to attach to, and at least 6 unattended paper rebalances show the plain system works without it); a budget ceiling for LLM spend above $0 from the Phase 3 vendor ADR, or a charter amendment; the Phase 5 spec accepted with points 2–4 as acceptance criteria and `spec-critic` run; and the Phase 5 model ADR accepted. The owner enters Phase 5 by merging the spec; no further "should there be an LLM layer" ADR is needed for the advisory form.

7. **Veto, or any authority beyond advisory, needs a new ADR** that cites a **pre-registered** test (in the trial registry, registered before the memos it scores were generated) over the advisory record, showing at minimum that memo probabilities are calibrated and that they separate outcomes from the unconditional base rate, with the sample size and threshold fixed at registration. That ADR must also replace the ADR 0005 paper-versus-backtest tracking check with one that accounts for vetoes, since the backtest cannot contain them, and must extend the counterfactual journal to every vetoed name. Independent post-cutoff evidence of an LLM veto layer adding net value (the §11 gap) would strengthen such an ADR but does not replace our own record.

**What each option rejects, for the record.** Option 1 rejects using the owner's interest in a hybrid as a reason to add an unproven component to money-handling code. Option 2 rejects any authority for the model and rejects backtesting it at all. Option 3 is rejected now for lack of evidence and because it would break the paper-tracking check; it is not rejected forever. Option 4 is rejected by the charter and stays rejected.

## Consequences

- Good: the MVP has no injection surface, no nondeterminism in the decision path, no vendor dependency and no LLM spend, and the exit criterion is met with an answer of "none yet" that says exactly what "yet" means. The one thing the research could not assess (an LLM on a quant shortlist, post-cutoff) gets assessed with our own forward record before it can touch the portfolio. The advisory rules are structural (which tables read which), so review does not have to catch a leak. The pre-mortem targets the behavioral risks in §10, where a small account is most likely to lose discipline rather than money.
- Bad / accepted risks: the owner's hybrid waits until after Phase 4, at least six months of paper rebalances away. The advisory memo can still move the owner; that channel is accepted because it is logged and measurable, and an owner who overrides on a memo's say-so is doing what the override log exists to show. Memos cost money and need a budget amendment. At 12 rebalances a year the calibration record grows slowly, so the door to veto stays closed for years even if the memo turns out to be good; that is intended. A memo cannot be reproduced bit-for-bit after the fact; what is reproducible is its input, and the drift probe measures how much that matters.
- Reversibility: cheap now, there is no code. Cheap for Phase 5 in the advisory form, because removing a component nothing depends on is a deletion. Costly beyond that: once model output affects the portfolio, the paper-versus-backtest tracking rule, the journal schema and the risk wrapper's contract all change, which is why point 7 requires a new ADR.
- Revisit if: the Phase 3 vendor ADR sets LLM spend to zero for good (then Phase 5 is dropped from the roadmap, not just deferred); a vendor offers verifiable pinning and determinism at acceptable cost (the logging burden drops); independent post-cutoff evidence appears for an LLM veto on quant shortlists; the advisory record meets a pre-registered test under point 7; or the owner's budget or objective changes materially (ADR 0005 "revisit if").
