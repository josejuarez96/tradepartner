# 0008. LLM role: none in the MVP, advisory memo at most, never a number and never an order

**Status:** Proposed  ·  **Date:** 2026-09-25  ·  **Issue:** #52

## Context

The Phase 1 exit criteria ([roadmap](../roadmap.md)) require an ADR on the LLM role "even if the answer is none yet". None of ADRs 0001–0007 records one, so the question has stayed open into Phase 2. It has three parts in the handoff ([§12](../research/2026-09-24-initial-research-handoff.md) items 8–10): whether there is an LLM layer at all and with what **authority**; **model selection** (frontier, open-weight or point-in-time, pinning, fallback); and **evaluation** (post-cutoff scoring, calibration, sample size, counterfactuals, drift). This ADR decides authority and the gate to Phase 5, and fixes the rules the Phase 5 spec must satisfy for the other two. It does not choose a vendor or a model: that is a separate ADR at Phase 5 start, per the "always requires an ADR" rule in [development-process.md](../ways-of-working/development-process.md).

The subject is LLM components **inside** TradePartner at run time, plus one rule (Decision point 3) on values that LLMs produce while building it. The Claude Code agents themselves are otherwise out of scope ([agents.md](../ways-of-working/agents.md) draws that line).

**What is already fixed and this ADR cannot loosen:**
- Charter principle 1: any edge comes from strategy, data or discipline, not from using an LLM. Principle 3 and process rules 4–5: code computes numbers, LLMs never produce a number that feeds a decision, and no code path lets model output reach the broker without passing deterministic risk rules. Rule 5 leaves "LLM authority beyond that" to an ADR: this one.
- The charter defers the LLM analyst layer beyond the MVP (Phases 2–4), and the roadmap puts it in Phase 5, "only if an ADR says so", with the note that its first job, if any, is process discipline (a pre-mortem on owner overrides), not prediction.
- The dashboard reads the system's own database; its only write is a logged override with a reason (charter, "Interface"; roadmap, "User experience").
- Spend by the running system is **$0/month** until the Phase 3 vendor ADR sets a ceiling for data, APIs and LLM calls together (charter, [ADR 0005](0005-objective-benchmark-stop-criteria.md)).
- [ADR 0005](0005-objective-benchmark-stop-criteria.md) ranks calibration second among objectives "once anything in the system emits probabilities" and says it becomes primary if the LLM layer enters scope. It also requires paper to track the backtest within `paper.tracking_k` × modeled cost at Phase 4 exit.

**What the research says** (handoff [§8](../research/2026-09-24-initial-research-handoff.md), sources and tiers as graded there; nothing here is new evidence):
- *Document analysis:* the best models answer about 59–61% of held-out SEC-filing analyst questions (Vals Finance Agent v2, independent); the top models still fail about 40% of tasks and the ranking changes within weeks.
- *Forecasting:* frontier models reach parity with superforecasters only as engineered ensembles (ForecastBench, July 2026); strong models are well calibrated (Prophet Arena calibration error ≤ 0.05) but earned an average return below break-even against the market.
- *Trading:* no consistent evidence that capability turns into P&L. StockBench (post-cutoff) found most models fail to beat buy-and-hold; Profit Mirage found Sharpe decay of 51–62% after the training cutoff for GPT-4o-based trading agents. Alpha Arena rankings reportedly inverted between seasons, but that rests on Tier 3 news relays, not Nof1's primary data (handoff §11).
- *Contamination:* a backtest of a frontier or hosted LLM on dates before its training cutoff is inflated by memorization, and instructions or masking do not prevent recall (Lopez-Lira, Tang and Zhu; MemGuard-Alpha; NumLeak). Such a component **cannot be backtested honestly**; it can only be evaluated forward, post-cutoff.
- *Point-in-time models* (ChronoGPT, DatedGPT, Kelly et al.) are leak-free by construction but are 1–4B parameters with IFEval around 25–31%; their results come from headline sentiment and embeddings, not multi-document memos.
- *Operations:* temperature-0 API calls are not reproducible (80 distinct completions in 1,000 identical requests in one test); vendors reprice, retire and silently re-route models; Fable/Mythos access was suspended for 19 days in June 2026; a memo on a 20K-token packet costs about $0.35 per call at list prices.
- *Gap* ([§11](../research/2026-09-24-initial-research-handoff.md)): no study exists of an LLM as a **veto** layer on a quant shortlist using post-cutoff data only. The use the owner was most interested in has no evidence either way.
- *Risks* ([§10](../research/2026-09-24-initial-research-handoff.md)): prompt injection via scraped content, nondeterminism, silent re-routing, vendor outages, cost accumulation, contaminated evaluation, and persuasive but wrong reasoning.

The owner's original interest (handoff §2) was a hybrid: a quant strategy plus external data, "with an LLM helping make informed decisions". The forces to balance are that interest, the evidence that the help is unproven for prediction, the operational risks, and a $0 budget.

## Options considered

1. **None for the MVP.** No LLM call anywhere in the running system. Pro: matches the evidence and charter principle 1; $0; no prompt-injection surface; every decision in the journal is reproducible from stored inputs; nothing to pin or version. Con: the owner's hybrid interest waits; no calibration record accumulates, so "does a memo help" cannot be answered from our own data; Phase 5 stays an empty placeholder.
2. **Advisory memo only (Phase 5).** An LLM reads a fixed input packet that code assembles from the point-in-time store and writes a structured memo (for example a pre-mortem, a bear case, a probability on a pinned event, invalidation criteria), shown to the owner next to the decision it comments on. No code path consumes the memo. Pro: builds exactly the post-cutoff, forward evaluation record the research says is missing, with no authority over the portfolio; the operational risks are bounded, because a wrong or missing memo changes nothing the system does; calibration becomes measurable, as ADR 0005 anticipates. Con: costs money, so it needs a budget ceiling above $0; a memo can still steer the owner through an override, an indirect channel from model output to orders; nondeterminism and re-routing make a memo non-reproducible; the record accrues at 12 rebalances a year, so it takes years to say anything about outcomes.
3. **Veto with logged counterfactuals.** The LLM may remove names from the code-computed shortlist; the removed names' outcomes are tracked as counterfactuals. Pro: the only option where the LLM affects P&L while still never producing a number or placing an order; counterfactual tracking makes it evaluable in principle. Con: a veto **is** a portfolio decision, taken every month by design, so model nondeterminism, contamination, injection and outages all become portfolio risks; it cannot be backtested (contamination), so every month it acts, paper diverges from the backtest by construction, and its only evaluation is live, which at a monthly cadence takes years; there is no evidence for it (§11 gap). Adopting it now would build the one component the research explicitly could not assess.
4. **Any other role where model output feeds the system.** This covers an LLM as a signal source (sentiment scores), as an order placer ("agentic" trading like Alpha Arena), and as an **extractor** that pulls facts or numbers out of filings or text into the store. Rejected by rules 4 and 5 and charter principle 3: each makes a model-produced value an input to a decision. The trading evidence (StockBench, Profit Mirage) is also against the first two. Structured facts come from structured sources, parsed by code (the `FilingSource` path). Listed so the rejection is on record; not considered further.

## Decision

We will take option 1 now, define option 2 as the **only** form the LLM layer may take when it enters scope, and keep option 3 closed until a further ADR cites forward evidence from option 2.

1. **No LLM in the runtime until Phase 5 is entered.** Whatever phase the project is in, the running system makes no LLM call until the Phase 5 spec and the Phase 5 model ADR are accepted (point 7). There is no `src/tradepartner/llm/` package, no `llm` config section and no LLM SDK among the runtime dependencies in `pyproject.toml` before then. Phase 6 does not wait for Phase 5: live may start after Phase 4 with no LLM layer. If Phase 5 is entered, before or after Phase 6, the advisory rules below apply to paper and live alike. A PR that adds an LLM client or an LLM SDK dependency before Phase 5 is out of scope by this ADR, and `safety-reviewer` runs on it regardless.

2. **The only authority ever granted without a new ADR is advisory.** "Advisory" means precisely: the memo's sole consumer is the owner, through the dashboard. No code path reads a memo to compute anything that feeds the decision, order or fill tables, or the risk-gated wrapper. The memo table is written only by the memo job and read only by the dashboard and the scoring job. A memo's probability is **scored, never consumed**: it is a forecast to be calibrated, not an input. This is enforced, not left to review:
   - a test scans the imports of every module outside `tradepartner.llm` (and outside the dashboard and scoring modules) and fails if any imports `tradepartner.llm` or reads the memo table;
   - a test fails if `pyproject.toml`'s runtime dependencies contain an LLM SDK while `tradepartner.llm` does not exist (the point-1 ban, checkable today).

   The Phase 5 plan may swap the import scan for an import-linter contract, adopted through ADR 0004's process.

3. **No LLM-produced value feeds a decision, even at build time.** Rule 4 covers LLMs used to build the system as well as ones inside it. A value an LLM produced (a mapping table, a sector label, a threshold, a corrected price) enters the store or config only through a reviewed code or config change whose PR states the value's source, and only if that source is a human decision or a record with a `known_at`. Build agents write code and hand-built test fixtures; they never write generated data that the runtime loads.

4. **The memo job and its relation to the order path.**
   - Memos are generated by a **separate batch job**, run after the rebalance's decisions are committed. The order path never waits for it, never calls it and never reads its output; a test shows that the job failing or hanging leaves the run's decisions and orders unchanged. An LLM failure is **not** a system fault under [ADR 0007](0007-clock-failures-halt-path.md) and never enters the halt path.
   - The dashboard makes **no LLM call**. It displays stored memos, in keeping with the charter's read-only interface. The override screen shows whatever memos exist for the decision being overridden; if there are none, it says so.
   - An override is **never blocked or delayed** by the memo layer: no memo, a stale memo or an outage all leave the override screen working exactly as it does in Phase 4.
   - Every override, including one that follows a memo, passes the risk-gated wrapper like any other order ([ADR 0003](0003-data-adapters-local-first.md) rule 7, process rule 5).

5. **The indirect channel is logged, not denied.** An owner override that follows a memo is still an owner override (rule 8): it is logged with a reason, and the override row records the id of every memo on screen at the time. "Overrides after a memo" is then a query and a process metric under ADR 0005 objective 1. The first Phase 5 deliverable is the one the roadmap names: a **pre-mortem** for each decision in the target set, generated by the batch job and shown on the override screen before an override is confirmed. A pre-mortem is not a forecast and is not scored for calibration; it is measured through override behavior (how often overrides follow one, and how overridden decisions performed against the system's). The per-decision memo with a probability is the second deliverable. The Phase 5 spec may ship them together, but may not ship the second without the override linkage.

6. **Rules the Phase 5 spec must satisfy** (handoff §12 items 8–10, decided here as rules; the spec supplies the mechanics):
   - *Input packet:* assembled by code from the store as of the rebalance timestamp T, through the as-of API only, so a memo sees nothing the strategy could not. Any free text in the packet (a filing excerpt, later a news item) comes from the point-in-time store with its `known_at`, never from a fetch at memo time, and is wrapped and labelled as untrusted data in the prompt. Memo calls run with **tools, browsing and retrieval disabled**, so the model cannot pull in data from outside the packet. Prompt injection can then at worst corrupt a memo, which has no authority; `safety-reviewer` checks the wrapping and the disabled tools.
   - *Target set:* which decisions get a memo (every shortlist name, only changes, only positions) is the spec's choice, sized against the cost cap. The order of magnitude: at $0.35 a memo, 100 memos a rebalance is about $35 a month, about $420 a year before drift probes.
   - *Output schema:* structured and validated. The **event a probability refers to is pinned in the schema** (for example "this name's total return beats SPY's over the one-month hold") and registered in the trial registry before the first memo is generated, so the forecast target cannot be chosen after the outcome.
   - *Point-in-time and scoring:* a memo is a stored fact with `known_at` = its generation time (rule 6). Memos are generated **forward only** and never backfilled; the backtest engine and trial registry have no memo input, so no memo can appear in a backtest. A memo is **scored only if its `known_at` is before the first order submission of the rebalance it comments on**; a later memo (after an outage, say) is displayed, flagged late and excluded from scoring. This is the "post-cutoff-only evaluation" the roadmap's Phase 5 exit requires, made true by construction.
   - *Every memo row logs:* model id as returned by the API, prompt template version, a hash of the full input packet, the full input and output text, token counts and cost. The returned id catches re-routes the vendor reports; a silent re-route leaves it unchanged, so the **drift probe** is the only check for those. The probe re-sends a stored packet on a schedule the spec sets and records the distance between outputs. Probe outputs are stored apart from memos, never displayed as memos and never scored.
   - *Calibration:* Brier score of the memo probability on the pinned event at the cadence horizon (one month, [ADR 0006](0006-universe-and-cadence.md)), plus reliability by bucket, on the review page. Per ADR 0005 this becomes the primary objective for the LLM layer. The spec registers, before the first memo, the minimum number of scored **rebalances** (not memos: memos from one month share a market and are correlated) before any calibration figure is reported as more than provisional.
   - *Fallback:* a missing memo (outage, cost cap reached, validation failure) changes nothing: the dashboard shows "no memo".
   - *Cost:* a monthly cap from config, at most the LLM share of the ceiling the Phase 3 vendor ADR sets. When the cap is reached, memos are skipped, not queued.

7. **Entering Phase 5 requires all of:** Phase 4 exit criteria met (the memo needs a journal and an override log to attach to, and 6 unattended paper rebalances show the plain system works without it); an LLM spend ceiling above $0, from the Phase 3 vendor ADR or a charter amendment; the Phase 5 model ADR accepted; and the Phase 5 spec accepted with points 2–6 as acceptance criteria and `spec-critic` run. The owner enters Phase 5 by merging the spec; no further "should there be an LLM layer" ADR is needed for the advisory form.

8. **Recommendations to the Phase 5 model ADR, not decisions.** Because the memo is advisory, reproducibility is a logging requirement, not a correctness one, so a hosted frontier or open-weight model looks acceptable if pinned and logged as in point 6. Point-in-time models look too weak at instruction-following for memos, and better suited to a news-text *signal*, which is a separate deferred roadmap item with its own ADR, where their leak-free property is the point. The model ADR decides these, plus local versus hosted against the budget ceiling, and names a fallback model or "skip", never a silent substitute.

9. **Veto, or any authority beyond advisory, needs a new ADR.** It must cite a test **pre-registered** in the trial registry before the memos it scores were generated, over the advisory record, showing at minimum that memo probabilities are calibrated and that they separate outcomes from the unconditional base rate. The sample size, the threshold and the handling of within-rebalance correlation (the unit is the rebalance, or the test clusters by it) are fixed at registration. That ADR must also say how the ADR 0005 paper-versus-backtest tracking check treats veto months, since the backtest cannot contain the vetoes, and must extend the counterfactual journal to every vetoed name. Independent post-cutoff evidence of an LLM veto layer adding net value (the §11 gap) would strengthen such an ADR but does not replace our own record.

**What each option rejects, for the record.** Option 1 rejects using the owner's interest in a hybrid as a reason to add an unproven component to money-handling code. Option 2 rejects any authority for the model and rejects backtesting it at all. Option 3 is rejected now for lack of evidence and because it would put a monthly, automated divergence from the backtest into the portfolio; it is not rejected forever. Option 4 is rejected by the charter and stays rejected.

## Consequences

- Good: the MVP has no injection surface, no nondeterminism in the decision path, no vendor dependency and no LLM spend, and the exit criterion is met with an answer of "none yet" that says exactly what "yet" means. The one thing the research could not assess (an LLM on a quant shortlist, post-cutoff) gets assessed with our own forward record before it can touch the portfolio. The advisory boundary is a test, not a reviewer's memory. The pre-mortem targets the behavioral risks in §10, where a small account is most likely to lose discipline rather than money.
- Bad / accepted risks: the owner's hybrid waits until after Phase 4, at least six months of paper rebalances away. The advisory memo can still move the owner; that channel is accepted because it is logged and measurable, and an owner who overrides on a memo's say-so is exactly what the override log exists to show. Memos cost money and need a budget above $0. At 12 rebalances a year the calibration record grows slowly, so the door to veto stays closed for years even if the memo turns out to be good; that is intended. A memo cannot be reproduced bit-for-bit after the fact; its input can, and the drift probe measures how much the difference matters.
- Reversibility: cheap now, there is no code. Cheap for Phase 5 in the advisory form, because removing a component nothing depends on is a deletion. Costly beyond that: once model output affects the portfolio, the paper-versus-backtest tracking rule, the journal schema and the risk wrapper's contract all change, which is why point 9 requires a new ADR.
- Revisit if: the Phase 3 vendor ADR sets LLM spend to zero for good (then Phase 5 is dropped from the roadmap, not just deferred); a vendor offers verifiable pinning and determinism at acceptable cost (the logging burden drops); independent post-cutoff evidence appears for an LLM veto on quant shortlists; the advisory record passes a pre-registered test under point 9; or the owner's budget or objective changes materially (ADR 0005 "revisit if").
