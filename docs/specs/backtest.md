# Spec: Backtest engine and trial registry (Phase 3)

**Status:** Draft  ·  **Issue:** #51  ·  **Related:** [ADR 0003](../decisions/0003-data-adapters-local-first.md) (rules 5, 6, 8), [ADR 0004](../decisions/0004-tooling-adopt-avoid.md) (engine, oracle, metrics), [ADR 0005](../decisions/0005-objective-benchmark-stop-criteria.md), [ADR 0006](../decisions/0006-universe-and-cadence.md), [roadmap Phase 3](../roadmap.md), [data-foundation spec](data-foundation.md), [handoff](../research/2026-09-24-initial-research-handoff.md) §7 D1 and §12 item 7, [trial registry](../research/trial-registry.md), research [G1](../research/2026-09-25-g1-momentum-post-2010.md) (PR #61, unmerged at drafting), [G3](../research/2026-09-25-trend-timing.md), [G4](../research/2026-09-25-g4-signal-combination.md), [G8](../research/2026-09-25-price-vendors.md), [free-data terms](../research/2026-09-25-free-data-terms.md)

## Problem & why now

Phase 2 answers "what was knowable at T?". Phase 3 asks the next question honestly: *how would a rule have done, using only what was knowable at each step, net of costs, with every attempt counted?* This spec builds the backtest engine, the cost model, the locked holdout, the trial registry in the store, deflated Sharpe reporting, the `bt` oracle check, the `backtest` CLI and the two dashboard pages. It is where charter principles 2, 4 and 6 (count every trial, point-in-time data, tune on process not P&L) become code with tests.

The first registered hypothesis is the MVP strategy from the roadmap: long-only, monthly-rebalanced 12-1 momentum on the ADR 0006 universe, against SPY and MTUM buy-and-hold. The evidence (G1) puts its net excess return near zero, so the point of Phase 3 is a correct, auditable engine, not a good number.

## Users & usage

- **The owner** registers a hypothesis by merging its file and running `tradepartner hypothesis register`, runs `tradepartner backtest <hypothesis>` from time to time, and reads the backtest page and the trial-registry view. Only the owner spends the holdout, overrides the gap gate, signs off on the gap, writes the price-vendor ADR and runs anything against the real store (CLAUDE.md rule 9: agents never enter the main checkout).
- **The `backtest-runner` agent** (candidate in [agents.md](../ways-of-working/agents.md)) runs a registered hypothesis **only on a temp-file or fixture store** (synthetic trials, `store_path` set explicitly) and reports. Its trials never enter the owner's N and V, it never runs on the real store, and it never passes a holdout or override flag.
- **Phase 4** reads trial results to compare paper returns with the backtest (ADR 0005, `paper.tracking_k`) and needs the owner's gap sign-off row (ADR 0003 rule 8).
- **Tests**, on every PR, run the engine on the fixture universe with the network disabled, including the truncation-invariance suite and the `bt` oracle.

## Definitions

- **Rebalance session** T_i: the last XNYS session of a calendar month (ADR 0006), from `calendar.last_session_of_month`. **T** as an instant is close(T_i) (`calendar.session_close`), tz-aware UTC, as in the Phase 2 spec.
- **Fill session** F_i = `calendar.next_session(T_i)`. The fill price is F_i's open or close per `execution.fill_price` (ADR 0006; `close` since T3).
- **Step** i: the work done at read time close(T_{i+1}) for the holding month (F_i, T_{i+1}]: value the month, then compute the next signal and targets. Every provider read of a run uses a rebalance close as `t`.
- **Data cutoff** of a run: close of its last rebalance session. Nothing is read with a later `t`.
- **Month i return**: equity at close(T_{i+1}) over equity at close(T_i), minus one. Monthly returns are the unit for Sharpe, skew, kurtosis and the ADR 0005 paper-tracking check. `MONTHS_PER_YEAR = 12` is a constant derived from the ADR 0006 cadence, not config.
- **Hypothesis**: a file under `docs/hypotheses/` with an economic rationale, a fixed parameter set including its holdout window, expected magnitudes, the prior evidence already seen for the holdout period, and a retirement condition, registered in the store before any run (domain rule 1). Each belongs to a **family** from the enumerated `hypotheses.families` list, the unit for counting trials and holdout spends.
- **Trial**: one engine run, from the moment the registry issues a trial handle. Failures, refusals, crashes and reruns are trials. **Kind** ∈ `in_sample`, `holdout`, `tracking` (Phase 4's paper-period comparison; reserved here, never counted as holdout). A **synthetic** trial runs on a store whose file is not `settings.store.path` (tests, the oracle) and is excluded from the trial count (ADR 0004); the CLI cannot create one, and the registry refuses `synthetic=True` or `family=oracle` on the real store.
- **In-sample window**: from the hypothesis's `in_sample_start` to the last rebalance session before its frozen `holdout.start`. **Holdout window**: the hypothesis's frozen `[holdout.start, holdout.end]`, both dates named in the file. Sessions after `holdout.end` belong to Phase 4 tracking and are refused here.
- **Series**: `strategy`, `SPY`, `MTUM` (from `benchmarks`). Benchmarks are buy-and-hold, total return, under the same fill convention and cost model (ADR 0005), so their only trade cost is the initial buy. *Amendment 2026-10-06 (#1074, [ADR 0014](../decisions/0014-strategies-as-registered-objects.md) point 4):* a family's registry entry may add one comparison benchmark of its own as a fourth series, with `excess_cagr_<name>` and `tracking_error_<name>` keys; SPY and MTUM stay required for every family (strategy-interface plan T129).

## Requirements

1. **Engine over the as-of API only.** The engine reads market data through a `DataProvider` protocol whose every method takes a tz-aware `t`. The store-backed provider calls only `store.asof`, `store.master`, `store.delistings`, `universe.universe_as_of` and `gap.survivorship_gap`, passing the trial's frozen `Settings` into every call, never an adapter. It opens a **short-lived read-only connection per step** (from a connection factory) so a long run never holds the store against the ingest job. At step i, with `t = close(T_{i+1})`, it reads: the **marking frame** `adjusted_prices_as_of(t, held ∪ benchmark ids, include_dividends=True)` for the sessions F_i..T_{i+1}; the universe `universe_as_of(t)`; the **signal frame** `adjusted_prices_as_of(t, universe ids, include_dividends=strategy.signal_total_return)`; listing ends; dropped dividends; late dividends (req 5); the survivorship gap. The provider is read once per step and every cost level is evaluated from the same reads. A rebalance date is a calendar output, never a weekday rule.
   *Amendment 2026-10-04 (#787):* the marking frame, the signal frame and `raw_prices` (the raw fill price behind `shares` and the exit price, req 4) are all read with `traded_only=True` ([data-foundation spec](data-foundation.md), "price-quality gate"). So a zero-volume bar is a missing bar for reqs 2, 4 and 5: no fill, the mark is kept, and a stale exit can follow. A delisting exit sells at the last *traded* close, which may fall before the final session. The bar is also missing for the signal (req 3). The universe applies the same gate, plus the unaccepted-jump part of rule 6. The three new `universe.*` keys are frozen with that section (req 10).
2. **Position valuation, one frame per step.** Positions are carried as dollar values, not share counts. Within step i every price ratio comes from the marking frame alone: a position bought at F_i is worth value × P(s)/P(F_i) at session s, and P is the adjusted-as-of-`t` price. So a split inside the month cancels and a dividend inside the month is reinvested in the paying name on its ex-date, whichever `strategy.signal_total_return` says; an action that becomes known only after its ex-date enters the first step whose read time knows it. Reported `shares` are value over the raw fill price, for the page and the weights table only. The drifted value at close(T_{i+1}) carries into step i+1, where the marking frame as of close(T_{i+2}) prices it forward to F_{i+1}. `BacktestResult` exposes the per-step marking frames, targets and the stitched return series (req 14 needs them).
3. **Signal and portfolio (pure functions).** 12-1 momentum: the adjusted close at the last session of month T−`strategy.skip_months` over the adjusted close at the last session of month T−`strategy.formation_months`, minus one; a name lacking either bar is excluded and counted. Target weights: the top `strategy.top_fraction` of ranked names, `strategy.weighting` (`equal`), long-only, ≥ 0, sum ≤ 1, remainder cash; ties by `security_id` ascending. Cadence and hold are ADR 0006, not config.
   *Amendment 2026-10-03 (#720; accepted 2026-10-06, #1033):* a second signal family, `profitability` (gross profit over total assets from the #660 statement facts), is specified under "Amendment 2026-10-03 (#720)" below; the momentum signal and `portfolio.target_weights` are unchanged, the engine dispatches the signal read and the score by the hypothesis's family.
4. **Fills, costs, cash.** Trades are target minus drifted weights, fractional, at the fill price. Buys are sized so that cash after costs is never negative (a buy's notional is scaled by 1/(1 + per-side rate)). A target name with no bar on F_i is not bought; a held name to be sold with no bar on F_i is not sold and stays at its last mark until the next fill session or an exit rule; both are counted as `missing_fill`. A held name with no bar on a session keeps its last mark. Cash earns `backtest.cash_rate` (0). Equity = cash + Σ position values on every session; cash changes only by fills, costs and `cash_rate` (dividends are reinvested in-name by req 2).
5. **Delistings, stale names, late dividends.** A held name whose listing has ended by the step's read time (Phase 2 req 4, derived from rows known at `t`) is sold at its last close on its final session into cash and counted as `delisting_exit` (`backtest.delisting_exit=last_close`, the ADR 0004 oracle convention). A held name still listed at `t` but with no bar in the last `backtest.stale_exit_sessions` sessions before T_{i+1} is exited at its last close and counted as `stale_exit` (open question 4). Exits pay `per_side_bps` and commissions like any sell. A dividend whose ex-date falls in month i but which becomes known only after close(T_{i+1}) is **lost for good** (the step that would have reinvested it has passed); at each step the provider's `late_dividends(t_prev, t, ids)` reports every dividend known in (t_prev, t] whose ex-date is ≤ t_prev, on a name held on that ex-date, however many months late it arrives, and the rebalance row counts them as `n_late_dividends`. Both exit counts, the survivorship gap at every rebalance (ADR 0003 rule 5, count and size share), the universe size and the number of members whose listing rests on `snapshot_static` rows (#35) are part of every result.
6. **Cost model (pure).** Cost of a trade = notional × `costs.per_side_bps` / 10⁴ + shares × `costs.commission_per_share` + `costs.commission_per_order`, charged from cash at the fill. Every run is evaluated at the base level and at each level in `costs.sensitivity_per_side_bps` (commissions unchanged) from the same reads; strategy metrics, equity and rebalance rows are stored per level (`cost_per_side_bps` column); target weights are identical across levels and stored at the base level only. Sensitivities are never new trials. N, V, DSR and the red flag use the **base** level.
7. **Metrics (pure).** Per series and cost level, with these exact keys: `cagr`, `vol_annual`, `sharpe_monthly` (non-annualized, `metrics.risk_free_rate`), `sharpe_annual` (= `sharpe_monthly` × √12), `sharpe_monthly_excess_spy` (monthly returns minus SPY's), `max_drawdown` (daily equity), `turnover_monthly` (one-sided average), `cost_drag` (gross minus net CAGR), `excess_cagr_spy`, `excess_cagr_mtum`, `tracking_error_spy`, `tracking_error_mtum`, `skew_monthly`, `kurtosis_monthly` (non-excess), `skew_monthly_excess_spy`, `kurtosis_monthly_excess_spy`, `n_months`. The `*_excess_spy` keys are computed for `strategy` and `MTUM` only and stored as null for `SPY`. Standard metrics come from the library ADR 0004 names (chosen in the plan); PSR and DSR are ours.
8. **Deflated Sharpe (Bailey & López de Prado).** SR* = √V · ((1−γ)Φ⁻¹(1−1/N) + γΦ⁻¹(1−1/(N·e))), γ = `numpy.euler_gamma` (0.5772156649015329); DSR = Φ((SR − SR*)√(T−1) / √(1 − γ₃·SR + (γ₄−1)/4 · SR²)), with SR the **monthly, non-annualized** Sharpe of this trial, T = `n_months`, γ₃ = `skew_monthly`, γ₄ = `kurtosis_monthly`. Computed on two **bases**, `raw` (`sharpe_monthly`, `skew_monthly`, `kurtosis_monthly`) and `excess_spy` (`sharpe_monthly_excess_spy`, `skew_monthly_excess_spy`, `kurtosis_monthly_excess_spy`), each with its own inputs (open question 7 picks the headline). **N** = the number of `ok`, non-synthetic, `in_sample` trials in the same family at run time, this one included, reruns included; **V** (per basis) = the sample variance of that basis's monthly Sharpe over the **latest `ok` trial per distinct (parameter hash, window) pair** among them, so a rerun raises N and replaces its pair's value. `family_sharpes` returns both bases and reads only the monthly keys; an annualized Sharpe never feeds V. With fewer than two pairs, SR* = 0 and `dsr_basis=psr`. Stored per trial: `n_trials`, and per basis `sharpe_variance`, `sr_star`, `psr_zero`, `dsr`. The stored DSR uses N and V at run time and goes stale; the page recomputes DSR with **today's N and today's V** (a fresh `family_sharpes` call) from the trial's stored `trial_metrics` inputs and shows it next to the stored value, labelled "N at run time".
   *Amendment 2026-10-07 (#901; [research-registry spec](research-registry.md) req 9, accepted 2026-10-05, #931; research-registry plan T83b, #1190): research runs on return data raise N, never V.* **N** = the number of `ok`, non-synthetic, `in_sample` trials in the same family at run time, this one included, reruns and sweep variants included (strategy-lab spec req 3), **plus** `store.research.family_run_count(conn, family)`: Σ `n_configurations` over the family's `ok`, non-synthetic, non-holdout-spending research runs whose registration has `touches_returns = true`, exploratory runs included. A run with `touches_returns = false` (an `agreement` statistic, a `benchmark` score against gold labels) adds nothing, and neither does a holdout-spending run (a spend, not an in-sample look, as for backtest trials). `backtest.results.family_n_split` computes N's two parts and `family_n` returns their sum; nothing else counts. *(Amended 2026-10-10, #1408, research-registry req 9 amendment: a `failed` return run also counts, by the larger of its declared and evaluated configurations.)* **V is unchanged**: a research run has no Sharpe and adds no pair. So while the family has fewer than two backtest pairs, SR* = 0 whatever N is (this req's rule above), and the research share shows in `n_trials` and `n_research` but deflates nothing. Stored per trial: `n_trials` is that N, and its research part goes in the new nullable `trial_results.n_research` (NULL on rows written before the research registry's migration and on non-`ok` rows; 0 on an `ok` row whose family has no counted research run). The page's "today's N" is the same sum at view time and shows the split (backtest trials, research runs) beside the stored `n_research`; a store that a read-only connection opens before that migration has no research tables, so both research cells are blank and today's N is the backtest count. `write_results` refuses a store without the research tables before any detail or result row, and the trial then closes `failed` (unreachable in practice: every writing command migrates first), so a stored N never silently leaves the research share out. The strategy-lab spec's own req 8 amendment is a separate change and is not made here.
9. **Trial registry in the store.** Tables `hypotheses`, `trials`, `trial_results`, `trial_metrics`, `trial_rebalances`, `trial_equity`, `trial_weights`, `owner_decisions` (schema below), created by `store.schema` at schema version 2 with an additive migration from version 1, listed in `REGISTRY_TABLE_NAMES` separate from the fact tables in `TABLE_NAMES` so the look-ahead harness is untouched. A later fact-table DDL change goes to version 3, never a silent edit of version 2. Any writing command (`hypothesis register`, `backtest`, `decision`, `ingest`) migrates a version-1 store; the read-only pages show a "registry not initialised" state instead. **Append-only**: `store.registry` exposes inserts and reads only; a trial's outcome is a separate `trial_results` row, never an update; a trial with no result row is shown as `unfinished`. **Trial handle**: `registry.open_trial` is the only constructor of `TrialHandle`; `StoreProvider` verifies at construction, through a registry connection that may differ from its data connection, that the handle's id exists in `trials`; the engine refuses to run without a handle (ADR 0005: no id, no run). Every trial records hypothesis, kind, window, data cutoff, the store's latest `ingested_at` at open, code version (git commit, dirty flag), the frozen parameter hash, the synthetic flag, reasons, `run_by` and a note. A run fails (`store changed during run`) if the store's latest `ingested_at` differs between trial open and result write. [docs/research/trial-registry.md](../research/trial-registry.md) becomes a pointer to the tables and the `trials` command.

Wherever this spec says "version 2" for the registry, read version 3; "a version-1 store" in this requirement, req 17 and the "Registry and holdout" acceptance line means a version-2 store (the not-initialised state). A version-1 store raises `SchemaVersionError` and is rebuilt, never migrated or shown.
10. **Pre-registration freezes parameters.** The hypothesis file is the source of truth for the keys it names; the live `Settings` fill the rest at registration. The file **must** name `holdout.start`, `holdout.end`, `in_sample_start` and every `strategy.*` and `costs.*` key, or registration fails; the holdout never comes from live `Settings`. `tradepartner hypothesis register <file>` stores the file's SHA-256 and the frozen values of `strategy.*`, `universe.*`, `execution.fill_price`, `costs.*`, `backtest.*`, `adjust.*`, `master.*`, `gap.*`, `holdout.*`, `metrics.*`, `benchmarks` and `alpaca.historical_feed`, prints the full set and its hash. A run uses the frozen values, never the live ones, so no environment variable can move a hypothesis's holdout or threshold. A changed file or a different frozen set is a new hypothesis, never a variant.
11. **Locked holdout and window rules.** The trial handle is issued first. Then, before any provider call: a window starting before `in_sample_start` or ending after the frozen `holdout.end` is refused (`refused_window`; the latter belongs to Phase 4 tracking); a window touching the frozen holdout is refused (`refused_holdout`) unless `--spend-holdout --holdout-reason` is given. A holdout run has `kind=holdout` and its reason; when any hypothesis in the family already spent the holdout it is marked `holdout_repeat` and the page says so (domain rule 3); a repeat for the **same** hypothesis additionally requires `--holdout-repeat`. **Gap gate** (ADR 0003 rule 6): with the flag, the only reads before the gate are `survivorship_gap(t)` at the window's rebalance closes; the run is refused (`refused_gap`) when the count share at any of them exceeds the frozen `gap.count_share_threshold`, unless `--override-gap --gap-reason` records the owner's decision in the trial and in `owner_decisions`. The in-sample default window is `[in_sample_start, last rebalance session before holdout.start]`, so an ordinary run cannot drift into the holdout.
12. **Owner decisions.** `tradepartner decision <kind> --reason` appends an `owner_decisions` row (`gap_signoff` for ADR 0003 rule 8, the Phase 4 entry gate; `gap_override` and `holdout_spend` are also written by the flags in req 11) with the trial it refers to and the gap values at that time.
13. **No look-ahead.** A run ending at T is a function only of rows with `known_at ≤ close(T)`: truncation invariance holds for the whole run, and a run to T_i equals the prefix of a longer run through T_i. Truncation and prefix invariance alone do not see a plan read at a later rebalance close (a fill at F_k from targets planned at read_time(T_{k+1}) stays inside both cuts; #201), so a third check detects one that changes a compared plan field: for every rebalance T_k with a next rebalance, T_0 included, the targets for F_k and the plan fields of T_k's rebalance row (`n_universe`, `n_targets`, `n_static_listings`, `n_excluded_no_history`, `gap_count_share`, `gap_size_share`) are unchanged when the store is truncated at read_time(T_k) (benchmark bars excepted) in a run that continues to T_{k+1}; the fills and valuation after T_k are not, and are not compared.
14. **`bt` oracle** (ADR 0004). On a temp-file copy of the fixture universe, with zero costs, fractional shares and the same lagged target weights, `bt` and our engine agree on portfolio equity at every compared session to within the tolerance pinned in the test file. `bt` receives the **stitched frame** from `BacktestResult`: per name, each session's return taken from the marking frame of the step that contains it, cumulated into one price index, so both engines see identical ratios and the fixture's late-known revisions cannot separate them. With `fill_price=close` every session is compared; with `open`, `bt` receives the stitched open series and only fill sessions are compared (a deviation from ADR 0004's wording, recorded in its amendment). The delisted fixture name is sold at its last close on its final session in both, asserted explicitly. The oracle registers its own synthetic hypothesis (`family=oracle`) on that temp-file store and passes its path as `run_hypothesis(..., store_path=...)`, the parameter the CLI never sets; `run_hypothesis` returns the results it wrote.
15. **Red flag.** A trial whose base-level `excess_cagr_spy` exceeds `metrics.red_flag_excess_cagr_pp` is marked `red_flag=true` and the page says so: G1 found no live or gross window above +1.1 pp/yr. A prompt for a look-ahead and cost audit, not a gate.
16. **CLI.** `tradepartner backtest <hypothesis> [--start] [--end] [--spend-holdout --holdout-reason] [--holdout-repeat] [--override-gap --gap-reason] [--note]` (exit 0 ok, 1 failed, 2 refused; prints trial id, metrics table, gap maxima, flags); `tradepartner hypothesis register <file>`; `tradepartner trials [--hypothesis] [--include-synthetic]`; `tradepartner decision gap-signoff --trial <id> --reason`. No `--synthetic` flag exists. No secrets in output.
17. **Pages.** Streamlit, read-only, inside the Phase 2 shell's single read-only connection: a **backtest page** (trial picker; equity of the three series on a log axis; drawdowns; monthly turnover and cost bars; metrics per cost level; both DSR bases with N, V and SR*, stored and recomputed with today's N; gap, universe size, static reliance and late dividends per rebalance; kind, synthetic, repeat, red and refused states; family-wide holdout spends) and a **trial-registry view** (every trial newest first; hypothesis filter; synthetic hidden by default; failed, refused and unfinished rows visible with their message; owner decisions). Both show "registry not initialised" on a version-1 store. No run button: runs are CLI only.
18. **First hypothesis end to end.** `docs/hypotheses/h1-momentum-12-1.md` is registered and run over the in-sample window on the owner's real store, by the owner, under whatever `PriceSource` the price-vendor ADR (plan task T29) names. "End to end" means: hypothesis registered, trial issued, run completed, metrics, both DSR bases and the gap stored, `quant-auditor` passed on the run, page shows the trial, universe size per rebalance in the evidence. It does **not** mean the holdout was spent: on a source above the gap threshold the holdout stays locked, and a result on free data is optimistic and claims no edge (ADR 0003).

**Amendment 2026-10-10 (#1408, owner decision on #1011 item 4).** Req 11's same-hypothesis repeat flag also applies after a research spend in that hypothesis's family: because a research spend has no `hypothesis_id`, a later backtest holdout spend requires `--holdout-repeat`. A prior backtest spend by a different hypothesis in the family still marks a repeat without requiring the flag, subject to the family cap. Req 8's research share of N also counts `failed` return runs (research-registry req 9 as amended by #1408).

## Acceptance criteria (testable)

Engine and timing
- [ ] Every provider call of a run carries `t = close(T_{i+1})` for some rebalance session (recording provider); the fill session is `calendar.next_session(T_i)` across a month-end before a holiday and on a half day (fixture cases).
- [ ] With `execution.fill_price=close` the fill equals F_i's close; with `open`, F_i's open; the two runs have identical targets and weights and different fill prices.
- [ ] Valuation: a synthetic store with a 2:1 split and a dividend both ex inside a holding month values the held name with no jump on the split date and with the dividend reinvested (equity equals the hand-computed total return); a dividend known only after its ex-date but before close(T_{i+1}) changes that step and none before; one known only after close(T_{i+1}) changes no equity and is counted in `n_late_dividends` of the rebalance row of the step that first knows it, whether one or three months late.
- [ ] Momentum on a synthetic frame: the skip month is excluded; a name missing the formation-start bar is excluded and counted; ties rank by `security_id` ascending; weights are ≥ 0, sum ≤ 1 and equal within the selected set; no session after `t` is read.
- [ ] Cash identity on every session; cash is never negative at any cost level, including the ladder maximum.
- [ ] A target name with no bar on F_i is not bought; a held name to be sold with no bar on F_i keeps its last mark and its value until the next fill session; both appear in `missing_fill`; a held name with no bar on an ordinary session keeps its last mark.
- [ ] `SEC_WINDOW_DELIST` held at its delisting exits at its last close on its final session into cash, counted as `delisting_exit`, paying `per_side_bps`; `SEC_TRANSFER` held across October 2018 exits at the 2018-10-31 close (delisted at that read time) and is eligible again once the new listing is known; a name with a trailing gap beyond `backtest.stale_exit_sessions` while still listed exits as `stale_exit`, and one whose gap closes before T_{i+1} does not.
- [ ] Rebalance rows carry gap count and size share from `survivorship_gap`, universe size, static-listing count, dropped-dividend count and late-dividend count, per cost level.
- [ ] Benchmarks: SPY and MTUM equity equals a hand-computed buy-and-hold with the fixture dividends reinvested, one initial cost, same fill convention.
- [ ] `engine.run` without a `TrialHandle` raises before any provider call; `StoreProvider` refuses a handle whose id is not in the registry connection's `trials`; a plain integer is rejected.
- [ ] `StoreProvider` opens one read-only connection per step and closes it before the next (recording factory); a write lock taken between steps does not fail the step that follows it.

Costs and metrics
- [ ] Three-trade fixture: costs match hand-computed values for `per_side_bps`, `commission_per_share` and `commission_per_order` (ADR 0004); zero cost is the identity; a higher level never yields a higher net CAGR on the same reads; the provider is read once for all levels (recording provider).
- [ ] Metrics on a synthetic monthly series match hand-computed values for every key in req 7; `sharpe_annual = sharpe_monthly × √12`; AST check: `backtest/{metrics,costs,fills,valuation,engine}.py` contain no numeric literals other than 0, 1, −1, 2, 4, 12 and 10 000, and γ is `numpy.euler_gamma`.
- [ ] Deflated Sharpe reference values (computed with `numpy.euler_gamma`): SR=0.25, T=120, γ₃=−0.5, γ₄=4, N=20, V=0.01 gives SR*=0.190071, PSR(0)=0.994120, DSR=0.727048; N=100 gives SR*=0.253060, DSR=0.487699; SR=0, N=1 gives 0.5; N=1 reduces to PSR and is labelled `psr`; DSR falls as N, kurtosis or negative skew grow (all to 1e-6).
- [ ] Both DSR bases are stored with their own `sharpe_variance`, `sr_star` and `psr_zero`, the excess basis computed from the `*_excess_spy` skew and kurtosis; the `*_excess_spy` keys are null for `SPY`; the red flag is set when the base-level `excess_cagr_spy` exceeds `metrics.red_flag_excess_cagr_pp`, not otherwise.

## Risks & domain checks

- **Look-ahead:** the engine sees the store only through `t`-parameterised provider calls with rebalance closes; truncation and prefix invariance over every rebalance session prove it, and the plan-read timing check detects a plan read at a later rebalance close that changes a compared plan field (truncation and prefix invariance alone do not see a fill at F_k from a read at read_time(T_{k+1}); #201); the revision case proves the test can fail; one frame per step means a later restatement never reaches an earlier step, and a dividend known too late is counted, not back-filled.
- **Survivorship:** the delisted name exits at its last close, the optimistic convention (the missing tail is where the decline lives, ADR 0003); every result carries the gap per rebalance, stale exits, universe size and static-listing reliance (#35 can otherwise shrink the historical universe to survivors); the holdout cannot be spent above the threshold without a logged owner decision; the Phase 4 gate has its sign-off row.
- **Multiple testing:** every run is a trial by construction (no handle, no provider, no run); N counts reruns, V takes the latest per pair; sensitivities and synthetic runs do not touch N; synthetic and oracle trials are impossible on the real store; a new parameter set is a new hypothesis; families are enumerated so N cannot be reset by renaming; the page recomputes DSR with today's N and V so a stored value cannot flatter an old trial; `backtest-runner` runs only on temp-file or fixture stores, so no agent trial escapes or pollutes the owner's registry; the H1 file discloses holdout-period evidence already seen.
- **Costs:** per-side bps plus commissions on every trade including exits; sensitivity ladder up to the historical effective-spread level; Phase 4 paper fills recalibrate the base (ADR 0006 consequences).

**The signal (pure; req 3, generalised).** `signals.gross_profitability(facts, sics, t, *, security_ids, annual_period_days, max_fact_age_days, exclude_sic_ranges, include_derived, basis) -> ProfitabilitySignal(scores, excluded)`, with `t` the tz-aware read time `close(T)` (a naive `t` raises; `t_session` is `t`'s session date), scores a name as `gross_profit / total_assets` (basis `gross`; basis `cash` substitutes `operating_cash_flow`, an OCF-over-assets proxy reserved for a pre-declared variant, see Config keys) by these rules, in this order, each exclusion counted by reason:

0. **Guard.** Rows with `known_at > t` are dropped before anything else, as `momentum_12_1` drops sessions after `t_session`; the provider's as-of read already returns none, and the function does not trust that.
1. **Scope.** A name whose SIC at `t` lies in any `exclude_sic_ranges` range is not scored (`n_excluded_sector`); a name with no SIC known at `t` passes scope, as ADR 0006 rule 3 lets a missing SIC pass in `universe.py`. 2. **Numerator row.** Among the name's `gross_profit` rows known at `t` with `period_days` inside `annual_period_days` (default `[350, 380]`: calendar years, 52- and 53-week fiscal years; quarters, half-years, nine-month and stub periods are ignored), the one with the latest `period_end`; two with one `period_end` take the larger `period_days`. `basis = derived` rows are used when `include_derived` is true and counted (`n_derived`), skipped otherwise. No row: `n_excluded_no_facts`.
3. **Denominator row.** The `total_assets` row (`period_days = 0`) with **the same `period_end`** as the numerator row. No match: `n_excluded_no_facts`. The pair's `known_at` is the later of the two rows'; both are `≤ t` by the as-of read.
4. **Freshness.** `t_session − period_end ≤ max_fact_age_days` (default 548 days, 18 months; the file's open question B3-3), else `n_excluded_stale_facts`.
5. **Values.** A non-finite numerator or a non-positive or non-finite denominator excludes the name (`n_excluded_malformed`); nothing is ever scored zero for a missing fact.
6. **Rank** descending; ties by `security_id` ascending. `portfolio.target_weights` takes the top `profitability.top_fraction` of the **scored** names at `profitability.weighting` (`equal`), long-only, ≥ 0, sum ≤ 1, remainder cash, unchanged.

## Amendment 2026-10-11 (#1498): the risk-free series from the store

[ADR 0020](../decisions/0020-fred-risk-free-rate.md) adds the 3-month T-bill rate (`DTB3`) to the store as a point-in-time `rates` table ([data-foundation spec, amendment 2026-10-11](data-foundation.md#amendment-2026-10-11-1498-the-rates-table-and-the-fred-rate-source)). This amendment says how the metrics read it. The sentences of req 7 and "Config keys" that name `metrics.risk_free_rate` stand; what changes is where the per-period rate comes from. The code is the data-foundation plan's T170 to T170c; the owner's T170d flips the default after the real-store backfill.

*Keys.* Three new `metrics.*` keys, frozen per req 10 like the rest of the section, each with a `FROZEN_KEY_DEFAULTS` entry (strategy-lab spec, Definitions "Frozen-key defaults"): **`metrics.risk_free_source`** ∈ {`constant`, `store`}, table entry `constant`; **`metrics.risk_free_series`** = `DTB3`, the `rates.series` id a `store` trial reads; **`metrics.risk_free_basis`** ∈ {`discount`, `yield`}, table entry `discount` (DTB3 is quoted on a discount basis; the table stores the published number and the metrics convert). `metrics.risk_free_rate` is unchanged and is read only under `constant`. The live default of `risk_free_source` is `constant` when T170 lands and **`store` from T170d on**, the owner's task that backfills the real store (as T78 flipped `edgar.statement_facts_enabled` once the store held the rows), so no registration made between the code and the backfill can fail on a missing rate; the table entry stays `constant` at the flip (strategy-lab spec, Definitions, amended 2026-10-11: the one key whose config default and table default differ). None of the three enters the fingerprint, as `risk_free_rate` does not (`frozen.fingerprint`; the rate does not decide a run), so two registrations that differ only in the source share a (canonical set, window) pair.

*The per-session rate.* For a session s, `rf(s)` is the value of the latest observation of `risk_free_series` by `observation_date` among the `rates` rows with `known_at ≤ close(s)`, latest revision per observation date. The engine reads the table **once**, at the run's data cutoff (`DataProvider.rates(t, series)` → `rates_as_of(t, [series])` at the last step's `t`), only when the frozen source is `store`, and keeps the frame on `BacktestResult`; the frame carries `known_at`, so the per-session filter is the as-of read at close(s) (the data-foundation amendment's "Point in time"; tested below). Under `discount` the published rate `d` (percent / 100) becomes the 91-day bill's bond-equivalent yield `y = 365 × d / (360 − 91 × d)`; under `yield`, `y = d`. The session's accrual is `1 + y × n_s / 365`, with `n_s` the calendar days from the previous session to s, so a weekend or a holiday accrues to the next session as a bill does. Period i's risk-free return is `rf_i = Π_{s ∈ (T_i, T_{i+1}]} (1 + y(s) × n_s / 365) − 1`, over the same sessions as the period's equity return. Under `constant`, `rf_i = (1 + risk_free_rate)^(1 / periods_per_year) − 1`, exactly today's. A session with **no rate known at its close** (the sessions before the backfill's first stamp, a series the store lacks) fails the trial with `risk_free_missing`, naming the series and the session, before any result row is written: never zero, never the constant, never carried forward from before the series starts. Inside the series, `rf(s)` carries the latest known observation across the sessions with none (weekends, bank holidays and the two-session posting lag), which is what a bill held across them earns; the carry is bounded by the ingest, not here: the daily request starts no later than the day after the latest stored observation (data-foundation amendment, "Daily"), so a lapse in runs is refetched by the next run and leaves no hole, and health warns on any gap between consecutive observation dates longer than `rates.max_stale_sessions` sessions.

*Metrics.* `sharpe_period` is the Sharpe of the excess series `r_i − rf_i` (the library's `risk_free` argument at 0); when every `rf_i` is the compounded constant this is today's number to the last bit, which is how H1's pinned metrics stay unchanged. `skew_period` and `kurtosis_period` are the moments of the same excess series `r_i − rf_i` (the series whose Sharpe the PSR formula takes; under `constant` they equal today's values, since subtracting one constant from every period leaves the central moments as they are), so the **`raw` DSR basis moves with `sharpe_period` under `store`**, and so does the family's raw V, which reads `sharpe_period`. `sharpe_period_excess_spy`, `skew_period_excess_spy`, `kurtosis_period_excess_spy` and the **`excess_spy` DSR basis are unchanged**: SPY's excess cancels the rate, and the `excess_spy` basis is the headline (open question 7). `cagr`, `vol_annual`, `max_drawdown`, turnover, cost drag and the benchmark keys are unchanged. One key joins `METRIC_KEYS` (req 7's list), stored for every series and level as the others are: **`risk_free_annual`** = `(Π (1 + rf_i))^(periods_per_year / n_periods) − 1`, the annualised risk-free return the run used, equal to `metrics.risk_free_rate` under `constant`. The CLI's and the page's metric loops read `METRIC_KEYS`, so they show it with no change of their own. The conversion and the period product live in a new pure module, `backtest/riskfree.py`, whose three day-count constants (365, 360, 91) are named once there; the module joins req 7's AST-literal list with those three allowed, as `schedule.py` is listed with 12, 52 and 252.

*Which trials change.* **None retroactively.** Every registration made before T170 lacks the key and reads `constant` from the table; its past trial rows stand, and its reruns compute what they compute today. H1's registration, trials and open paper window are unchanged (the paper path computes no Sharpe). A trial of a registration made after T170d's flip records `store`, the series and the basis in its frozen set, and `risk_free_annual` on its metrics rows: that is how a reader knows which rate a trial used. The family's V mixes annualised raw Sharpes under both sources until every pair is a post-flip registration; the `excess_spy` V does not.

*Look-ahead (req 13).* A run ending at T is a function of `rates` rows with `known_at ≤ close(T)`: truncation invariance holds with `rates` in the truncated set; a `rates` row first known after close(T) with a different value changes no metric of a run to T, and the same row known at or before close(T) does (the test with teeth); and the per-session filter at close(s) equals `rates_as_of(close(s))` for every session of the fixture window. A rate stamped on the day it describes is the broken adapter's case (`early_rate_stamp`).

*Acceptance (T170, T170b, T170c).*
- [ ] `riskfree.period_risk_free` on a hand-built series: the discount conversion at `d = 0.05` gives `y = 0.051336...` (365 × 0.05 / (360 − 4.55)); a weekend's three days accrue to Monday; a period's `rf_i` equals the hand product; `yield` leaves the value as is; a session with no rate known raises `risk_free_missing` naming it.

Sensitivity levels (`costs.sensitivity_per_side_bps`) vary `per_side_bps` as today with the two new terms held at the frozen values. **The measured level:** `backtest <slug> --measured-cost-bps <x>` evaluates one more level at `x`, labelled `measured` in `trial_metrics.cost_per_side_bps`'s companion column `cost_level_kind ∈ {base, ladder, measured}`, from the same reads; never the base, never a new trial, never in N, V or DSR; the flag is accepted on **in-sample trials only** (a holdout or forward run refuses it, `refused_measured_level`); `x` is a paper book's median per-fill slippage plus half-spread, **fixed before the run** and quoted in the trial's note with its source book(s) and window, and **never from the book whose strategy is being examined** (H1's `main` and the daily operations book feed B10's and B9's levels; a book never calibrates its own cost).

## Amendment 2026-10-18 (#1820): the kill ladder's rung-4 delay and rung-5 placebos

ADR 0023's rungs 4 and 5 need two things no requirement above specifies: a signal read one or more sessions stale, and a placebo in place of the signal. The [plan](../plans/backtest.md)'s T217, T217c and T217b (#1754, split #1820) build them; this amendment says what, from the design calls the owner delegated to the orchestrator on 2026-10-18 (#1820) and spec-critic's pass on PR #1821. 1. **The delay shock (rung 4; req 1's read time; req 13).** `strategy.signal_delay_sessions = d` (default 0) moves the plan's **read** and nothing else. Under `d > 0` the read session is the **latest rebalance session at `schedule.rebalance_cadence` at or before the d-th XNYS session before T_i**, and the read instant t' is its close (`read_time` of it): the universe, the signal's inputs, the signal, the static-listing count and the plan's survivorship gap are all the read session's own, read at t' exactly as that session's plan reads them, so the delayed plan at T_i **is built from the read session's reads and scores against the book as it stands at T_i**: under stateless construction (`equal`, band 0) it is the read session's plan re-dated, and under `hold` or a non-zero band the construction step reads T_i's book, as today; one read instant, no mixing, and the signal's own rules hold unchanged (`signals.momentum` and `formation_sessions` take only a rebalance session, and the anchors are the read session's). At `daily` the read session is exactly d sessions back, the one-session delay ADR 0023's rung 4 names for the fast books; at `week_end` and `month_end` any d below the period's length is the previous rebalance session, so the smallest shock there is one period (a stale plan traded a period late), and the key keeps its unit, sessions. The plan is **built at T_i and filled at F_i** as today (`Plan.session`, the fill session and the fill price are unchanged), and the run's gap gate stays at T_i's close (it gates the run, it is not the plan's read). No read happens after T_i's own `t` (req 13 holds as today), and a fact first known in (t', t] enters neither the members nor the scores. A sweep's shared pre-read uses the same read session per variant, so a sweep under a delay reads once per group as today.

2. **The placebos (rung 5).** `strategy.placebo ∈ {none, shuffle, random_entry}` (default `none`) with `strategy.placebo_seed` (default 0, non-negative) replace the family's scores after the signal is computed and before construction: `Plan.scores` holds the scores construction used, the placebo's, while exclusions, counts and every other plan field are the real signal's. Both are **deterministic and stdlib-only** (no new dependency): the scored names are sorted by security id, and the generator is `random.Random("<placebo_seed>:<ordinal of the rebalance session>")`, so one `placebo_seed` draws afresh at every rebalance, two runs of one file are identical, and the plan step carries no generator state. **`shuffle`** assigns the id-sorted score vector back to the id-sorted names after one `Random.shuffle` of it. **`random_entry`** is one `Random.shuffle` of the id-sorted names scored n down to 1 in shuffled order, a random ranking: construction takes its top k under `equal`, and under `hold` the entries a held name leaves open are filled from the same ranking (a k-name draw with every other name at 0 would fill them in security-id order, a fixed bias). Neither key is a sweep axis, though a sweep's fixed block may set them. The generator's output is pinned by a test against Python 3.12, so a stdlib change fails by name rather than in a hand list.

3. **The trial row and its note (ADR 0023: every rung-4 and rung-5 run is a `trials` row, labelled).** A placebo or delayed file registers and runs as any other (`hypothesis register`, `backtest run`, or a sweep whose fixed block sets the keys), counted in its family's N as req 7 counts it. The run writes the label itself wherever a ladder trial row is opened (`backtest run`'s row and each sweep variant's row): `note` begins `placebo=<mode> seed=<n>` when the placebo is not `none` and `signal_delay=<d>` when d is non-zero (space-separated, in that order), followed after `; ` by the `--note` given, if any; at the defaults the note is exactly the `--note` given, so no stored row changes. The paper planner's tracking rows are the book's own and carry no tag (a placebo never reaches it, item 4; a delayed file that becomes a book names its delay in its frozen set).

4. **A placebo never becomes a book and never spends a holdout (`refused_placebo`).** `sweep promote`, `hypothesis register --operations-book-of`, and a holdout or tracking run (`backtest run` into the holdout, `paper` tracking) refuse a file whose frozen `strategy.placebo` is not `none`, with the one code **`refused_placebo`** as the first word after the path or slug in the refusal's message (the convention `refused_fill_convention` and `refused_cash_rate` name above; `PromotionRefused`, `LabRegistrationError` and the run's pre-trial `ValueError` respectively), before anything is written; `promote`'s refusal 6 makes the file's set the argmax's, so a placebo variant is refused through a matching file too. A delayed file (`d > 0`, no placebo) is refused by none of them: a stale-signal strategy is implementable, and a book of it plans through `engine.plan`, so it honours the delay.

*Acceptance (testable).* At the defaults every pinned run is byte-identical (H1's and the TWIN's fingerprint and digests, the reference metrics, every registered trial's rows); at `daily` a delay of 1 on the fixture equals the previous session's plan re-dated, field by field, at `month_end` with the turnover screen on it equals the previous month-end's plan re-dated (both under `equal`, band 0), and a membership change or a planted bar revision first known in (t', t] changes neither; `run_many` at delay 1 equals separate runs; `shuffle` with one seed is identical across two runs and differs across seeds and across sessions; `random_entry` on a seeded fixture equals the hand ranking and across 200 seeds every member ranks first at least once; the generator pin: `random.Random("0:1").shuffle` of `[0, 1, 2, 3, 4]` is `[3, 0, 2, 4, 1]`; a placebo run's `trials.note` is `placebo=shuffle seed=7`, a delayed run's `signal_delay=1`, a default run's the `--note` given or NULL, and a delayed sweep's variant rows carry `signal_delay=1`; `sweep promote`, `--operations-book-of`, a holdout run and a tracking run refuse a placebo file with `refused_placebo` and write nothing, and none of them refuses a delayed file.

A 50/50 book is `gross_exposure = 1.0`, `net_exposure = 0.0`.

3. **The shortability proxy (req 3; ADR 0024 item 3; settled, its limits stated).** No free history of borrow availability or fees exists. [ADR 0021](../decisions/0021-alpaca-assets-borrow-status-record.md)'s record starts 2026-10-11, after every in-sample and holdout window the registry holds (the latest `holdout.end` is 2026-09-30). So **no backtest reads `borrow_status`**, and the table stays outside the data vintage (ADR 0021 point 4 asks a backtest amendment to decide this; this is that decision). A ranked name is **short-eligible** at T_i when it is a universe member at t (ADR 0006's rules and floors, already applied) and its raw close on T_i, read as of t, is at least `portfolio.short_min_price`. Every eligible name is assumed easy to borrow at item 6's headline fee. The $5 floor is Alpaca's own line: below $5 its short maintenance is the greater of $2.50 a share or 100 %. The count of ranked names the floor removes is a plan count, `n_short_below_price`. **The proxy's limits, stated on every long/short trial's page:** (a) it never sees a hard-to-borrow name, a recall, a failed locate or a fee spike. The [beyond-long-only report](../research/2026-10-10-beyond-long-only.md) (Muravyev, Pearson and Pollet 2025; Drechsler and Drechsler) puts most of an anomaly's short-leg return in exactly those names, so **the proxy biases the short leg's return upward**, most in small, heavily shorted names; (b) ADR 0024 lets a hypothesis widen its universe, and below the large caps the proxy gets worse. A wider-universe `long_short` file says so at admission, beside ADR 0024's corporate-actions caveat; (c) Alpaca's flags are one broker's book (5,373 shortable of 33,636 assets on 2026-10-11). The 300 bp line of item 6 is the stress for (a). Whether a later check compares the proxy with the recorded ETB set over the forward span is open question 23.

4. **The signed book (reqs 2, 4, 5; ADR 0024 item 1; settled).** Positions are signed dollar values. A short is a negative value, marked to market at every session's close by the same price ratios as a long (value_s = value_F × P_s / P_F from the step's adjusted frame), so `value_positions` and `carry_to_fill` are linear in the sign. A short open credits its proceeds less its cost to cash, and a cover debits its notional plus cost. Equity = cash + Σ signed values. Gross exposure is Σ |value| / equity and net exposure is Σ value / equity, at every session. `apply_trades` runs in four passes: long sells, covers, short opens, long buys. A flip is a close and then an open. **Long buys are capped by free cash**, which is cash − Σ |short value|, ADR 0010's restated cash rule of this date. So short proceeds never fund the long leg beyond equity and no debit balance arises; under gross ≤ 1.0 and this rule, margin interest is zero, and the engine says so rather than models it. Every trade of either leg pays the cost model of req 6 (per-side bps, the #1731 spread and impact terms, commissions). Under `long_only` the four passes reduce to today's two and every pinned run is byte-identical. The `value > 0` filters in `_step` become `value != 0` only under `long_short`; seam 5's negative-value raise stays for `long_only` books. A session whose equity is not positive ends the run with `ValueError` naming the session ("the book's equity is gone"), recorded as a `failed` trial. A short's loss is unbounded and the engine does not hide a ruin.

5. **Dividends owed on a short (req 2; ADR 0024 item 5; settled).** A short is marked on the dividend-adjusted frame, so on the ex-date it loses the dividend that a long of the same name earns. The payment in lieu is inside the equity path and has no cash line of its own. Equity differs from paying the dividend from cash by a second-order term: the marked short carries the dividend inside its value, so the dividend is in effect re-shorted and moves with the stock until the cover. *(2026-10-19, owner, #1876)* The store's factor is 1 − D / prior close, so the re-short is at the prior close less the dividend, not at the ex-date close. The difference (marked minus cash) is n·D·(1 − P(s) / (P(X−1) − D)) from the ex-date close on, for n shares short, dividend D, raw close P(s) and ex-date X. It is already non-zero at the ex-date close (T218's fixture check: −4.4e-6 of equity, about 0.2 % of the dividend). The term is about 1 % of the dividend for a 1 % move, and the engine accepts it and the page states it, together with the split between `trial_equity.cash` and the position. `n_dropped_dividends` and `n_late_dividends` count short holdings too (held at the close before the ex-date). A dropped dividend biases a short leg's return **upward** and a long leg's downward; the counts are per rebalance, as today. Alpaca paper simulates no dividends on either leg ("Paper trading account does NOT simulate dividends", fetched 2026-10-19), so a short book's paper equity beats its backtest on every short ex-date. The tracking comparison states it (paper spec, amendment of this date).

6. **Borrow cost (req 6; ADR 0024 items 2 and 3; the rule settled, the headline value open).** `costs.borrow_bps_per_year` (default 0.0) is the declared headline borrow fee. On each session s of a step after the fill, cash is debited Σ |short value at close(s_prev)| × bps / 10⁴ × (calendar days from s_prev to s) / 360. This is Alpaca's documented rule: `Σ((each stock’s HTB short $ market value * that stock’s HTB rate) / 360)`, with weekend days charged. `costs.borrow_sensitivity_bps` (default empty) lists further rates. The engine runs each as one more book at the base per-side level, written as series `strategy_borrow_<n>bp` in `trial_equity` and `trial_metrics`. These books are **reported only**: never in V, DSR, the red flag, a promotion rule or any selection statistic, the `beta_spy` rule of #1731. **A `long_short` file is refused `refused_borrow_rate` unless its headline is above 0 and {0, 30, 300} ⊆ {headline} ∪ sensitivity**, the report's grid. The 0 bp line is a reference only, never the headline net result (ADR 0024 item 3). Both keys join `POST_REGISTRATION_COST_KEYS`; the headline may only rise above its table default (`HIGHER_ALLOWED_COST_KEYS`). **Hard-to-borrow names** get no per-name fee in a backtest, because no data exists and the proxy admits none (item 3). Their cost lives in the 300 bp stress line. **No rebate:** under `backtest.cash_rate = store` cash accrues `rf(s)` on free cash only (cash − Σ |short value| at the previous close), because Alpaca pays retail accounts no interest on short proceeds (the report's section 7). The headline's value is open question 21.

7. **Exits for a short (req 5; ADR 0024 item 5; settled).** *Delisting:* a short whose listing ends is covered at its last close on its final session, the long rule mirrored, with cost. For a cash merger the last close is near the deal price. For a delisting for cause the price usually falls further after the listing ends, so covering at the last close forgoes that gain: **conservative for the short, never optimistic.** Short P&L carries no survivorship bias, because delisted names are in the universe and in the short leg exactly as in the long (point-in-time listings, the delisters' bars). *Stale or halted:* a name with no bar keeps its last mark, as today, and is covered at its last bar's close after `backtest.stale_exit_sessions`. A squeeze during a halt is understated until the cover, and the page states it. *Squeeze (drift cover):* when a short's |value| / equity at a session's close exceeds `portfolio.short_cover_weight`, it is covered at the next session's `execution.fill_price` with cost, decided from data known at that close (a look-ahead test pins it), and counted as `n_drift_covers` at the base level. The paper book's risk rule is the same rule on the same frozen key. Nothing else trades between rebalances. The drift-cover default is open question 22.

8. **Reporting and benchmarks (req 7; ADR 0024 item 7 open).** Series are unchanged (SPY and MTUM, ADR 0005). A `long_short` trial also writes, for the strategy series at every level: `gross_exposure_mean`, `gross_exposure_max`, `net_exposure_mean`, `net_exposure_min`, `net_exposure_max`, `borrow_paid_annual` (the fees over mean equity, per year) and `excess_cagr_rf` (CAGR over the store's T-bill series). It writes them through the family-benchmark pattern of `metric_keys`, so a `long_only` trial writes no new row. The backtest page shows net exposure and item 3's limits beside every long/short trial. A market-neutral book trails SPY by about the equity premium by construction, so **until the ADR 0005 amendment that ADR 0024 item 7 requires** (open question 24), `sweep promote` refuses a `long_short` file with `refused_benchmark_pending`, and the paper spec refuses its `paper start` with the same code. The in-sample run itself is allowed.

9. **The oracle (ADR 0004).** `bt` takes negative weights. The oracle test gains one long/short fixture case (zero costs, fractional, gross 1.0, net 0.0, the same lagged signal and adjusted frame) that must agree within the existing tolerance. The engine is extended, not replaced. ADR 0004's consequence that "if the strategy later needs intraday bars, shorting, or event-driven fills, that engine will not be enough" is read as met for shorting once this case passes; the dated note on ADR 0004 is part of open question 24's recommendation.

*Acceptance (testable).* At the defaults every pinned run is byte-identical (H1's and the TWIN's fingerprint and digests, the reference metrics, the oracle, the lookahead suite); a non-default `portfolio.*` value is refused before T223; on a hand fixture a 50/50 book's equity equals the hand ledger to 1e-9 through a short open, a 10 % rise, a cover, a flip and a delisting cover, and across a dividend ex-date differs from paying the dividend from cash by item 5's hand term n·D·(1 − P(s) / (P(X−1) − D)) to 1e-9 (*(2026-10-19, owner, #1876)*); long buys never exceed free cash; a `long_short` file with `hold`, a non-zero band, a 0 bp headline or a grid missing 300 bp is refused by name; the borrow fee over a Friday-to-Monday step is three days' charge; free-cash accrual on the fixture equals the hand product; a planted price above `short_cover_weight` at close(s) covers at s+1's fill price and a planted revision known after close(s) changes nothing; the `bt` long/short case agrees; a `long_short` trial writes the seven metric rows and a `long_only` trial none; `sweep promote` refuses a `long_short` file `refused_benchmark_pending`.

*Config keys* (defaults; source): `portfolio.side=long_only`, `portfolio.gross_exposure=1.0`, `portfolio.net_exposure=1.0`, `portfolio.short_min_price=5.0`, `portfolio.short_cover_weight=0.10` (frozen section `portfolio`, post-registration); `costs.borrow_bps_per_year=0.0`, `costs.borrow_sensitivity_bps=[]` (in `POST_REGISTRATION_COST_KEYS`); each with a `FROZEN_KEY_DEFAULTS` entry appended in landing order (#1792); nothing in `.env.example` beyond one comment; no new dependency, no schema version (the new series and metric rows fit `trial_equity`, `trial_metrics` and `trial_rebalance_counts` as they are).

*Out of scope:* gross above 1.0 (the owner's leverage decision, ADR 0024 item 4); `hold` or a band on a signed book; an SPY-hedge short leg (B12 decides whether one is wanted); per-name HTB fees, locates and a borrow-status read; margin interest; intraday; live.

## Amendment 2026-10-19 (#1894): spin-offs from stored inputs, an opt-in key, the counts, and what paper does

The owner split T211 on 2026-10-19 (#1797): T211 is the beta-adjusted alpha alone, already on `main` (PR #1796), and the spin-off half becomes the [plan](../plans/backtest.md)'s **T211b to T211e**, built from this amendment. The team that claimed T211 stopped on four gaps in the 2026-10-18 paragraph *Spin-offs* above (#1797): its type and config names do not exist; its factor has no stored input; it contradicts the [data-foundation spec](data-foundation.md)'s consumer pin; and its count needs a place to live. This amendment settles each one. The 2026-10-18 invariant still holds: H1's and the TWIN's canonical set, fingerprint and hash, the reference metrics and every registered trial's rows stay unchanged. That is why item 3 makes the adjustment opt-in.

1. **Names (settled).** The stored type is **`spinoff`** (`ActionType.SPINOFF`, written by the corporate-actions ingests since T172c and #1712), not `spin_off`. No `action_types` config key exists. The adjustment path's type list is the SQL literal in `store/asof.py`'s `_adjusted_params`, and it gains `'spinoff'` only for a read that asks for spin-offs (item 3). Keys and counts in English use `spin_offs`; the stored value stays `spinoff`. In the 2026-10-18 acceptance, "a planted `spin_off`" means a planted `spinoff` row.

2. **The factor from stored inputs (settled).** A `spinoff` row is stored in the T64 convention ([data-foundation spec](data-foundation.md), amendment #1506, *Spin-offs*): the child c is in `security_id`, the ratio r (child shares per parent share) is in `ratio_or_amount`, the parent p is in `source_action_id`, and E is in `ex_date`. With these, the value distributed per parent share is **D = r × C**. C is the child's raw `close` on session E, its first regular session (the parser resolves the child at E), read as the latest revision of that bar known at `t`. The parent's prior close P is chosen exactly as for a dividend: the raw close of the parent's latest bar before E known at `t`, within `adjust.max_prior_close_gap_sessions`. The factor is **1 − D / P**. It applies to the parent's `open`/`high`/`low`/`close` on sessions before E, beside the split and dividend factors. Two rows of one parent on one ex-date are two factors. **A valued spin-off is a dividend in kind of amount D:** every adjusted read, mark and equity path equals what the same store would give with a parent dividend of amount D on E. That equivalence is the main test.
   **Selection.** A read of `ids` selects spin-off rows by their **parent**, `source_action_id IN ids` (as `backfill.py` selects a benchmark's), never by `security_id`, which is the child. P comes from the parent's bars. C is read from the child's bar on E whether or not the child is in `ids`. Every existing path that keys an action by `security_id` keeps doing so for splits and dividends: the actions filter, the prior-bar join, the marking probe and `late_dividends`.
   **Unvalued.** In the following cases the factor is 1 and the read reports the spin-off as unvalued, with a reason: no bar of the child on E known at `t` (`no_child_close`); the dividend's four rules, under their names, applied to the parent's prior bar and to D (`no_prior_bar`, `outside_calendar_range`, `stale_prior_bar`, and `implausible_amount` when D ≥ `adjust.max_dividend_to_prior_close` × P). `unvalued_spin_offs_as_of(conn, t, ids)` in `store/asof.py`, a sibling of `dropped_dividends_as_of`, lists `(parent, child, ex_date, reason)`. A non-finite or non-positive r or C raises, as a corrupt split ratio does.

3. **The opt-in key, and the pin relaxed for one read (settled).** `adjusted_prices_as_of` gains `include_spin_offs: bool = False`. The flag requires `include_dividends=True`: a spin-off is a distribution, so it belongs in the total-return series only, and passing it without dividends raises `ValueError`. At the default, every consumer the data-foundation spec pins stays **byte-identical** with and without a `spinoff` row: `adjusted_prices_as_of` (both dividend settings), `dropped_dividends_as_of`, `price_jumps_as_of`, `universe_as_of`, `late_dividends`, and every execution reader. The pin is relaxed for `adjusted_prices_as_of(..., include_spin_offs=True)` alone; see the [data-foundation amendment of this date](data-foundation.md#amendment-2026-10-19-1894-the-spin-off-consumer-pin-relaxed-for-one-read). A frozen key, **`adjust.apply_spin_offs`** (default `false`, a `FROZEN_KEY_DEFAULTS` entry at the schema version T211c lands at), decides the flag. `store_provider` passes it on every dividend-including adjusted read the engine makes, which covers the signal reads and the marking reads. Until T211e wires it, the key is in `hypothesis.NOT_YET_APPLIED_KEYS`, so a `true` file cannot be run or planned (`load_frozen` refuses it) and records no result under a label no run applies. The key's rules are #1792 item 1's rules for a member, applied to an `adjust.*` key, through a pinned append-only `frozen.POST_REGISTRATION_ADJUST_KEYS`: it is not a required key, it is frozen at its default when absent, and it is never taken from live `Settings`. A file that wants spin-offs names the key, and a forward book (ADR 0023) registers `true`. It is a fingerprint key (`frozen._FINGERPRINT_KEYS`). At `false` it is outside the canonical set, so no stored fingerprint moves, and it is **outside the promotion identity** (open question 26). It is not a sweep axis: `adjust.*` is a forbidden axis. `marking_changed_ids_as_of` also names a spin-off's parent when the row, or the child's bar on E, becomes known or effective. The probe is deliberately broad, so this happens whatever the key says.

4. **Point in time (settled).** At `t`, a spin-off adjusts only when all of the following hold: the row's `known_at ≤ t`; E is on or before `t`'s session; and the child's bar on E and the parent's prior bar both have `known_at ≤ t`. A later revision of any of the three changes reads at later `t` only. A spin-off that becomes effective only after the step whose period contains E has passed follows req 5's late-dividend rule word for word (the dividend-in-kind equivalence of item 2): earlier steps' equity is never restated. The rebalance row of the step that first knows it counts it as `n_late_spin_offs`, on a parent held on E, as `n_late_dividends` counts. Spin-off stamps are often late: a row's `known_at` is the session after Alpaca's `process_date`, which can be weeks after E (data-foundation open question 18). So on a `daily` book most spin-offs will be late, and the count is how that shows. The lookahead cases are a `spinoff` row, a child bar and a revision of either, each planted after `t`: each changes no price at or before `t`.

5. **The counts (settled; where they live is question 27).** **`n_spin_offs_unvalued`** and **`n_late_spin_offs`** are named counts in **`trial_rebalance_counts`** (ADR 0014 point 3, schema version 14): once per rebalance at the base level, through `RebalanceRow.counts`. **No schema change, no migration.** They are written only under `adjust.apply_spin_offs = true`, so a `false` trial, H1 and the TWIN included, writes no new row and every pinned digest is unchanged. They count the spin-offs of parents the step holds, as `n_dropped_dividends` and `n_late_dividends` count dividends: `engine.py`'s rebalance-row write site, through the provider's `unvalued_spin_offs` and `late_spin_offs`. The backtest page shows them with the rebalance's named counts.

6. **The data vintage (settled, its staling open: question 28).** `registry.data_vintage` gains `spin_offs: bool = False`. When true, it also counts `corporate_actions` rows of type `spinoff`. Every caller that has a trial passes that trial's frozen `adjust.apply_spin_offs`: `registry.py`'s registration, staleness and backup-equality reads (lines 914, 1015, 1819), `lab.py:632` and `lab_queries.py:307`. The release-level vintages (`registry.py:1728`, `1767`) stay `spin_offs=False`. A trial that reads spin-offs is staled by a new one, and no other trial is: the 88 rows T172d stored on 2026-10-16 stale nothing that does not read them.

7. **What paper does (settled for the backtest; the paper side is a new task).** Paper journals a spin-off child as a `spinoff_receipt` and sells it whole on the next session (`exits.py`). Today it reaches that only at `window.start`, for a residue between windows (T64). Inside an open window, `reconcile_run` passes `spinoffs = {}`, so a child the broker books is an `unknown_symbol` or `broker_only_position` mismatch, which fails closed. Its docstring's "until T48b" is stale, since T48b is ticked. Agreement on a spin-off session therefore needs a paper task outside T211b to T211e (#1896, paper spec, safety-reviewer). That task fills `explanations.spinoffs` from the `spinoff` rows known at S whose parent the ledger held on the session before E, and settles how long a child may wait for its row. Once both sides exist, they book the same value. The backtest credits D per parent share held on E inside the parent's total return. Paper receives r child shares per parent share and realises them at its next-session fill. The difference is the child's move from close(E) to that fill, plus the parent-only exposure in between: a tracking residual, measured by the existing comparison, not a booking error. **That holds only for a spin-off the backtest values in time.** A late one (item 4) is a **booked disagreement of D per parent share**: the backtest loses it, while paper holds the child. Item 4 expects that to be most spin-offs on a `daily` book. `n_late_spin_offs` counts it, and question 29 puts that consequence to the owner. A `true` book that holds a parent through a spin-off before #1896 lands keeps failing closed on paper, as it does today.

*Acceptance (testable).* Equivalence: on a hand fixture, a valued spin-off gives the same adjusted frame, marks and equity to 1e-12 as a dividend of amount r × C on E. Each unvalued reason leaves the frame equal to the row-deleted frame and is listed by `unvalued_spin_offs_as_of`. `include_spin_offs=True` without dividends raises. The data-foundation pin test holds at the default, and with the flag the frame differs from the row-deleted frame only on the parent's sessions before E, by the factor. A planted row, child bar or revision known after `t` leaks nothing. The marking cache rebuilds the parent when the row becomes known. One step late, a spin-off is counted in `n_late_spin_offs` and changes equity exactly as a dividend of amount D that late would. `data_vintage(spin_offs=False)` ignores a `spinoff` row and `spin_offs=True` does not. H1's and the TWIN's fingerprint, hash and digests are unchanged, and they write no spin-off count. The backtest page shows a `true` trial's two counts.

*Config keys* (default; source): `adjust.apply_spin_offs=false` (frozen, `POST_REGISTRATION_ADJUST_KEYS`, a `FROZEN_KEY_DEFAULTS` entry at the schema version current when it lands); no schema change; no `.env.example` variable.

## Amendment 2026-10-19 (#657): the `momentum` buy/hold buffer, `strategy.hold_top_fraction`

**Why.** [H1](../hypotheses/h1-momentum-12-1.md) and [G1](../research/2026-09-25-g1-momentum-post-2010.md) name a buy/hold buffer as a second hypothesis in the `momentum` family, not a variant of H1. In Novy-Marx & Velikov (RFS 2016), a buffer that buys into the top 10 % and holds a name until it leaves the top 20 % cut turnover from about 34.5 % to 18.8 % per side per month and raised the net return from 0.68 to 0.85 %/month (value-weighted decile long-short, 1963–2012). The [strategy-lab spec](strategy-lab.md)'s Out of scope says a hysteresis band can become a sweep axis only after a spec amendment adds it as a new `strategy.*` key, with a `FROZEN_KEY_DEFAULTS` entry that preserves today's behaviour. Team hypfiles found that no such key exists (#657, 2026-10-10). **Owner decision, 2026-10-19 on #657:** go ahead. The order is this amendment, then the engine build (the [plan](../plans/backtest.md)'s T238 and T239), then the sweep file. The owner accepts the cost: one more trial in `momentum`'s N, which raises the family's deflated-Sharpe bar. ADR 0023's break-first rule gives engine work only to a kill-ladder survivor; the owner's decision is this item's exception to it, with a rung-1 cost note on #657 before the sweep file (open question 32, decided 2026-10-19). **The #1731 invariant holds:** at the default, H1's and the TWIN's canonical sets, fingerprints and hashes, the reference metrics and every registered trial's rows are unchanged. Nothing else in this spec changes.

1. **The key (settled).** `strategy.hold_top_fraction` is a share in [0, 1]. Its default is **0.0**, which means "no buffer": the hold cut equals the buy cut. `StrategyConfig` accepts 0.0, or a value with `top_fraction ≤ value ≤ 1`. It refuses a value in (0, `top_fraction`), and the message names both keys. **A value equal to `top_fraction` is normalised to 0.0 by the validator.** So a file that names it and a file that leaves it out have one frozen set, one canonical set and one fingerprint. That keeps a sweep from gridding an unbuffered duplicate: the lab spec's req 1 refuses two variants with one fingerprint, and it refuses a fingerprint that is already registered. A non-default value with `strategy.weighting = hold` is refused, because hold mode has its own exit rule and the buffer is a rule of `equal` weighting. The key also joins these tables:
   - `FROZEN_KEY_DEFAULTS` gains `("strategy.hold_top_fraction", 0.0, <the schema version current when it lands>)`, appended last.
   - `POST_REGISTRATION_OWN_KEYS` gains it in the same PR, under the #1358 item 3 rule. Absent from a file, the key is frozen at 0.0, never from the live `Settings`, and no stored fingerprint moves.
   - `FAMILY_ONLY_KEYS` maps it to `momentum`, so an `oracle` or `combined` file or sweep with a non-default value is refused naming the key (#1358 item 1).
   - `FAMILIES["momentum"].sweepable_keys` gains it, and so does `count_names` (`n_retained`, item 2).
   - It takes no `lab.axis_lattice` entry, as `strategy.turnover_top_fraction` took none: `momentum`'s family rules copied their lattice at the family's first registration.
   - The lab spec's "Read group" key list is unchanged.
   - Until T239 applies the key, it is in `NOT_YET_APPLIED_KEYS`, so `load_frozen` refuses a non-default value and no run records results under a label the engine ignores.
   - `.env.example` does not change.
   - A `long_short` file with a non-default value is refused **`refused_portfolio`**. This extends the #1872 item 1 rule for `hold` and the band, because a buffered signed book is not specified.

2. **The retention rule (req 3; `momentum`, `equal` weighting; settled).** At plan i, `ranked` is the plan's scored names, by score descending with ties by `security_id` ascending. These are the scores the plan targets from, after B10's screen, rung 4's delay and rung 5's placebo. Let n = |ranked|, k = `_selected_count(n, top_fraction)` and h = `_selected_count(n, hold_top_fraction)`, so h ≥ k and both use the same count rule. Then **targets_i = ranked[:k] ∪ {s ∈ P_{i−1} : s ∈ ranked[:h]}**. P_{i−1} is the set of names with a non-zero target in the **previous plan of the same run**, **after the successor-chain renaming the engine already applies to that plan's targets at t_i** (`_rename_chained`, #821): a held name that became A' through a ticker change or merger is retained as A' when A' ranks inside h. It is empty at the run's first plan. P_{i−1} is **carried** from step i−1, never recomputed at step i, so a revision known after close(T_{i−1}) cannot change it. Each target gets `_equal_weight(|targets_i|)`, req 3's `equal` rule (every selected name the same weight, summing to at most 1). So the book holds between k and h names, and a retained name is reset to the common weight at every rebalance (open question 33, decided 2026-10-19). A name that is not ranked at T_i is never retained, whether it was excluded for any reason, delisted or left the universe. P_{i−1} is the previous plan's targets, not the book's positions. It is therefore the same at every cost level, and a `Plan` stays one per step, "identical for every cost level". In one rare case the two differ: a name the book exited between rebalances (delisting or stale exit) that is still ranked inside h at T_i is entered again; the rule says so. `n_retained` = |targets_i ∖ ranked[:k]| is a plan count. It goes to `trial_rebalance_counts` by name (ADR 0014 point 3) and is **reported only when the buffer is on**, the #1358 pattern. The paper plan trial writes none. `strategy.rebalance_band` applies after the rule, as it does today. **At 0.0 no new path runs:** the targets are `target_weights`' output, with no read of the previous plan and no count, byte for byte.

3. **Turnover and costs (reqs 4 and 6; settled).** No formula changes. An exit is sold whole. An entry is bought at 1/|targets_i|. A retained name trades only its reweight, from its drifted weight to 1/|targets_i|, or nothing when the band covers the drift. `trial_rebalances.turnover`, `cost_paid` and `n_targets`, and the period turnover metric, are computed as today at every cost level. The buffer's saving therefore shows where H1's turnover shows, and rung 1 of the kill ladder can read it. A month with many retained names holds more names at smaller weights.

4. **Run starts and the engine's entry point (req 13; settled).** Every run starts with P = ∅, just as every run starts in cash. An in-sample run, a holdout run and a forward tracking trial each begin from no previous targets, so the first plan of each is the unbuffered one. P_{i−1} comes from reads at t_{i−1} ≤ t_i, so truncation and prefix invariance hold. Invariance to the start date does not hold, and the spec does not claim it. The public `engine.plan`, paper's entry point, gains a keyword-only `previous_targets`. For a registration with the buffer on, a call that omits it raises `ValueError` naming the key; an explicit empty mapping means a first plan. The paper planner calls `engine.plan` without the argument today, so on a buffered window its plan trial fails (`PlanTrialError`, the run ends `failed`), and it never trades an unbuffered plan under a buffered label. This fails closed like `_refuse_hold` (#1832), with one difference: `_refuse_hold` refuses before any trial opens, while this opens the plan trial and fails it.

5. **Look-ahead (req 13).** The suite runs truncation invariance, prefix invariance and the plan-read check over a buffered `momentum` twin. A **revision case with teeth**: a bar revision known after close(T_i) that would move a held name across h at T_i leaves `run(end=T_i)` unchanged and changes `run(end=T_{i+1})`. A **carried-state case**: a revision to a bar on or before T_{i−1}, known in (close(T_{i−1}), close(T_i)], that would move a name across k at T_{i−1} leaves plan i−1's targets unchanged, and plan i's retained set equals `buffered_targets(scores_i, P = the unrevised plan i−1 targets, …)`; the case fails on an implementation that re-plans T_{i−1} inside step i. A **chain case**: a held name renamed by a successor chain and ranked between k and h at T_i is retained. The **pinned check**: with the key absent or equal to `top_fraction`, the pinned fingerprints and canonical sets in `tests/backtest/test_frozen_defaults.py` (H1's, the TWIN's, `combined`'s) are unchanged, as are the fixture twin's `in_sample` run metrics and its fake provider's call log.

6. **Paper (not built now).** Paper is built only if a buffer variant is promoted and the owner opens a paper book for it (the [paper plan](../plans/paper-trading.md)'s T240, owner-gated). The paper planner then passes `previous_targets` from the window's `paper_plans` row for the latest rebalance session strictly before T_i (chosen as `report._latest_plan` chooses), renamed through the successor chains known at t_i. When T_{i−1}'s row is missing after `window.start`, the plan trial fails closed. Where a window's first plan takes P from is open question 34. `momentum`'s holdout is spent (ADR 0023; ADR 0016), so such a book is a tracking window, never an exam of record. For the same reason a buffer variant's trials are in-sample only: T240's trigger is the owner's decision to open a paper book for one, whatever route that takes.

**Trial count.** Each grid value is one hypothesis, and each run of one is a trial in `momentum`'s N (the lab spec's reqs 1 and 7). That raises the deflated-Sharpe bar of every `momentum` reading made at the larger N. The owner accepted one trial, so the sweep file is a one-value grid: `top_fraction = 0.10`, `hold_top_fraction = 0.20` (open question 31, decided 2026-10-19).

*Acceptance (testable).*

At `top_fraction = 0.10`, `0.05` is refused naming both keys, `1.5` is refused, and `0.10` stores `0.0`. `0.20` with `weighting = "hold"` is refused. The table's last entry is the key at `0.0`. `POST_REGISTRATION_OWN_KEYS` and `FAMILY_ONLY_KEYS` are pinned with the key. An `oracle` or `combined` file naming `0.20` is refused naming the key. `lab.sweepable_keys` lists the key. The fixture twin with the key at `0.10` has the TWIN's fingerprint and canonical set; at `0.20` it has another. Before T239, `load_frozen` refuses `0.20`.

## Amendment 2026-10-19 (#1598): the known-answer index check, outside the trial count

**Why here, and why an amendment.** Nothing checks the data, the universe and the return arithmetic against a known answer, and every trial rests on them. The check holds the whole universe with no signal and compares it with SPY and RSP (#1598). The owner decided on 2026-10-12 that it is a proper feature, that its window is 2019-08 to 2026-09 including the holdout years, that those years show only the gap and the names behind it, and that it is never a strategy trial; he lifted the ADR 0023 D5 pause on it on 2026-10-19. The feature is size M, and the [doc types](../README.md#document-types) keep a new spec for size-L work. It reuses this spec's marking frame (req 1), its delisting exit (req 5) and its benchmark series (Definitions, "Series"), and it is defined by what it must not be: a trial. So it is a dated amendment here, and the [plan](../plans/backtest.md)'s T243 to T247 build it. The owner's read-only first pass (#1598, comment of 2026-10-12) is the method's prototype; its defects are already filed (#1613, #1614, #1615). **Invariant:** the check writes nothing to any store; no registered canonical set, fingerprint, hash, trial row, data vintage or holdout spend moves, and no trial reads anything it adds.

1. **What it computes (settled).** For each month m in the window, with T_{m−1} and T_m the last XNYS sessions of the previous month and of m (`calendar.last_session_of_month`) and t_m = close(T_m):
   - *Members* M_m: `universe_as_of(conn, t_{m−1}, settings).members`, read at t_{m−1}, under the live `Settings` (question 35), each with its `market_cap`.
   - *Weights.* Equal: 1/|M_m| per member. Cap: `market_cap` / Σ `market_cap` over the members whose cap is positive and finite; a member without one is left out of the cap book and counted (`n_no_cap`). Caps rest on cover-page shares, not float-adjusted, which is a known source of cap-weight tracking error (#1598, first pass), stated in the output.
   - *Name return* r_j = A_j(e) / A_j(s) − 1 from one frame, `adjusted_prices_as_of(conn, t_m, M_m ∪ {SPY, RSP}, include_dividends=True, traded_only=True, include_spin_offs=settings.adjust.apply_spin_offs)`, the engine's marking read (req 1, amendment #787), where s is the member's latest traded bar at or before T_{m−1} and e its latest at or before T_m. A member whose listing ends inside the month therefore ends at its last traded close and its proceeds earn nothing to T_m (req 5, no delisting return). A member with no traded bar at or before T_{m−1} has r_j = 0 and is flagged `no_entry_bar` (item 4).
   - *Index return* R_m = Σ_j w_j (1 + r_j) − 1 per weighting, rebalanced at close(T_{m−1}): zero costs, no cash, no signal, no fill lag. The benchmark return r_b is SPY's or RSP's A(T_m) / A(T_{m−1}) − 1 from the same frame. Both series share the same two instants, so the gap isolates data and arithmetic, not the fill convention, which the `bt` oracle checks (ADR 0004).
   - *Gap* G_m = R_m − r_b: equal weight against RSP, cap weight against SPY. *Year:* G_y = Π(1 + R_m) − Π(1 + r_b) over the window's months of year y; *tracking error* TE_y = the sample standard deviation of that year's G_m × √12, blank with fewer than two months. The same pair is printed over the development months and over the protected months as two totals.

2. **Never a trial: no `open_trial`, no new kind (settled).** The check calls no `registry` writer and opens no handle. It cannot use `StoreProvider`, which requires a `TrialHandle` (`store_provider.py`); it reads through `store.asof`, `universe.universe_as_of`, `store.delistings` and `store.benchmarks` on its own short-lived read-only connections (`store.db.open_read_only`), one per month as the provider does. The alternatives were rejected:
   - *A `trials` row of an existing kind.* It needs a registered hypothesis and a family. The check has neither; an `index` family would get family rules, a holdout and a place in every lab view. An `in_sample` row counts in N (`registry._COUNTED_FROM`: in-sample, non-synthetic, `ok`), and a `holdout` row is a spend (`family_holdout_spends` reads every `kind = 'holdout'` row). `synthetic=True` is refused on the real store.
   - *A fourth, non-counted kind.* `TrialKind` is a literal pinned by the `trials.kind` CHECK, so it needs a migration and an audit of every `trials` reader: N and V, holdout spends, staleness, backup equality, `lab status`, the trials page. One missed filter would put the check into N or a spend count, which is exactly what the owner ruled out. The gain is a row with no parameters to deflate.
   - *A research-registry `return` run.* A `touches_returns` run must name a family and raises its N (research-registry spec req 9), and a window over a protected one is refused or spent (req 5).
   CLAUDE.md rule 7 logs every backtest run of a strategy. The check has no hypothesis, no parameter to choose among and no selection. Under the research-registry Definitions it reads outcomes (returns) and no treatment, so it is not a run. What keeps it from becoming a strategy is structural, and tested: it takes no score, filter or name list; its weightings are the two above; its CLI options are a pinned set; and its modules import no registry writer and no engine entry point.

3. **Where the benchmark returns come from (settled; two cases open).** Stored bars only, through the same marking frame as the members, total return (dividends included), so the store's own adjustment is under test along with the members'. SPY is stored (`benchmarks`, 2016-01-04 on). RSP is not, and it must not become a trial series (`benchmarks` is a frozen key, and a third entry would add a series to every new registration). So:
   - **A check-only symbol.** A new non-frozen config section `index_check` holds `check_only_symbols` (default `["RSP"]`). A validator refuses an overlap with `benchmarks`. `backfill_benchmark` (and `tradepartner backfill-benchmark`) accepts a symbol in either list, and seeds `BENCH:RSP` (`benchmark = TRUE`, source `config`) exactly as it seeded MTUM (#840). It still refuses when another security already lists the ticker (question 36). The [runbook](../runbooks/benchmark-backfill.md) gains the RSP command. From then on the daily ingest fetches it as it fetches every benchmark-flagged security.
   - **No trial can read it.** `store.benchmarks.CHECK_ONLY_IDS` (a pinned, append-only `frozenset`, starting `{"BENCH:RSP"}`) names the check-only securities. `benchmark_security_ids` refuses to resolve one unless the caller passes `check_only=True`, which only the index check does. A frozen `benchmarks` that names RSP therefore fails the trial by name rather than reading it.
   - **No trial's vintage moves.** Backfilled bars keep their session-close `known_at`. Counted, they would move the data vintage of every trial whose cutoff is after 2016 and stale every counted trial once (the risk the spin-off amendment, item 6, avoided). `registry.data_vintage` leaves out `prices_daily` and `corporate_actions` rows whose `security_id` is in `CHECK_ONLY_IDS`, under both values of its `spin_offs` argument (the `spin_offs=True` path replaces the `corporate_actions` clause today, `registry.py:570-571`, so the exclusion is added to both clauses and to a new `prices_daily` entry). This is exact, since no trial can read those rows (question 37). The seeded `securities`, `listings` and `classifications` rows are stamped at the clock, after every stored cutoff, so they move nothing.
   - A benchmark with no traded bar on T_{m−1} or T_m stops the run with `missing_benchmark_bar <symbol> <session>`; the check never carries a stale benchmark mark.

4. **Attribution: the names behind a month (settled).** The contribution of member j is c_j = w_j (r_j − r_b), and Σ_j c_j = G_m exactly, because the weights sum to one. For each weighting, the `index_check.worst_months` months with the largest |G_m| (both signs, question 39; ties by month) are listed. Each lists its `index_check.names_per_month` members with the largest |c_j| (ties by `security_id`), plus every member with |r_j| ≥ `index_check.extreme_name_return`. Each listed name shows its ticker at t_m, c_j in percentage points, and its **flags**, each read as of t_m for the month (T_{m−1}, T_m]:
   - `missing_bars=<n>`: XNYS sessions in the month with no traded bar while the name is listed (`traded_only` drops zero-volume bars, so these are missing too);
   - `no_entry_bar`: no traded bar at or before T_{m−1};
   - `split=<ratio>`: a `split` row with its ex-date in the month (more than one: each);
   - `dividend=<amount>` and `dup_dividend`: a `dividend` row in the month, and two live rows with one ex-date and one amount under different source ids, the #1613 pattern, shown even where the pair is real (F 2025-02);
   - `dropped_dividend`: listed by `dropped_dividends_as_of` at t_m;
   - `spin_off`: a `spinoff` row whose parent is the name, valued or not per `adjust.apply_spin_offs`;
   - `delisted`: a listing end in the month (`listing_ends_as_of`), so the name exited at its last traded close;
   - `extreme`: |r_j| ≥ `index_check.extreme_name_return`.
   Each month also prints a census: the count of members carrying each flag. The census and the flags are counts and labels, never return levels, so they print in every month.

5. **Protected months: gaps only (settled; the owner's 2026-10-12 guard).** A month m is **protected** when T_m is after the edge E. E is the earlier of the store's development boundary (`registry.development_boundary`, ADR 0016) and the day before the earliest `holdout.start` over the registered non-oracle families' rules (`lab_registry.family_rules`). With neither in the store, every month is protected (fail closed). A year with any protected month is a protected year. On today's store E is 2023-12-29, so 2024 to 2026 are protected. For a protected month or year, the output carries G, TE, the census, and the worst-month names with their c_j and flags. **It carries no level of either series**: not R_m, not r_b, and not a name's r_j. A benchmark level is public, but gap plus benchmark is the universe level, so the benchmark's level is withheld too. The protected rows' type has no level fields, and the JSON has no level keys for them, rather than nulls. An `extreme` name in a protected month is listed by its flag, with no r_j. The header prints E, its source, and "protected months show gaps only (owner, 2026-10-12, #1598); not a trial, nothing written". That line is the run's record of the owner's OK (question 38). Reading these months spends no holdout. The owner ruled the check out of the holdout rules, it reads no hypothesis, signal or family, and ADR 0016's refusal binds the paths that build a family's window (`backtest`, `sweep run`, a research run), and this is none of them. The guard keeps return levels off the record; it is not secrecy, since public benchmark returns and the printed gap give the level by addition.

6. **The output (settled).** `tradepartner index-check [--start YYYY-MM] [--end YYYY-MM] [--out PATH]` (2026-10-20, owner on #2045: no `--store`; the configured store, as every command). The window defaults are `index_check.start_month` and `end_month`. It prints:
   - a header: the store path, its schema version, the code version and dirty flag, the data vintage at close(T_end), the `universe.*` and `adjust.apply_spin_offs` values used, E, and the protected line;
   - a **by-year** table: months, members at the year's first rebalance, then EW, RSP, EW−RSP and TE, then CW, SPY, CW−SPY and TE, with levels shown as `·` in protected years;
   - the two zone totals;
   - a **by-month** table with the same columns plus `n_no_cap` and the flag census;
   - the **worst months** per weighting, with their names (item 4).
   `--out` writes the same masked content as JSON. Exit 0 when printed. Exit 2 on a refusal, before any month is read: `refused_window` (a start whose T_{m−1} is before the calendar's first session, an end month not completed at the clock, or an end before the start); `refused_rank_by` (`universe.rank_by` is not `cap`, so no member has a cap); a `BenchmarkIdentityError` for SPY or RSP. Exit 1 when a month fails after reading has begun: `missing_benchmark_bar`, or the `ValueError` `universe_as_of` raises when a rule-6 jump candidate carries an invalid corporate action. The owner runs it on the real store, read-only; agents run it only on fixture stores (CLAUDE.md rule 9). **A dashboard page is a later, separate line** (T247), not claimable until the owner asks for it on #1598.

*Acceptance (testable).*
- **Three-name hand case.** A, B and C with caps 1, 1 and 2 at both rebalances, and a synthetic benchmark. The tolerance 1e-12 applies to the exact expressions (for example the year's equal-weight gap, (76/75)(1.01) − (1.01)(1.02)); the figures below are their rounded displays. Month 1: returns +10 %, −10 % and +4 %, benchmark +1 %. Month 2: returns 0 %, +5 % and −2 %, benchmark +2 %. Expected:
  - equal weight: R = 1.3333 % and 1.0000 %, gaps +0.3333 and −1.0000 pp, year gap −0.6733 pp, TE 3.266 %;
  - cap weight: R = 2.0000 % and 0.2500 %, gaps +1.0000 and −1.7500 pp, year gap −0.7650 pp, TE 6.736 %;
  - month 1's equal-weight contributions: A +3.0000, B −3.6667, C +1.0000 pp, summing to the gap (to 1e-12).
- **Missing bars.** On the fixture store, a member with two sessions of missing bars in a planted bad month is listed in that month's attribution with `missing_bars=2`.
- **Flags on the fixture.** A planted duplicate dividend is flagged `dup_dividend`. A member delisted mid-month ends at its last traded close and is flagged `delisted`. A member without a cap is left out of the cap book and counted.
- **Protected rows.** With E set between the two months, the protected month's printed level cells are `·` (checked by column, not by a text search, since a level's digits can recur inside a gap) and its JSON has no level key; the development month shows its levels.
- **Point in time.** A bar revision, a dividend and a listing end, each planted with `known_at` after t_m, change nothing for month m.
- **Writes nothing.** After a run, every table's row count and the schema version are unchanged, every connection was read-only, and the modules import from `store.registry` and `store.lab_registry` only a pinned allow-list of reads (`development_boundary`, `data_vintage`, `family_rules`), and nothing from `backtest.engine` or `backtest.holdout`. A `missing_benchmark_bar` month exits 1 with that message.
- **No selection input.** The CLI's option set is pinned.
- **RSP.** `backfill_benchmark` accepts RSP and refuses a symbol in neither list. A `BENCH:RSP` bar planted with `known_at` before a cutoff leaves `data_vintage` unchanged. `benchmark_security_ids` refuses `RSP` without `check_only=True`. The config refuses RSP in both lists.
- **Pins unchanged.** H1's and the TWIN's fingerprint, hash and digests are unchanged.

*Config keys* (defaults; source): the `index_check` section, **not frozen** and part of no hypothesis: `start_month="2019-08"`, `end_month="2026-09"` (the owner, 2026-10-12); `check_only_symbols=["RSP"]`, `equal_benchmark="RSP"`, `cap_benchmark="SPY"` (#1598); `worst_months=10`, `names_per_month=5`, `extreme_name_return=0.60` (the first pass's ±60 % screen). Also `store.benchmarks.CHECK_ONLY_IDS={"BENCH:RSP"}` (a code constant, pinned). There is no schema version, no `.env.example` variable and no new dependency.

*Out of scope:* the fill path and costs (the `bt` oracle checks them); a delisting haircut (open question 4); fixing what the check finds (each defect is an issue, as #1613 to #1615 were); S&P membership; float-adjusted caps; a dashboard page before T247; any use of the check's output to choose a universe rule or a strategy parameter. Such a use would be a search over the universe, so it goes through a hypothesis and the lab.
