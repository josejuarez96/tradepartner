# Spec: Backtest engine and trial registry (Phase 3)

**Status:** Draft  ·  **Issue:** #51  ·  **Related:** [ADR 0003](../decisions/0003-data-adapters-local-first.md) (rules 5, 6, 8), [ADR 0004](../decisions/0004-tooling-adopt-avoid.md) (engine, oracle, metrics), [ADR 0005](../decisions/0005-objective-benchmark-stop-criteria.md), [ADR 0006](../decisions/0006-universe-and-cadence.md), [roadmap Phase 3](../roadmap.md), [data-foundation spec](data-foundation.md), [handoff](../research/2026-09-24-initial-research-handoff.md) §7 D1 and §12 item 7, [trial registry](../research/trial-registry.md), research [G1](../research/2026-09-25-g1-momentum-post-2010.md) (PR #61, unmerged at drafting), [G3](../research/2026-09-25-trend-timing.md), [G4](../research/2026-09-25-g4-signal-combination.md), [G8](../research/2026-09-25-price-vendors.md), [free-data terms](../research/2026-09-25-free-data-terms.md)

## Problem & why now

Phase 2 answers "what was knowable at T?". Phase 3 asks the next question honestly: *how would a rule have done, using only what was knowable at each step, net of costs, with every attempt counted?* This spec builds the backtest engine, the cost model, the locked holdout, the trial registry in the store, deflated Sharpe reporting, the `bt` oracle check, the `backtest` CLI and the two dashboard pages. It is where charter principles 2, 4 and 6 (count every trial, point-in-time data, tune on process not P&L) become code with tests.

The first registered hypothesis is the MVP strategy from the roadmap: long-only, monthly-rebalanced 12-1 momentum on the ADR 0006 universe, against SPY and MTUM buy-and-hold. The evidence (G1) puts its net excess return near zero, so the point of Phase 3 is a correct, auditable engine, not a good number.

## Users & usage

- **The owner** registers a hypothesis by merging its file and running `tradepartner hypothesis register`, runs `tradepartner backtest <hypothesis>` from time to time, and reads the backtest page and the trial-registry view. Only the owner spends the holdout, overrides the gap gate, signs off on the gap, writes the price-vendor ADR and runs anything against the real store (CLAUDE.md rule 9: agents never enter the main checkout).
- **The `backtest-runner` agent** (candidate in [agents.md](../ways-of-working/agents.md)) runs a registered hypothesis **only on a temp-file or fixture store** (synthetic trials, `store_path` set explicitly) and reports. Its trials never enter the owner's N and V, it never runs on the real store, and it never passes a holdout or override flag.
- **Phase 4** reads trial results to compare paper returns with the backtest (ADR 0005, `paper.tracking_k`) and needs the owner's gap sign-off row (ADR 0003 rule 8).
- **Tests**, on every PR, run the engine on the fixture universe with the network disabled, including the truncation-invariance suite and the `bt` oracle.

## Definitions

- **Rebalance session** T_i: the last XNYS session of a calendar month (ADR 0006), from `calendar.last_session_of_month`. **T** as an instant is close(T_i) (`calendar.session_close`), tz-aware UTC, as in the Phase 2 spec.
- **Fill session** F_i = `calendar.next_session(T_i)`. The fill price is F_i's open or close per `execution.fill_price` (ADR 0006; `close` since T3).
- **Step** i: the work done at read time close(T_{i+1}) for the holding month (F_i, T_{i+1}]: value the month, then compute the next signal and targets. Every provider read of a run uses a rebalance close as `t`.
- **Data cutoff** of a run: close of its last rebalance session. Nothing is read with a later `t`.
- **Month i return**: equity at close(T_{i+1}) over equity at close(T_i), minus one. Monthly returns are the unit for Sharpe, skew, kurtosis and the ADR 0005 paper-tracking check. `MONTHS_PER_YEAR = 12` is a constant derived from the ADR 0006 cadence, not config.
- **Hypothesis**: a file under `docs/hypotheses/` with an economic rationale, a fixed parameter set including its holdout window, expected magnitudes, the prior evidence already seen for the holdout period, and a retirement condition, registered in the store before any run (domain rule 1). Each belongs to a **family** from the enumerated `hypotheses.families` list, the unit for counting trials and holdout spends.
- **Trial**: one engine run, from the moment the registry issues a trial handle. Failures, refusals, crashes and reruns are trials. **Kind** ∈ `in_sample`, `holdout`, `tracking` (Phase 4's paper-period comparison; reserved here, never counted as holdout). A **synthetic** trial runs on a store whose file is not `settings.store.path` (tests, the oracle) and is excluded from the trial count (ADR 0004); the CLI cannot create one, and the registry refuses `synthetic=True` or `family=oracle` on the real store.
- **In-sample window**: from the hypothesis's `in_sample_start` to the last rebalance session before its frozen `holdout.start`. **Holdout window**: the hypothesis's frozen `[holdout.start, holdout.end]`, both dates named in the file. Sessions after `holdout.end` belong to Phase 4 tracking and are refused here.
- **Series**: `strategy`, `SPY`, `MTUM` (from `benchmarks`). Benchmarks are buy-and-hold, total return, under the same fill convention and cost model (ADR 0005), so their only trade cost is the initial buy.

## Requirements

1. **Engine over the as-of API only.** The engine reads market data through a `DataProvider` protocol whose every method takes a tz-aware `t`. The store-backed provider calls only `store.asof`, `store.master`, `store.delistings`, `universe.universe_as_of` and `gap.survivorship_gap`, passing the trial's frozen `Settings` into every call, never an adapter. It opens a **short-lived read-only connection per step** (from a connection factory) so a long run never holds the store against the ingest job. At step i, with `t = close(T_{i+1})`, it reads: the **marking frame** `adjusted_prices_as_of(t, held ∪ benchmark ids, include_dividends=True)` for the sessions F_i..T_{i+1}; the universe `universe_as_of(t)`; the **signal frame** `adjusted_prices_as_of(t, universe ids, include_dividends=strategy.signal_total_return)`; listing ends; dropped dividends; late dividends (req 5); the survivorship gap. The provider is read once per step and every cost level is evaluated from the same reads. A rebalance date is a calendar output, never a weekday rule.
2. **Position valuation, one frame per step.** Positions are carried as dollar values, not share counts. Within step i every price ratio comes from the marking frame alone: a position bought at F_i is worth value × P(s)/P(F_i) at session s, and P is the adjusted-as-of-`t` price. So a split inside the month cancels and a dividend inside the month is reinvested in the paying name on its ex-date, whichever `strategy.signal_total_return` says; an action that becomes known only after its ex-date enters the first step whose read time knows it. Reported `shares` are value over the raw fill price, for the page and the weights table only. The drifted value at close(T_{i+1}) carries into step i+1, where the marking frame as of close(T_{i+2}) prices it forward to F_{i+1}. `BacktestResult` exposes the per-step marking frames, targets and the stitched return series (req 14 needs them).
3. **Signal and portfolio (pure functions).** 12-1 momentum: the adjusted close at the last session of month T−`strategy.skip_months` over the adjusted close at the last session of month T−`strategy.formation_months`, minus one; a name lacking either bar is excluded and counted. Target weights: the top `strategy.top_fraction` of ranked names, `strategy.weighting` (`equal`), long-only, ≥ 0, sum ≤ 1, remainder cash; ties by `security_id` ascending. Cadence and hold are ADR 0006, not config.
4. **Fills, costs, cash.** Trades are target minus drifted weights, fractional, at the fill price. Buys are sized so that cash after costs is never negative (a buy's notional is scaled by 1/(1 + per-side rate)). A target name with no bar on F_i is not bought; a held name to be sold with no bar on F_i is not sold and stays at its last mark until the next fill session or an exit rule; both are counted as `missing_fill`. A held name with no bar on a session keeps its last mark. Cash earns `backtest.cash_rate` (0). Equity = cash + Σ position values on every session; cash changes only by fills, costs and `cash_rate` (dividends are reinvested in-name by req 2).
5. **Delistings, stale names, late dividends.** A held name whose listing has ended by the step's read time (Phase 2 req 4, derived from rows known at `t`) is sold at its last close on its final session into cash and counted as `delisting_exit` (`backtest.delisting_exit=last_close`, the ADR 0004 oracle convention). A held name still listed at `t` but with no bar in the last `backtest.stale_exit_sessions` sessions before T_{i+1} is exited at its last close and counted as `stale_exit` (open question 4). Exits pay `per_side_bps` and commissions like any sell. A dividend whose ex-date falls in month i but which becomes known only after close(T_{i+1}) is **lost for good** (the step that would have reinvested it has passed); at each step the provider's `late_dividends(t_prev, t, ids)` reports every dividend known in (t_prev, t] whose ex-date is ≤ t_prev, on a name held on that ex-date, however many months late it arrives, and the rebalance row counts them as `n_late_dividends`. Both exit counts, the survivorship gap at every rebalance (ADR 0003 rule 5, count and size share), the universe size and the number of members whose listing rests on `snapshot_static` rows (#35) are part of every result.
6. **Cost model (pure).** Cost of a trade = notional × `costs.per_side_bps` / 10⁴ + shares × `costs.commission_per_share` + `costs.commission_per_order`, charged from cash at the fill. Every run is evaluated at the base level and at each level in `costs.sensitivity_per_side_bps` (commissions unchanged) from the same reads; strategy metrics, equity and rebalance rows are stored per level (`cost_per_side_bps` column); target weights are identical across levels and stored at the base level only. Sensitivities are never new trials. N, V, DSR and the red flag use the **base** level.
7. **Metrics (pure).** Per series and cost level, with these exact keys: `cagr`, `vol_annual`, `sharpe_monthly` (non-annualized, `metrics.risk_free_rate`), `sharpe_annual` (= `sharpe_monthly` × √12), `sharpe_monthly_excess_spy` (monthly returns minus SPY's), `max_drawdown` (daily equity), `turnover_monthly` (one-sided average), `cost_drag` (gross minus net CAGR), `excess_cagr_spy`, `excess_cagr_mtum`, `tracking_error_spy`, `tracking_error_mtum`, `skew_monthly`, `kurtosis_monthly` (non-excess), `skew_monthly_excess_spy`, `kurtosis_monthly_excess_spy`, `n_months`. The `*_excess_spy` keys are computed for `strategy` and `MTUM` only and stored as null for `SPY`. Standard metrics come from the library ADR 0004 names (chosen in the plan); PSR and DSR are ours.
8. **Deflated Sharpe (Bailey & López de Prado).** SR* = √V · ((1−γ)Φ⁻¹(1−1/N) + γΦ⁻¹(1−1/(N·e))), γ = `numpy.euler_gamma` (0.5772156649015329); DSR = Φ((SR − SR*)√(T−1) / √(1 − γ₃·SR + (γ₄−1)/4 · SR²)), with SR the **monthly, non-annualized** Sharpe of this trial, T = `n_months`, γ₃ = `skew_monthly`, γ₄ = `kurtosis_monthly`. Computed on two **bases**, `raw` (`sharpe_monthly`, `skew_monthly`, `kurtosis_monthly`) and `excess_spy` (`sharpe_monthly_excess_spy`, `skew_monthly_excess_spy`, `kurtosis_monthly_excess_spy`), each with its own inputs (open question 7 picks the headline). **N** = the number of `ok`, non-synthetic, `in_sample` trials in the same family at run time, this one included, reruns included; **V** (per basis) = the sample variance of that basis's monthly Sharpe over the **latest `ok` trial per distinct (parameter hash, window) pair** among them, so a rerun raises N and replaces its pair's value. `family_sharpes` returns both bases and reads only the monthly keys; an annualized Sharpe never feeds V. With fewer than two pairs, SR* = 0 and `dsr_basis=psr`. Stored per trial: `n_trials`, and per basis `sharpe_variance`, `sr_star`, `psr_zero`, `dsr`. The stored DSR uses N and V at run time and goes stale; the page recomputes DSR with **today's N and today's V** (a fresh `family_sharpes` call) from the trial's stored `trial_metrics` inputs and shows it next to the stored value, labelled "N at run time".
9. **Trial registry in the store.** Tables `hypotheses`, `trials`, `trial_results`, `trial_metrics`, `trial_rebalances`, `trial_equity`, `trial_weights`, `owner_decisions` (schema below), created by `store.schema` at schema version 2 with an additive migration from version 1, listed in `REGISTRY_TABLE_NAMES` separate from the fact tables in `TABLE_NAMES` so the look-ahead harness is untouched. A later fact-table DDL change goes to version 3, never a silent edit of version 2. Any writing command (`hypothesis register`, `backtest`, `decision`, `ingest`) migrates a version-1 store; the read-only pages show a "registry not initialised" state instead. **Append-only**: `store.registry` exposes inserts and reads only; a trial's outcome is a separate `trial_results` row, never an update; a trial with no result row is shown as `unfinished`. **Trial handle**: `registry.open_trial` is the only constructor of `TrialHandle`; `StoreProvider` verifies at construction, through a registry connection that may differ from its data connection, that the handle's id exists in `trials`; the engine refuses to run without a handle (ADR 0005: no id, no run). Every trial records hypothesis, kind, window, data cutoff, the store's latest `ingested_at` at open, code version (git commit, dirty flag), the frozen parameter hash, the synthetic flag, reasons, `run_by` and a note. A run fails (`store changed during run`) if the store's latest `ingested_at` differs between trial open and result write. [docs/research/trial-registry.md](../research/trial-registry.md) becomes a pointer to the tables and the `trials` command.
   *Note 2026-09-25 (#117):* #83 took schema version 2 for `corporate_actions.announced_at` first, so the registry ships as **version 3**, migrated additively from version 2, and a later fact-table change goes to version 4. Wherever this spec says "version 2" for the registry, read version 3; "a version-1 store" in this requirement, req 17 and the "Registry and holdout" acceptance line means a version-2 store (the not-initialised state). A version-1 store raises `SchemaVersionError` and is rebuilt, never migrated or shown.
10. **Pre-registration freezes parameters.** The hypothesis file is the source of truth for the keys it names; the live `Settings` fill the rest at registration. The file **must** name `holdout.start`, `holdout.end`, `in_sample_start` and every `strategy.*` and `costs.*` key, or registration fails; the holdout never comes from live `Settings`. `tradepartner hypothesis register <file>` stores the file's SHA-256 and the frozen values of `strategy.*`, `universe.*`, `execution.fill_price`, `costs.*`, `backtest.*`, `adjust.*`, `master.*`, `gap.*`, `holdout.*`, `metrics.*`, `benchmarks` and `alpaca.historical_feed`, prints the full set and its hash. A run uses the frozen values, never the live ones, so no environment variable can move a hypothesis's holdout or threshold. A changed file or a different frozen set is a new hypothesis, never a variant.
11. **Locked holdout and window rules.** The trial handle is issued first. Then, before any provider call: a window starting before `in_sample_start` or ending after the frozen `holdout.end` is refused (`refused_window`; the latter belongs to Phase 4 tracking); a window touching the frozen holdout is refused (`refused_holdout`) unless `--spend-holdout --holdout-reason` is given. A holdout run has `kind=holdout` and its reason; when any hypothesis in the family already spent the holdout it is marked `holdout_repeat` and the page says so (domain rule 3); a repeat for the **same** hypothesis additionally requires `--holdout-repeat`. **Gap gate** (ADR 0003 rule 6): with the flag, the only reads before the gate are `survivorship_gap(t)` at the window's rebalance closes; the run is refused (`refused_gap`) when the count share at any of them exceeds the frozen `gap.count_share_threshold`, unless `--override-gap --gap-reason` records the owner's decision in the trial and in `owner_decisions`. The in-sample default window is `[in_sample_start, last rebalance session before holdout.start]`, so an ordinary run cannot drift into the holdout.
12. **Owner decisions.** `tradepartner decision <kind> --reason` appends an `owner_decisions` row (`gap_signoff` for ADR 0003 rule 8, the Phase 4 entry gate; `gap_override` and `holdout_spend` are also written by the flags in req 11) with the trial it refers to and the gap values at that time.
13. **No look-ahead.** A run ending at T is a function only of rows with `known_at ≤ close(T)`: truncation invariance holds for the whole run, and a run to T_i equals the prefix of a longer run through T_i.
14. **`bt` oracle** (ADR 0004). On a temp-file copy of the fixture universe, with zero costs, fractional shares and the same lagged target weights, `bt` and our engine agree on portfolio equity at every compared session to within the tolerance pinned in the test file. `bt` receives the **stitched frame** from `BacktestResult`: per name, each session's return taken from the marking frame of the step that contains it, cumulated into one price index, so both engines see identical ratios and the fixture's late-known revisions cannot separate them. With `fill_price=close` every session is compared; with `open`, `bt` receives the stitched open series and only fill sessions are compared (a deviation from ADR 0004's wording, recorded in its amendment). The delisted fixture name is sold at its last close on its final session in both, asserted explicitly. The oracle registers its own synthetic hypothesis (`family=oracle`) on that temp-file store and passes its path as `run_hypothesis(..., store_path=...)`, the parameter the CLI never sets; `run_hypothesis` returns the results it wrote.
15. **Red flag.** A trial whose base-level `excess_cagr_spy` exceeds `metrics.red_flag_excess_cagr_pp` is marked `red_flag=true` and the page says so: G1 found no live or gross window above +1.1 pp/yr. A prompt for a look-ahead and cost audit, not a gate.
16. **CLI.** `tradepartner backtest <hypothesis> [--start] [--end] [--spend-holdout --holdout-reason] [--holdout-repeat] [--override-gap --gap-reason] [--note]` (exit 0 ok, 1 failed, 2 refused; prints trial id, metrics table, gap maxima, flags); `tradepartner hypothesis register <file>`; `tradepartner trials [--hypothesis] [--include-synthetic]`; `tradepartner decision gap-signoff --trial <id> --reason`. No `--synthetic` flag exists. No secrets in output.
17. **Pages.** Streamlit, read-only, inside the Phase 2 shell's single read-only connection: a **backtest page** (trial picker; equity of the three series on a log axis; drawdowns; monthly turnover and cost bars; metrics per cost level; both DSR bases with N, V and SR*, stored and recomputed with today's N; gap, universe size, static reliance and late dividends per rebalance; kind, synthetic, repeat, red and refused states; family-wide holdout spends) and a **trial-registry view** (every trial newest first; hypothesis filter; synthetic hidden by default; failed, refused and unfinished rows visible with their message; owner decisions). Both show "registry not initialised" on a version-1 store. No run button: runs are CLI only.
18. **First hypothesis end to end.** `docs/hypotheses/h1-momentum-12-1.md` is registered and run over the in-sample window on the owner's real store, by the owner, under whatever `PriceSource` the price-vendor ADR (plan task T29) names. "End to end" means: hypothesis registered, trial issued, run completed, metrics, both DSR bases and the gap stored, `quant-auditor` passed on the run, page shows the trial, universe size per rebalance in the evidence. It does **not** mean the holdout was spent: on a source above the gap threshold the holdout stays locked, and a result on free data is optimistic and claims no edge (ADR 0003).

## Acceptance criteria (testable)

Engine and timing
- [ ] Every provider call of a run carries `t = close(T_{i+1})` for some rebalance session (recording provider); the fill session is `calendar.next_session(T_i)` across a month-end before a holiday and on a half day (fixture cases).
- [ ] With `execution.fill_price=close` the fill equals F_i's close; with `open`, F_i's open; the two runs have identical targets and weights and different fill prices.
- [ ] Valuation: a synthetic store with a 2:1 split and a dividend both ex inside a holding month values the held name with no jump on the split date and with the dividend reinvested (equity equals the hand-computed total return); a dividend known only after its ex-date but before close(T_{i+1}) changes that step and none before; one known only after close(T_{i+1}) changes no equity and is counted in `n_late_dividends` of the rebalance row of the step that first knows it, whether one or three months late.
- [ ] Momentum on a synthetic frame: the skip month is excluded; a name missing the formation-start bar is excluded and counted; ties rank by `security_id` ascending; weights are ≥ 0, sum ≤ 1 and equal within the selected set; no session after `t` is read.
- [ ] Cash identity on every session; cash is never negative at any cost level, including the ladder maximum.
- [ ] A target name with no bar on F_i is not bought; a held name to be sold with no bar on F_i keeps its last mark and its value until the next fill session; both appear in `missing_fill`; a held name with no bar on an ordinary session keeps its last mark.
- [ ] `SEC_WINDOW_DELIST` held at its delisting exits at its last close on its final session into cash, counted as `delisting_exit`, paying `per_side_bps`; `SEC_TRANSFER` held across October 2018 exits at the 2018-10-31 close (delisted at that read time) and is eligible again once the new listing is known; a name with a trailing gap beyond `backtest.stale_exit_sessions` while still listed exits as `stale_exit`, and one whose gap closes before T_{i+1} does not.
- [ ] Rebalance rows carry gap count and size share from `survivorship_gap`, universe size, static-listing count, dropped-dividend count and late-dividend count, per cost level.
- [ ] Benchmarks: SPY and MTUM equity equals a hand-computed buy-and-hold with the fixture dividends reinvested, one initial cost, same fill convention.
- [ ] `engine.run` without a `TrialHandle` raises before any provider call; `StoreProvider` refuses a handle whose id is not in the registry connection's `trials`; a plain integer is rejected.
- [ ] `StoreProvider` opens one read-only connection per step and closes it before the next (recording factory); a write lock taken between steps does not fail the step that follows it.

Costs and metrics
- [ ] Three-trade fixture: costs match hand-computed values for `per_side_bps`, `commission_per_share` and `commission_per_order` (ADR 0004); zero cost is the identity; a higher level never yields a higher net CAGR on the same reads; the provider is read once for all levels (recording provider).
- [ ] Metrics on a synthetic monthly series match hand-computed values for every key in req 7; `sharpe_annual = sharpe_monthly × √12`; AST check: `backtest/{metrics,costs,fills,valuation,engine}.py` contain no numeric literals other than 0, 1, −1, 2, 4, 12 and 10 000, and γ is `numpy.euler_gamma`.
- [ ] Deflated Sharpe reference values (computed with `numpy.euler_gamma`): SR=0.25, T=120, γ₃=−0.5, γ₄=4, N=20, V=0.01 gives SR*=0.190071, PSR(0)=0.994120, DSR=0.727048; N=100 gives SR*=0.253060, DSR=0.487699; SR=0, N=1 gives 0.5; N=1 reduces to PSR and is labelled `psr`; DSR falls as N, kurtosis or negative skew grow (all to 1e-6).
- [ ] Both DSR bases are stored with their own `sharpe_variance`, `sr_star` and `psr_zero`, the excess basis computed from the `*_excess_spy` skew and kurtosis; the `*_excess_spy` keys are null for `SPY`; the red flag is set when the base-level `excess_cagr_spy` exceeds `metrics.red_flag_excess_cagr_pp`, not otherwise.

Registry and holdout
- [ ] Schema version 2 tables exist after `init_schema` on a fresh store and after a writing command opens a version-1 store; the version row is appended; no fact table changes; `REGISTRY_TABLE_NAMES` is disjoint from `TABLE_NAMES` and the Phase 2 harness tests still pass; a read-only open of a version-1 store raises `RegistryNotInitialised`.
- [ ] `store/registry.py` contains no `UPDATE` or `DELETE` (text check); closing a trial twice raises; ids increase; every `trials` row has a hypothesis; an unregistered slug is refused; a trial without a result lists as `unfinished`.
- [ ] `register_hypothesis(..., family="oracle")` and `open_trial(..., synthetic=True)` are refused when the connection's database file is `settings.store.path`, and accepted on a temp-file store reached through `run_hypothesis(store_path=...)`; the CLI exposes no such option.
- [ ] `hypothesis register` stores the file hash and the frozen set exactly as listed in req 10; a file missing `holdout.start`, `holdout.end`, `in_sample_start` or any `strategy.*`/`costs.*` key fails; file values win over `Settings` for keys the file names; a changed file yields a new hypothesis; a run uses frozen values when live `Settings` differ (tests for `strategy.top_fraction`, `universe.top_n_by_cap`, `adjust.max_prior_close_gap_sessions`, `holdout.start`, `gap.count_share_threshold`, `benchmarks` and `alpaca.historical_feed`); a family outside `hypotheses.families` is refused.
- [ ] Every run, including a failed one (injected provider error), a refused one and one where a row is inserted mid-run (`store changed during run`), leaves a `trials` row and a `trial_results` row with status and message; `ok` rows have metrics, equity, weights and rebalances.
- [ ] Trial count: N counts `ok`, non-synthetic, `in_sample` trials of the family including the current one; V (per basis) is over the latest `ok` trial per (parameter hash, window) pair; a rerun raises N by one and, with an identical result, leaves V unchanged; `family_sharpes` reads `sharpe_monthly` and `sharpe_monthly_excess_spy` only; synthetic, holdout and tracking runs leave N and V unchanged.
- [ ] Window rules: a `--start` before `in_sample_start` and an `--end` after the frozen `holdout.end` each exit 2 with `refused_window` and no provider call.
- [ ] Holdout: a window overlapping the frozen holdout without `--spend-holdout` exits 2 and logs `refused_holdout` with no provider call; with the flag and a reason it runs as `kind=holdout`; a second spend in the family is marked `holdout_repeat`; a second spend by the same hypothesis is refused without `--holdout-repeat`; `HOLDOUT__START` in the environment does not move a registered hypothesis's holdout; the in-sample default window is as in req 11.
- [ ] Gap gate: a holdout run on a fixture whose count share exceeds the frozen threshold at one rebalance date is refused (`refused_gap`) after `survivorship_gap` reads only; with `--override-gap --gap-reason` it runs and writes the reason to the trial and to `owner_decisions`; `decision gap-signoff` appends a row with the gap values.
- [ ] Code version, dirty flag and the store's max `ingested_at` at open are recorded.

Look-ahead
- [x] **Truncation invariance** of the full run: for every rebalance session T_i in the fixture range, `run(end=T_i)` on the full store equals `run(end=T_i)` with the data connection factory yielding `TruncatedStore.at(close(T_i))` (`tests/lookahead/harness.py`) and the registry connection the untruncated fixture store: equity, weights, rebalances.

## Risks & domain checks

- **Look-ahead:** the engine sees the store only through `t`-parameterised provider calls with rebalance closes; truncation and prefix invariance over every rebalance session prove it; the revision case proves the test can fail; one frame per step means a later restatement never reaches an earlier step, and a dividend known too late is counted, not back-filled.
- **Survivorship:** the delisted name exits at its last close, the optimistic convention (the missing tail is where the decline lives, ADR 0003); every result carries the gap per rebalance, stale exits, universe size and static-listing reliance (#35 can otherwise shrink the historical universe to survivors); the holdout cannot be spent above the threshold without a logged owner decision; the Phase 4 gate has its sign-off row.
- **Multiple testing:** every run is a trial by construction (no handle, no provider, no run); N counts reruns, V takes the latest per pair; sensitivities and synthetic runs do not touch N; synthetic and oracle trials are impossible on the real store; a new parameter set is a new hypothesis; families are enumerated so N cannot be reset by renaming; the page recomputes DSR with today's N and V so a stored value cannot flatter an old trial; `backtest-runner` runs only on temp-file or fixture stores, so no agent trial escapes or pollutes the owner's registry; the H1 file discloses holdout-period evidence already seen.
- **Costs:** per-side bps plus commissions on every trade including exits; sensitivity ladder up to the historical effective-spread level; Phase 4 paper fills recalibrate the base (ADR 0006 consequences).
- **Fill realism:** `close` fills do not equal Alpaca's first-trade open or NBBO fractional fills (T3); the Phase 4 `tracking` run measures the gap outside the holdout.
- **Corporate-actions depth (#86):** benchmark total return and a total-return signal depend on the dividends the source supplies; `n_dropped_dividends` and `n_late_dividends` per rebalance show it; `in_sample_start` is the owner's call (open question 8).
- **Store consistency and locks:** DuckDB allows one mode per process, so a run opens the trial (write), reads through a short-lived read-only connection per step, then writes results; a store that changed in between fails the run rather than mixing versions; per-step connections never hold the ingest job's write lock for a whole run.
- **Oracle blind spots:** `bt` shares our stitched frame and weights, so it checks the accounting loop, not the signal or the adjustment; the signal, valuation and cost model have their own hand-computed tests.
- **Performance:** ~115 rebalances × two `adjusted_prices_as_of` reads on a ~22M-row store may take minutes per run; ids are restricted to members and holdings; cost levels share reads; if a run exceeds one hour a follow-up issue adds a session-range filter to `adjusted_prices_as_of`.
- **Phase 2 interface:** `universe_as_of` (T13) and `survivorship_gap` (T15) must accept an injected `Settings` so frozen values reach them; the plan names it on T38; tracked as #102.
- **Owner-only steps:** T29 (vendor ADR) and T45b (real-store run) need the owner's machine and budget decision; agents cannot substitute for either.
- **Secrets, order path, LLM inputs:** none.

## Open questions

1. **H1 portfolio construction** (ADR 0006 defers it here). Options: (a) top 10% of the universe, equal weight (academic decile; ~100 names); (b) top 50 equal weight; (c) cap-weighted top decile (MTUM-like, lower turnover). **ADR 0006's revisit trigger fires with (a):** ~$100 of live capital across ~100 names is about $1 per order, at Alpaca's fractional minimum. The owner chooses: accept (a) for the backtest only and revisit sizing in Phase 4; accept (a) and record the trigger now for the Phase 4 spec; or choose (b) so backtest and live hold the same book. Recommendation: (a) for the backtest with the trigger recorded for Phase 4; no hysteresis band in H1 (a second hypothesis may add one, G1/G4).
2. **Holdout window** (named in the H1 file, never from live `Settings`). Options: (a) `holdout.start=2024-01-01`, `holdout.end` = the last completed month-end before H1's registration (for a registration in October 2026, 2026-09-30); everything after is out of sample for Phase 4 tracking; (b) a fixed 2022–2023 block; (c) the last 24 months at registration. Recommendation: (a). An open-ended holdout would swallow every paper month and collide with the ADR 0005 tracking check.
3. **Cost defaults.** `costs.per_side_bps=15` and the ladder `[0, 30, 60, 100]`. Recommendation: accept as placeholders and recalibrate from Phase 4 paper fills; the ladder already spans the G1 range.
4. **Exit conventions.** (a) Delisting exit at last close only (ADR 0004) or also a haircut sensitivity (Shumway-style −30%) for names delisted for cause; (b) whether the `stale_exit` rule stays: it is a forced exit ADR 0006 does not list and paper trading cannot copy. Recommendation: last close only in Phase 3, haircut as a later issue once a vendor's delisting reasons exist; keep `stale_exit` but report it separately, since a frozen mark on a name with no prices is the alternative.
5. **Trial count scope for DSR.** Options: (a) N over family-wide `ok` in-sample trials including reruns, V over the latest trial per (parameters, window) pair (spec'd); (b) per hypothesis; (c) distinct parameter sets only for both. Recommendation: (a).
6. **Red-flag threshold** `metrics.red_flag_excess_cagr_pp=3.0` is G1's framing. Recommendation: adopt as a reported flag, never a gate, and revisit at the Phase 3 retro.
7. **Headline deflated Sharpe.** Options: (a) DSR of raw monthly returns (Bailey & López de Prado's definition; for a long-only equity strategy it mostly measures market exposure); (b) DSR of monthly excess returns over SPY. Both are stored with their own inputs. Recommendation: (b) as the headline on the page, (a) alongside.
8. **H1 `in_sample_start`.** Alpaca history starts in 2016, so 2017-01-31 is the first feasible rebalance, but pre-2019 tickers rest on `snapshot_static` rows (#35) and corporate-actions depth is unknown (#86). Options: (a) 2017-01-31 with static reliance, dropped and late dividends reported per rebalance; (b) the first month-end after the cover-page tags and actions are both available (~2019). Recommendation: (a) now, revisited when #86 is measured; the per-rebalance columns make the bias visible.
9. **Starting before the price-vendor ADR.** ADR 0003 rule 8 and the roadmap put the ADR (T29, owner) at Phase 3 start. Options: (a) let the pure and registry chains start now and gate the owner's real-store run (T45b) and the phase exit on T29; (b) hold every Phase 3 task until T29 merges. Recommendation: (a); nothing before T45b depends on the source.
10. **Statistical threshold** (handoff §12 item 7). Options: (a) no numeric acceptance threshold in Phase 3: the H1 file states its retirement condition in words (for example "in-sample net excess over SPY below the G1 prior range and DSR(excess) below 0.5 retires H1 as a live candidate") and the ~84-month power arithmetic shows why a pass/fail cut-off would be theatre; (b) a pre-registered DSR(excess) cut-off, proposed 0.95 (Bailey & López de Prado's conventional confidence), recorded in the file and applied as a reported verdict. Recommendation: (a), with the DSR shown but not adjudicated, consistent with ADR 0005 (beating a benchmark is never a phase-exit criterion).
