# Spec: Backtest engine and trial registry (Phase 3)

**Status:** Draft  ·  **Issue:** #51  ·  **Related:** [ADR 0003](../decisions/0003-data-adapters-local-first.md) (rules 5, 6, 8), [ADR 0004](../decisions/0004-tooling-adopt-avoid.md) (engine, oracle, metrics), [ADR 0005](../decisions/0005-objective-benchmark-stop-criteria.md), [ADR 0006](../decisions/0006-universe-and-cadence.md), [roadmap Phase 3](../roadmap.md), [data-foundation spec](data-foundation.md), [handoff](../research/2026-09-24-initial-research-handoff.md) §7 D1 and §12 item 7, [trial registry](../research/trial-registry.md), research [G1](../research/2026-09-25-g1-momentum-post-2010.md) (PR #61, unmerged at drafting), [G3](../research/2026-09-25-trend-timing.md), [G4](../research/2026-09-25-g4-signal-combination.md), [G8](../research/2026-09-25-price-vendors.md), [free-data terms](../research/2026-09-25-free-data-terms.md)

## Problem & why now

Phase 2 answers "what was knowable at T?". Phase 3 asks the next question honestly: *how would a rule have done, using only what was knowable at each step, net of costs, with every attempt counted?* This spec builds the backtest engine, the cost model, the locked holdout, the trial registry in the store, deflated Sharpe reporting, the `bt` oracle check, the `backtest` CLI and the two dashboard pages. It is where charter principles 2, 4 and 6 (count every trial, point-in-time data, tune on process not P&L) become code with tests.

The first registered hypothesis is the MVP strategy from the roadmap: long-only, monthly-rebalanced 12-1 momentum on the ADR 0006 universe, against SPY and MTUM buy-and-hold. The evidence (G1) puts its net excess return near zero, so the point of Phase 3 is a correct, auditable engine, not a good number.

## Users & usage

- **The owner** registers a hypothesis by merging its file and running `tradepartner hypothesis register`, runs `tradepartner backtest <hypothesis>` from time to time, and reads the backtest page and the trial-registry view. Only the owner spends the holdout, overrides the gap gate or signs off on the gap.
- **The `backtest-runner` agent** (candidate in [agents.md](../ways-of-working/agents.md)) runs a registered hypothesis and reports. It never passes a holdout or override flag.
- **Phase 4** reads trial results to compare paper returns with the backtest (ADR 0005, `paper.tracking_k`) and needs the owner's gap sign-off row (ADR 0003 rule 8).
- **Tests**, on every PR, run the engine on the fixture universe with the network disabled, including the truncation-invariance suite and the `bt` oracle.

## Definitions

- **Rebalance session** T_i: the last XNYS session of a calendar month (ADR 0006), from `calendar.last_session_of_month`. **T** as an instant is close(T_i) (`calendar.session_close`), tz-aware UTC, as in the Phase 2 spec.
- **Fill session** F_i = `calendar.next_session(T_i)`. The fill price is F_i's open or close per `execution.fill_price` (ADR 0006; `close` since T3).
- **Step** i: the work done at read time close(T_{i+1}) for the holding month (F_i, T_{i+1}]: value the month, then compute the next signal and targets. Every provider read of a run uses a rebalance close as `t`.
- **Data cutoff** of a run: close of its last rebalance session. Nothing is read with a later `t`.
- **Month i return**: equity at close(T_{i+1}) over equity at close(T_i), minus one. Monthly returns are the unit for Sharpe, skew, kurtosis and the ADR 0005 paper-tracking check.
- **Hypothesis**: a file under `docs/hypotheses/` with an economic rationale, a fixed parameter set, expected magnitudes and a retirement condition, registered in the store before any run (domain rule 1). Each belongs to a **family** from the enumerated `hypotheses.families` list, the unit for counting trials and holdout spends.
- **Trial**: one engine run, from the moment the registry issues a trial handle. Failures, refusals, crashes and reruns are trials. **Kind** ∈ `in_sample`, `holdout`, `tracking` (Phase 4's paper-period comparison; reserved here, never counted as holdout). A **synthetic** trial runs on a fixture or in-memory store (tests, the oracle) and is excluded from the trial count (ADR 0004); the CLI cannot create one.
- **In-sample window**: from the hypothesis's `in_sample_start` to the last rebalance session before its frozen `holdout.start`. **Holdout window**: the hypothesis's frozen `[holdout.start, holdout.end]`, both fixed dates.
- **Series**: `strategy`, `SPY`, `MTUM` (from `benchmarks`). Benchmarks are buy-and-hold, total return, under the same fill convention and cost model (ADR 0005), so their only trade cost is the initial buy.

## Requirements

1. **Engine over the as-of API only.** The engine reads market data through a `DataProvider` protocol whose every method takes a tz-aware `t`. The store-backed provider calls only `store.asof`, `store.master`, `store.delistings`, `universe.universe_as_of` and `gap.survivorship_gap`, passing the trial's frozen `Settings` into every call, never an adapter. At step i, with `t = close(T_{i+1})`, it reads: the **marking frame** `adjusted_prices_as_of(t, held ∪ benchmark ids, include_dividends=True)` for the sessions F_i..T_{i+1}; the universe `universe_as_of(t)`; the **signal frame** `adjusted_prices_as_of(t, universe ids, include_dividends=strategy.signal_total_return)`; listing ends; dropped dividends; the survivorship gap. The provider is read once per step and every cost level is evaluated from the same reads. A rebalance date is a calendar output, never a weekday rule.
2. **Position valuation, one frame per step.** Positions are carried as dollar values, not share counts. Within step i every price ratio comes from the marking frame alone: a position bought at F_i is worth value × P(s)/P(F_i) at session s, and P is the adjusted-as-of-`t` price. So a split inside the month cancels and a dividend inside the month is reinvested in the paying name on its ex-date, whichever `strategy.signal_total_return` says; an action that becomes known only after its ex-date enters the first step whose read time knows it. Reported `shares` are value over the raw fill price, for the page and the weights table only. The drifted value at close(T_{i+1}) carries into step i+1, where the marking frame as of close(T_{i+2}) prices it forward to F_{i+1}.
3. **Signal and portfolio (pure functions).** 12-1 momentum: the adjusted close at the last session of month T−`strategy.skip_months` over the adjusted close at the last session of month T−`strategy.formation_months`, minus one; a name lacking either bar is excluded and counted. Target weights: the top `strategy.top_fraction` of ranked names, `strategy.weighting` (`equal`), long-only, ≥ 0, sum ≤ 1, remainder cash; ties by `security_id` ascending. Cadence and hold are ADR 0006, not config.
4. **Fills, costs, cash.** Trades are target minus drifted weights, fractional, at the fill price. Buys are sized so that cash after costs is never negative (a buy's notional is scaled by 1/(1 + per-side rate)). A target name with no bar on F_i is not bought; its weight stays in cash and is counted as `missing_fill`. A held name with no bar on a session keeps its last mark. Cash earns `backtest.cash_rate` (0). Equity = cash + Σ position values on every session; cash changes only by fills, costs and `cash_rate` (dividends are reinvested in-name by req 2).
5. **Delistings and stale names.** A held name whose listing has ended by the step's read time (Phase 2 req 4, derived from rows known at `t`) is sold at its last close on its final session into cash and counted as `delisting_exit` (`backtest.delisting_exit=last_close`, the ADR 0004 oracle convention). A held name still listed at `t` but with no bar in the last `backtest.stale_exit_sessions` sessions before T_{i+1} is exited at its last close and counted as `stale_exit` (open question 4). Both counts, the survivorship gap at every rebalance (ADR 0003 rule 5, count and size share), the universe size and the number of members whose listing rests on `snapshot_static` rows (#35) are part of every result.
6. **Cost model (pure).** Cost of a trade = notional × `costs.per_side_bps` / 10⁴ + shares × `costs.commission_per_share` + `costs.commission_per_order`, charged from cash at the fill. Every run is evaluated at the base level and at each level in `costs.sensitivity_per_side_bps` (commissions unchanged) from the same reads; strategy metrics are reported per level, stored inside the trial, never as new trials. N, V, DSR and the red flag use the **base** level.
7. **Metrics (pure).** Per series and cost level: CAGR; annualized volatility and Sharpe from monthly returns (`metrics.periods_per_year`, `metrics.risk_free_rate`); maximum drawdown on the daily equity curve; average one-sided monthly turnover; cost drag (gross minus net CAGR); excess CAGR and tracking error versus SPY and versus MTUM; skew and kurtosis of monthly returns; number of months. Standard metrics come from the library ADR 0004 names (chosen in the plan); PSR and DSR are ours.
8. **Deflated Sharpe (Bailey & López de Prado).** SR* = √V · ((1−γ)Φ⁻¹(1−1/N) + γΦ⁻¹(1−1/(N·e))), γ = 0.5772156649015329; DSR = Φ((SR − SR*)√(T−1) / √(1 − γ₃·SR + (γ₄−1)/4 · SR²)), with SR the **monthly, non-annualized** Sharpe of this trial, T its month count, γ₃ skew, γ₄ kurtosis (non-excess). Computed twice: on raw monthly returns and on monthly excess returns over SPY (open question 7 picks the headline). **N** = the number of `ok`, non-synthetic, `in_sample` trials in the same family at run time, this one included, reruns included; **V** = the sample variance of the base-level monthly Sharpe over the **distinct** (parameter hash, window) pairs among them, so a rerun raises N and leaves V unchanged. With fewer than two distinct pairs, SR* = 0 and the result is labelled `dsr_basis=psr`. PSR(0), N, V and SR* are stored with the trial.
9. **Trial registry in the store.** Tables `hypotheses`, `trials`, `trial_results`, `trial_metrics`, `trial_rebalances`, `trial_equity`, `trial_weights`, `owner_decisions` (schema below), created by `store.schema` at schema version 2 with an additive migration from version 1, listed in `REGISTRY_TABLE_NAMES` separate from the fact tables in `TABLE_NAMES` so the look-ahead harness is untouched. Any writing command (`hypothesis register`, `backtest`, `decision`, `ingest`) migrates a version-1 store; the read-only pages show a "registry not initialised" state instead. **Append-only**: `store.registry` exposes inserts and reads only; a trial's outcome is a separate `trial_results` row, never an update; a trial with no result row is shown as `unfinished`. **Trial handle**: `registry.open_trial` is the only constructor of `TrialHandle`; `StoreProvider` refuses to build without one whose id exists in its store's `trials`, and the engine refuses to run without one (ADR 0005: no id, no run). Every trial records hypothesis, kind, window, data cutoff, the store's latest `ingested_at` at open, code version (git commit, dirty flag), the frozen parameter hash, the synthetic flag, reasons, `run_by` and a note. A run fails (`store changed during run`) if the store's latest `ingested_at` differs between trial open and result write. [docs/research/trial-registry.md](../research/trial-registry.md) becomes a pointer to the tables and the `trials` command.
10. **Pre-registration freezes parameters.** The hypothesis file is the source of truth for the keys it names; the live `Settings` fill the rest at registration. `tradepartner hypothesis register <file>` stores the file's SHA-256 and the frozen values of `strategy.*`, `universe.*`, `execution.fill_price`, `costs.*`, `backtest.*`, `adjust.*`, `master.transfer_window_sessions`, `gap.*` and `holdout.*`, prints the full set and its hash. A run uses the frozen values, never the live ones, including the holdout window and the gap threshold, so no environment variable can move a hypothesis's holdout. A changed file or a different frozen set is a new hypothesis, never a variant. The H1 file names every `strategy.*` and `costs.*` key explicitly.
11. **Locked holdout.** The trial handle is issued first. A run whose window touches the frozen holdout is then refused before any provider call unless `--spend-holdout --holdout-reason` is given; the refusal is logged (`status=refused_holdout`). A holdout run has `kind=holdout` and its reason; when any hypothesis in the family already spent the holdout, the run is marked `holdout_repeat` and the page says so (domain rule 3). **Gap gate** (ADR 0003 rule 6): with the flag, the only reads before the gate are `survivorship_gap(t)` at the window's rebalance closes; the run is refused (`refused_gap`) when the count share at any of them exceeds the frozen `gap.count_share_threshold`, unless `--override-gap --gap-reason` records the owner's decision in the trial and in `owner_decisions`. The in-sample default end is the last rebalance session before the frozen `holdout.start`, so an ordinary run cannot drift into it.
12. **Owner decisions.** `tradepartner decision <kind> --reason` appends an `owner_decisions` row (`gap_signoff` for ADR 0003 rule 8, the Phase 4 entry gate; `gap_override` and `holdout_spend` are also written by the flags in req 11) with the trial it refers to and the gap values at that time.
13. **No look-ahead.** A run ending at T is a function only of rows with `known_at ≤ close(T)`: truncation invariance holds for the whole run, and a run to T_i equals the prefix of a longer run through T_i.
14. **`bt` oracle** (ADR 0004). On the fixture universe, with zero costs, fractional shares and the same lagged target weights, `bt` and our engine agree on portfolio equity at every compared session to within the tolerance pinned in the test file. `bt` receives the **stitched frame**: per name, each session's return taken from the marking frame of the step that contains it, cumulated into one price index, so both engines see identical ratios and the fixture's late-known revisions cannot separate them. With `fill_price=close` every session is compared; with `open`, `bt` receives the stitched open series and only fill sessions are compared (a deviation from ADR 0004's wording, recorded in its amendment). The delisted fixture name is sold at its last close on its final session in both, asserted explicitly. The oracle registers its own synthetic hypothesis (`family=oracle`) rather than overriding a registered one.
15. **Red flag.** A trial whose base-level net excess CAGR over SPY exceeds `metrics.red_flag_excess_cagr_pp` is marked `red_flag=true` and the page says so: G1 found no live or gross window above +1.1 pp/yr. A prompt for a look-ahead and cost audit, not a gate.
16. **CLI.** `tradepartner backtest <hypothesis> [--start] [--end] [--spend-holdout --holdout-reason] [--override-gap --gap-reason] [--note]` (exit 0 ok, 1 failed, 2 refused; prints trial id, metrics table, gap maxima, flags); `tradepartner hypothesis register <file>`; `tradepartner trials [--hypothesis] [--include-synthetic]`; `tradepartner decision gap-signoff --trial <id> --reason`. No `--synthetic` flag exists. No secrets in output.
17. **Pages.** Streamlit, read-only, inside the Phase 2 shell's single read-only connection: a **backtest page** (trial picker; equity of the three series on a log axis; drawdowns; monthly turnover and cost bars; metrics per cost level; both DSRs with N, V and SR*; gap, universe size and static reliance per rebalance; kind, synthetic, repeat, red and refused states; family-wide holdout spends) and a **trial-registry view** (every trial newest first; hypothesis filter; synthetic hidden by default; failed, refused and unfinished rows visible with their message; owner decisions). Both show "registry not initialised" on a version-1 store. No run button: runs are CLI only.
18. **First hypothesis end to end.** `docs/hypotheses/h1-momentum-12-1.md` is registered and run over the in-sample window on the owner's real store, under whatever `PriceSource` the price-vendor ADR names. "End to end" means: hypothesis registered, trial issued, run completed, metrics, both DSRs and the gap stored, `quant-auditor` passed on the run, page shows the trial, universe size per rebalance in the evidence. It does **not** mean the holdout was spent: on a source above the gap threshold the holdout stays locked, and a result on free data is optimistic and claims no edge (ADR 0003).

## Acceptance criteria (testable)

Engine and timing
- [ ] Every provider call of a run carries `t = close(T_{i+1})` for some rebalance session (recording provider); the fill session is `calendar.next_session(T_i)` across a month-end before a holiday and on a half day (fixture cases).
- [ ] With `execution.fill_price=close` the fill equals F_i's close; with `open`, F_i's open; the two runs have identical targets and weights and different fill prices.
- [ ] Valuation: a synthetic store with a 2:1 split and a dividend both ex inside a holding month values the held name with no jump on the split date and with the dividend reinvested (equity equals the hand-computed total return); a dividend known only after its ex-date changes the step that first knows it and none before.
- [ ] Momentum on a synthetic frame: the skip month is excluded; a name missing the formation-start bar is excluded and counted; ties rank by `security_id` ascending; weights are ≥ 0, sum ≤ 1 and equal within the selected set; no session after `t` is read.
- [ ] Cash identity on every session; cash is never negative at any cost level, including at `costs.sensitivity_per_side_bps` maximum.
- [ ] A target name with no bar on F_i is not bought and appears in `missing_fill`; a held name with no bar keeps its last mark.
- [ ] `SEC_WINDOW_DELIST` held at its delisting exits at its last close on its final session into cash, counted as `delisting_exit`; `SEC_TRANSFER` held across October 2018 exits at the 2018-10-31 close (delisted at that read time) and is eligible again once the new listing is known; a name with a trailing gap beyond `backtest.stale_exit_sessions` while still listed exits as `stale_exit`, and one whose gap closes before T_{i+1} does not.
- [ ] Rebalance rows carry gap count and size share from `survivorship_gap`, universe size, static-listing count and dropped-dividend count.
- [ ] Benchmarks: SPY and MTUM equity equals a hand-computed buy-and-hold with the fixture dividends reinvested, one initial cost, same fill convention.
- [ ] `engine.run` without a `TrialHandle` raises before any provider call; `StoreProvider` refuses a handle whose id is not in its store's `trials`; a plain integer is rejected.

Costs and metrics
- [ ] Three-trade fixture: costs match hand-computed values for `per_side_bps`, `commission_per_share` and `commission_per_order` (ADR 0004); zero cost is the identity; a higher level never yields a higher net CAGR on the same reads; the provider is read once for all levels (recording provider).
- [ ] Metrics on a synthetic monthly series match hand-computed CAGR, volatility, Sharpe, maximum drawdown, turnover and tracking error; AST check: `backtest/{metrics,costs,engine}.py` contain no numeric literals other than 0, 1, −1, 4, 10 000 and γ = 0.5772156649015329.
- [ ] Deflated Sharpe reference values (computed with γ above): SR=0.25, T=120, γ₃=−0.5, γ₄=4, N=20, V=0.01 gives SR*=0.190071, PSR(0)=0.994120, DSR=0.727048; N=100 gives SR*=0.253060, DSR=0.487699; SR=0, N=1 gives 0.5; N=1 reduces to PSR and is labelled `psr`; DSR falls as N, kurtosis or negative skew grow (all to 1e-6).
- [ ] Both DSRs are stored; the red flag is set when the base-level excess CAGR over SPY exceeds `metrics.red_flag_excess_cagr_pp`, not otherwise.

Registry and holdout
- [ ] Schema version 2 tables exist after `init_schema` on a fresh store and after a writing command opens a version-1 store; the version row is appended; no fact table changes; `REGISTRY_TABLE_NAMES` is disjoint from `TABLE_NAMES` and the Phase 2 harness tests still pass.
- [ ] `store/registry.py` contains no `UPDATE` or `DELETE` (text check); closing a trial twice raises; ids increase; every `trials` row has a hypothesis; an unregistered slug is refused; a trial without a result lists as `unfinished`.
- [ ] `hypothesis register` stores the file hash and the frozen set exactly as listed in req 10; file values win over `Settings` for keys the file names; a changed file yields a new hypothesis; a run uses frozen values when live `Settings` differ (tests for `strategy.top_fraction`, `universe.top_n_by_cap`, `adjust.max_prior_close_gap_sessions`, `holdout.start` and `gap.count_share_threshold`); a family outside `hypotheses.families` is refused.
- [ ] Every run, including a failed one (injected provider error), a refused one and one where a row is inserted mid-run (`store changed during run`), leaves a `trials` row and a `trial_results` row with status and message; `ok` rows have metrics, equity, weights and rebalances.
- [ ] Trial count: N counts `ok`, non-synthetic, `in_sample` trials of the family including the current one; V is over distinct (parameter hash, window) pairs; a rerun raises N by one and leaves V unchanged; synthetic, holdout and tracking runs leave both unchanged.
- [ ] Holdout: a window overlapping the frozen holdout without `--spend-holdout` exits 2 and logs `refused_holdout` with no provider call; with the flag and a reason it runs as `kind=holdout`; a second spend in the family is marked `holdout_repeat`; `HOLDOUT__START` in the environment does not move a registered hypothesis's holdout; the in-sample default end is the last rebalance session before it.
- [ ] Gap gate: a holdout run on a fixture whose count share exceeds the frozen threshold at one rebalance date is refused (`refused_gap`) after `survivorship_gap` reads only; with `--override-gap --gap-reason` it runs and writes the reason to the trial and to `owner_decisions`; `decision gap-signoff` appends a row with the gap values.
- [ ] Code version, dirty flag and the store's max `ingested_at` at open are recorded.

Look-ahead
- [ ] **Truncation invariance** of the full run: for every rebalance session T_i in the fixture range, `run(end=T_i)` on the full store equals `run(end=T_i)` on `TruncatedStore.at(close(T_i))` (`tests/lookahead/harness.py`): equity, weights, rebalances.
- [ ] **Prefix invariance**: `run(end=T_i)` equals the prefix through T_i of `run(end=T_n)`.
- [ ] A synthetic store with a bar revision and a dividend revision known after T_i leaves `run(end=T_i)` unchanged and changes `run(end=T_{i+1})` (the harness has teeth).
- [ ] AST check: nothing under `src/tradepartner/backtest/` imports `tradepartner.adapters`; nothing under `src/` imports `bt`, `ffn` or `yfinance`.

Oracle
- [ ] On the fixture universe under the oracle's own synthetic hypothesis, zero costs and fractional shares, the maximum absolute relative equity difference between `bt` and our engine over the compared sessions is ≤ the tolerance constant in the test file (1e-9 per ADR 0004); the delisted name's exit at its last close is asserted in both engines; the trial is logged with `synthetic=true`; a deliberate one-session mismatch fails the assertion.
- [ ] `bt` receives only the stitched frame built from the engine's own marking frames and the lagged weights, never raw prices or actions.

CLI and pages
- [ ] `backtest` prints the trial id and metrics and exits 0/1/2 as specified; `--spend-holdout` without `--holdout-reason` is refused; `hypothesis register`, `trials` and `decision` behave as above; output contains no secret-shaped string (scrub patterns from `cli_record`).
- [ ] Headless render of the backtest page shows the three equity series, drawdowns, turnover and costs, metrics per cost level, both DSRs with N, V and SR*, gap, universe size and static reliance per rebalance, the kind and flag states and family holdout spends, reading only through the shell's connection; the trial-registry view lists trials newest first, hides synthetic by default, shows refused, failed and unfinished rows and owner decisions; both show the not-initialised state on a version-1 store.

Real-store evidence (close-out PR, not unit tests)
- [ ] H1 registered and run over the in-sample window on the owner's store; trial row, metrics, both DSRs, gap and universe size per rebalance and page screenshot are in the PR; `quant-auditor` passed; the holdout is untouched (`trials` shows no `kind=holdout` row) unless the gap gate passed and the owner spent it.

## Out of scope

The price-vendor ADR and any vendor adapter (separate issue after G8; the close-out runs on whatever source that ADR names). Paper trading, the risk-gated broker wrapper, order placement and the `tracking` run itself (Phase 4; #33). The LLM layer and its ADR (#52). Any parameter search, grid or multi-signal variant beyond the registered hypothesis (G4; a second hypothesis is a new file and registration). A trend overlay (G3: at best marginal). Probability of backtest overfitting (CSCV) and a hysteresis buy/hold band (G1, G4): candidate later hypotheses. Shorting, leverage, intraday data, borrow costs. Tax modelling (G7, #50). Automated Parquet export at tags (deferred by the Phase 2 spec; separate size:S issue). Registry integrity rules in `health --check` (follow-up issue). Fixing #35 and #83 (Phase 2 data questions; the engine inherits what the as-of API returns and reports static reliance).

## Data / interfaces

**Tables** (registry; no `known_at`, like `ingestion_runs`; all append-only; in `REGISTRY_TABLE_NAMES`):
- `hypotheses(hypothesis_id, slug, family, title, doc_path, doc_sha256, params_json, params_sha256, in_sample_start, registered_at, registered_by)`
- `trials(trial_id, hypothesis_id, kind, started_at, start_session, end_session, data_cutoff, store_max_ingested_at, code_version, code_dirty, synthetic, holdout_repeat, holdout_reason, gap_override_reason, run_by, note)`
- `trial_results(trial_id, finished_at, status ∈ {ok, failed, refused_holdout, refused_gap}, message, n_trials, sharpe_variance, sr_star, dsr, dsr_excess_spy, dsr_basis, psr_zero, red_flag, gap_max_count_share, gap_max_size_share)`
- `trial_metrics(trial_id, series, cost_per_side_bps, metric, value)`
- `trial_rebalances(trial_id, session, fill_session, n_universe, n_static_listings, n_targets, turnover, cost_paid, gap_count_share, gap_size_share, n_missing_fill, n_delisting_exits, n_stale_exits, n_excluded_no_history, n_dropped_dividends)`
- `trial_equity(trial_id, series, cost_per_side_bps, session, equity, cash)`
- `trial_weights(trial_id, fill_session, security_id, target_weight, fill_price, shares)`
- `owner_decisions(decision_id, made_at, kind ∈ {gap_signoff, gap_override, holdout_spend}, hypothesis_id, trial_id, values_json, reason)`

**Hypothesis file** (`docs/hypotheses/<slug>.md`, template in `docs/templates/hypothesis.md`): slug, family, title, economic rationale with citations, `in_sample_start` (open question 8), the parameter block (every `strategy.*` and `costs.*` key; any other frozen key it wants to pin), expected magnitudes and red flags (for H1 from G1's primary sources: net excess prior ≈ 0 pp/yr, range −1 to +1; single-year gaps of ±13–18 pp; worst quarter ≈ −18 to −19%; tracking error ≈ 8.4%), and what result would retire the hypothesis.

## Risks & domain checks

- **Look-ahead:** the engine sees the store only through `t`-parameterised provider calls with rebalance closes; truncation and prefix invariance over every rebalance session prove it; the revision case proves the test can fail; one frame per step means a later restatement never reaches an earlier step.
- **Survivorship:** the delisted name exits at its last close, the optimistic convention (the missing tail is where the decline lives, ADR 0003); every result carries the gap per rebalance, stale exits, universe size and static-listing reliance (#35 can otherwise shrink the historical universe to survivors); the holdout cannot be spent above the threshold without a logged owner decision; the Phase 4 gate has its sign-off row.
- **Multiple testing:** every run is a trial by construction (no handle, no provider, no run); N counts reruns, V does not double-count them; sensitivities and synthetic runs do not touch N; a new parameter set is a new hypothesis; families are enumerated so N cannot be reset by renaming; DSR is reported with its inputs.
- **Costs:** per-side bps plus commissions; sensitivity ladder up to the historical effective-spread level; Phase 4 paper fills recalibrate the base (ADR 0006 consequences).
- **Fill realism:** `close` fills do not equal Alpaca's first-trade open or NBBO fractional fills (T3); the Phase 4 `tracking` run measures the gap outside the holdout.
- **Corporate-actions depth (#86):** benchmark total return and a total-return signal depend on the dividends the source supplies; `n_dropped_dividends` per rebalance shows it; `in_sample_start` is the owner's call (open question 8).
- **Store consistency:** DuckDB allows one mode per process, so a run opens the trial (write), reads through a read-only connection, then writes results; a store that changed in between fails the run rather than mixing versions.
- **Oracle blind spots:** `bt` shares our stitched frame and weights, so it checks the accounting loop, not the signal or the adjustment; the signal, valuation and cost model have their own hand-computed tests.
- **Performance:** ~115 rebalances × two `adjusted_prices_as_of` reads on a ~22M-row store may take minutes per run; ids are restricted to members and holdings; cost levels share reads; if a run exceeds one hour a follow-up issue adds a session-range filter to `adjusted_prices_as_of`.
- **Phase 2 interface:** `universe_as_of` (T13) and `survivorship_gap` (T15) must accept an injected `Settings` so frozen values reach them; the plan names it on T38.
- **Secrets, order path, LLM inputs:** none.

## Open questions

1. **H1 portfolio construction** (ADR 0006 defers it here). Options: (a) top 10% of the universe, equal weight (academic decile; ~100 names); (b) top 50 equal weight; (c) cap-weighted top decile (MTUM-like, lower turnover). Recommendation: (a), pre-registered in H1, with no hysteresis band in H1 (a second hypothesis may add one, G1/G4). Note for Phase 4: 100 names on ~$100 live sits at Alpaca's fractional minimum; that is a sizing question there, not a reason to change the backtest.
2. **Holdout window.** Options: (a) `holdout.start=2024-01-01`, `holdout.end` = the last completed month-end before H1's registration (frozen at registration; everything after is out of sample for Phase 4 tracking); (b) a fixed 2022–2023 block; (c) the last 24 months at registration. Recommendation: (a). An open-ended holdout would swallow every paper month and collide with the ADR 0005 tracking check.
3. **Cost defaults.** `costs.per_side_bps=15` and the ladder `[0, 30, 60, 100]`. Recommendation: accept as placeholders and recalibrate from Phase 4 paper fills; the ladder already spans the G1 range.
4. **Exit conventions.** (a) Delisting exit at last close only (ADR 0004) or also a haircut sensitivity (Shumway-style −30%) for names delisted for cause; (b) whether the `stale_exit` rule stays: it is a forced exit ADR 0006 does not list and paper trading cannot copy. Recommendation: last close only in Phase 3, haircut as a later issue once a vendor's delisting reasons exist; keep `stale_exit` but report it separately, since a frozen mark on a name with no prices is the alternative.
5. **Trial count scope for DSR.** Options: (a) N over family-wide `ok` in-sample trials including reruns, V over distinct (parameters, window) pairs (spec'd); (b) per hypothesis; (c) distinct parameter sets only for both. Recommendation: (a).
6. **Red-flag threshold** `metrics.red_flag_excess_cagr_pp=3.0` is G1's framing. Recommendation: adopt as a reported flag, never a gate, and revisit at the Phase 3 retro.
7. **Headline deflated Sharpe.** Options: (a) DSR of raw monthly returns (Bailey & López de Prado's definition; for a long-only equity strategy it mostly measures market exposure); (b) DSR of monthly excess returns over SPY. Both are stored. Recommendation: (b) as the headline on the page, (a) alongside.
8. **H1 `in_sample_start`.** Alpaca history starts in 2016, so 2017-01-31 is the first feasible rebalance, but pre-2019 tickers rest on `snapshot_static` rows (#35) and corporate-actions depth is unknown (#86). Options: (a) 2017-01-31 with static reliance and dropped dividends reported per rebalance; (b) the first month-end after the cover-page tags and actions are both available (~2019). Recommendation: (a) now, revisited when #86 is measured; the per-rebalance columns make the bias visible.
9. **Starting before the price-vendor ADR.** ADR 0003 rule 8 and the roadmap put the ADR at Phase 3 start. Options: (a) let the pure and registry chains start now and gate the close-out (T45) and the phase exit on the ADR; (b) hold every Phase 3 task until it merges. Recommendation: (a); nothing before T45 depends on the source.
