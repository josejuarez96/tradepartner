## Problem & why now

ADR 0013 (Accepted 2026-10-05) lets a pretrained **classification** model label a code-selected passage of a public filing with one option from a set we fix, so that a job can compare the label with what our rules concluded and hand the owner a shortlist of disagreements. The label lives only in the research store; the owner reads the filing and decides; a fix enters the system only as a reviewed code or config change. The ADR names this spec at `docs/specs/research-labeling.md`, makes its existence with status Accepted the key that its tests turn on (point 3 (a)), and says nothing in points 1 to 9 is built before it (point 9, Process).

The owner chose the first pilot: **task A, the security-master departure reason** (owner decision 3). The pain is current. The security master's rules are patched one filing at a time, each fix starting with a person reading a Form 25 or an 8-K: #921 (Valaris: a footnote alias kept a Form-25-delisted span alive; a repair would have deleted 1,298 post-bankruptcy bars), #943 (a repair dry run would delete live Seagate, 1,714 bars, and MiMedx, 1,484 bars, because the rules read their redomicile and relisting filings wrong), #905 (Sotheby's cover page after a stopped line), #828 and #922 (Match Group's 2020 separation, an owner-accepted successor the rules no longer derive). A model that reads the filings and says "redomicile", "bankruptcy" or "compliance delisting" fixes none of these; it turns the pile of every listing end into a shortlist of the ones where the filing and the rule disagree.

Two things make this the right first pilot and shape the spec. The population is small (every Form 25 since 2016, a few thousand filings; the corpus fetch prints the exact count), so the whole population is labelled and the pilot's cost is cents, not dollars. And **nothing in the system holds the filing text**: ingest parses the Form 25 notification and deletes the document (`edgar_source._fetch_delisting`), stores no accession on the `delistings` row, and reads no 8-K body; the master reads the Form 15, 8-A12B and 8-K12B markers from the filing index at build time and stores none of them; the event-data collector fetches no 8-K primary document in v1. The pilot therefore starts with a corpus build, not a model call (ADR 0013 Context, "What is already fixed", last bullet; owner question 3 there).

**Why now.** The vendor credit the owner holds ($20, owner decision 2) is the pilot's whole budget, and promotional credits are "subject to any additional terms ... including terms with respect to expiration" (vendor MCA, req 17); the owner's store has been through three repair rounds this week, each a hand-read of filings; and ADR 0013 point 3 says the ADR 0008 point 2 tests, still unwritten, land with this plan's first task, so the boundary becomes a test before any client exists.

## Users & usage

- **The owner** runs everything that touches the real corpus, the real vendor or his store: the corpus fetch (EDGAR, paced), the frame build (one read of his store), the gold labelling session (150 filings, blind, before any model output exists, through the one-keystroke labelling aid of req 9), the fixture recording (his key), the pilot run, every later batch, and the review of each shortlist. He sees: the labelling aid for gold labels; a review screen per shortlist item (the passage, two answers in the same form with no attribution and no probability, the filings' EDGAR URLs); the registry rows on the dashboard's research view (counts, metrics, cost; never a label or a passage). He spends an estimated 3.75 to 5 hours on the gold sample, inside the budget of about 3 to 5 hours he set (owner decision 3, 2026-10-05; ADR 0013 point 5's 10 to 20 hours was for a 300-item sample) and then minutes per shortlist item.
- **Agents** build and test against fixture stores, hand-built packets, a scripted stub and the owner's recordings. They never hold the key, never call the vendor, never run on the owner's store; every run they open is `synthetic` (research-registry Definitions). A fix the shortlist motivates is an ordinary PR a team builds under its own issue, with a pinned test, citing the review file's hash and the filing's accession (ADR 0013 point 4).
- **The research registry** records every run (`benchmark` for the pilot scoring, the fixture recording and every batch with its review; `robustness` for the drift and perturbation probes), every dataset version (frame, gold sample, drift set, inference records, review file) and every holdout spend (the sealed `pilot` period, once).
- **Nothing else.** The running system (ingest, paper, dashboard, alerts) makes no model call and reads no label. `tradepartner.execution` and the dashboard never import `tradepartner.research` (ADR 0013 point 3 (b)).

## Definitions

- **Listing end**: one Form 25 or 25-NSE filing in EDGAR's quarterly `form.idx` accepted on or after 2016-01-01, attributed to the issuer CIK named in its XML (the exchange's copy of a 25-NSE, which the index lists under the exchange's CIK with the same accession, is the same listing end), with its amendments (`25/A`, `25-NSE/A`) attached to it (req 2). The population of task A is every listing end whose primary document is the XML `notificationOfRemoval`; pre-XML and unstamped filings are counted and excluded.
- **Rule answer**: what the master and resolver concluded for the listing end, computed by code at a fixed as-of time `t` and `code_version` during the **frame build** (req 2), never during a run: the derived status `listed` / `delisted` / `transferred` from `store.delistings.listing_ends_as_of`; `unmatched` when no `delistings` row joins the filing by (issuer CIK, exchange, acceptance), the rule's own failure to place it; whether the same `security_id` has a `listings` row with `valid_from` after the Form 25's effective day and before the security's next listing end (the #820 relisting rule); whether a successor security (`<cik>@<date>`, `config.parse_successor_id`) exists whose `<date>` falls after the Form 25's filing session and before the CIK's next listing end (the #820 new-equity rule); and whether a Form 15 (`15-12B`, `15-12G`) was accepted within `master.reorganisation_window_sessions` XNYS sessions of the Form 25's filing session, on either side (the #820 veto). The Form 15, 8-A12B and 8-K12B filings come from the fetch's manifest, because the store holds none of them.
- **Passage** (the **packet**'s text): what code selects for one listing end (req 3): the Form 25 notification rendered as labelled fields, and the body items and first press-release exhibit of the issuer's 8-K, 8-K/A and 8-K12B filings accepted in a fixed calendar-day window around the Form 25's filing date, truncated by a fixed rule to `research.labeling.max_packet_tokens`.
- **Option set**: the closed set of answers the model may give (req 4), always including `unresolved`, versioned as an object with a hash (prospective spec §3, `prompt_version`).
- **Class**: one of five groups that partition the eight non-`unresolved` options (req 5): `transfer`, `continuity`, `insolvency`, `terminal`, `removal`. Scoring compares classes; the review screen shows classes.
- **Crosswalk**: the registered map from each rule answer onto the subset of options it is consistent with (req 5). A **disagreement** is a model label outside that subset; `unresolved` is neither agreement nor disagreement and is always on the shortlist.
- **Shortlist**: for one batch, every disagreement, every `unresolved`, and a seeded random sample of the agreements (ADR 0013 point 4), capped per batch (req 9).
- **Gold label**: the owner's label for a sampled listing end, made from the filing text alone, before any model output exists for the task, with the passage he relied on (protocol §6, §7).
- **Frame**: the tabular dataset of the whole population: one row per listing end with the identifiers, the documents' normalised texts, the marker filings and the rule answer at `t` (req 2). Every run binds one tabular dataset derived from it (the gold sample, the frame itself, a prospective frame, the drift set), so `research.load_dataset` is the one reader of everything a run uses (research-registry req 3).
- **Inference record**: one append-only record per (listing end, configuration, attempt) in the research store (req 7). **Review record**: one append-only record per shortlist item the owner decided (req 9), in the review file (owner decision 4 (a)).
- **Research store**: `research.data_dir` (default `data/research/`, gitignored by `data/*`), the content-addressed directory #810 chose. Nothing under it is a fact.
- **Pilot credit**: the owner's $20 vendor credit. `research.spend_ceiling_usd_total` (req 8) is its config form.

2. **Corpus and frame: fetch outside `tradepartner.research`, build inside it, one tabular dataset.** (#956 item 3.)
   - **Fetch** (`tradepartner corpus fetch departure-reason [--since 2016-01-01] [--until <date>] [--cik <cik>]... [--limit n]`, module `tradepartner.corpus.departure_fetch`, outside `tradepartner.research` because it imports the EDGAR adapter). The **population** comes from EDGAR, not the store: every `25`, `25-NSE`, `25/A` and `25-NSE/A` row in the quarterly `form.idx` (`edgar_raw.filing_index_quarter`) accepted in the range, de-duplicated by accession and attributed to the issuer CIK in the notification XML. For each, the submissions JSON of the issuer CIK gives the acceptance time and `primaryDocument` (as the event-data collector does, req 2 (a) there; a filing the submissions carry no acceptance for is counted `unstamped` and excluded, never dated from the index). An amendment is attached to the latest earlier original of the same issuer CIK and exchange, and its documents join that listing end's packet; an amendment with no original is its own listing end flagged `orphan_amendment`. From the same index the fetch records, per listing end, the issuer's `8-K`, `8-K/A` and `8-K12B` filings accepted in `[filing date − research.labeling.context_before_days, filing date + research.labeling.context_after_days]` (calendar days: a filing window, not a session window) and its `15-12B`, `15-12G`, `8-A12B` and `8-K12B` **marker filings** from 30 calendar days before the filing date to the earlier of the CIK's next listing end and `research.labeling.marker_after_days` (default 400) after it, each with accession, form, acceptance and filing date (the frame build applies the master's session windows to them). It downloads the Form 25 primary document, each context 8-K's primary document and its first `EX-99.1` exhibit through `edgar_raw.download_filing_file` at the existing paced rate (`edgar.requests_per_second`; the cross-process limiter once the event-data plan lands it; free-data terms 7a: at most 10 per second) with the existing User-Agent, and **copies** the bytes to `edgar.cache_dir/corpus/departure-reason/<build_id>/files/<cik>/<accession>/<filename>`, so that `_fetch_delisting`'s unlink of `cached_filing_path` (edgar_source.py) and a `DELISTING_VERSION` bump can never remove them; a file already present under the build's directory is not requested again. It writes a **manifest** `edgar.cache_dir/corpus/departure-reason/<build_id>/manifest.json`: one entry per listing end (`cik`, exchange, class, `form25_accession`, form, acceptance, filing date, effective day from the XML else filing date + 10 days, `rule_provision` normalised by stripping the `17 CFR 240.` prefix, so `12d2-2(a)(2)`, the attached amendments, the context documents and the marker filings, each with its local path and the SHA-256 of the raw bytes) and the **counts**: `form.idx` rows seen, listing ends kept (with how many of them are flagged `orphan_amendment`), and one count per exclusion category (`pre_xml`, `unstamped`, `exchange_copy`, `amendment_attached`), so that listing ends kept + `pre_xml` + `unstamped` + `exchange_copy` + `amendment_attached` equals the index rows seen. A document EDGAR does not serve is recorded as missing with its HTTP status, never retried past `edgar`'s retry policy, and the listing end stays (protocol §4.5: a failure is counted, not screened out). The fetch imports nothing from `tradepartner.research`, reads nothing from the runtime store, and writes nothing under `research.data_dir`.
   - **Frame build** (`tradepartner research frame build departure-reason --manifest <path> --as-of <t> [--register]`, module `tradepartner.research.labeling.frame`, which imports no adapter: it reads the manifest's local paths and the runtime store through read-only readers only). It extracts text deterministically with a versioned extractor (`corpus_version`; HTML to text, whitespace and entity normalisation, 8-K item segmentation on the `Item N.NN` headings, character offsets on the normalised text whose SHA-256 is recorded), renders the Form 25 notification as labelled fields (`issuer`, `exchange`, `class`, `rule_provision`, `signature_date`), and computes the **rule answer** of Definitions for every listing end at `t` with one short-lived read-only connection to `settings.store.path`, opened after the texts are extracted and closed before anything is written: the join to `delistings` by (issuer CIK, exchange, `filed_at` = acceptance), `listing_ends_as_of(conn, t, settings)`, the `listings` and `securities` reads, and `master.reorganisation_window_sessions` applied through the XNYS calendar to the manifest's Form 15 dates. It writes **one tabular file** (`frame.parquet`) under `research.data_dir/frames/departure-reason/<sha256>/`, one row per listing end: `listing_end_id` (= `form25_accession`), `cik`, `security_id` (null when `unmatched`), `exchange`, `class_title`, `form25_accepted_at` (the event column), `form25_filed_on`, `effective_on`, `rule_provision`, `documents` (JSON: the Form 25 fields and each context document's form, accession, acceptance, items, normalised text, offsets and hashes), `markers` (JSON), `rule_status`, `rule_relisted`, `rule_successor_id`, `rule_form15_in_window`, `rule_row` (the crosswalk row of req 5), `rule_as_of`, `rule_code_version`, `corpus_version`, `missing_documents` (JSON), plus the exclusion counts in a sidecar `counts.json`. `--register` calls `store.research.register_dataset` under the name `departure-reason-frame` with `--event-column form25_accepted_at` and the computed span (no split file: every row is `full`); without it the command prints the `tradepartner dataset register` invocation. A rebuild (new texts, or new rule answers after a resolver fix, recorded by `rule_code_version` and `rule_as_of`) is a new version; nothing edits an export in place. A **prospective frame** (`--since <freeze date>`) is registered under `departure-reason-frame-prospective` with a split file assigning every row `prospective`.
   - **Survivorship.** The population is the index's Form 25s, so every delisted name is in it by construction; the checks are the count identity above and that every `delistings` row at `t` joins exactly one listing end (a row that joins none is reported: it means ingest kept a filing the index does not list, or the join key drifted). `quant-auditor` reviews the fetch and the frame build (frame code; data-foundation domain rules).

3. **Packet builder: pure, from the bound dataset's row only.** `tradepartner.research.labeling.packets.build_packet(row, option_set, limits) -> Packet` takes one frame row (or a row of any dataset derived from the frame, which carries the same `documents` column) and returns the `state` string and its metadata, deterministically: the Form 25 fields first (with the filing date and the effective day written out in words and ISO form, so the model is not asked to compare dates: TC §4 and the vendor's documented weakness on "Date and time comparison"); then, in fixed priority order, the 8-K12B body, the 8-K items in `research.labeling.eightk_items` (default `["3.01", "2.01", "1.01", "5.03", "3.03", "8.01"]`, in that order), then the first `EX-99.1` of each 8-K, each document labelled with its form, accession and acceptance date; the whole truncated at `research.labeling.max_packet_tokens` (default 8000; a token is estimated as 4 characters before the call, replaced by the vendor's returned `usage.input_tokens` after it), by dropping whole documents from the lowest priority up, then truncating the last kept document at a sentence boundary; what was dropped and where the cut fell are in the packet's metadata. The text is wrapped between fixed delimiters and labelled as filing text; the question text and the option set are never inside the delimiters. **The builder contains no table name** from `TABLE_NAMES`, `JOURNAL_TABLE_NAMES`, `MASTER_CHECK_TABLE_NAMES`, `REGISTRY_TABLE_NAMES` or `RESEARCH_TABLE_NAMES` (whole-token match, req 14), no gold- or review-dataset name, and never reads the `rule_*` columns (the shortlist in req 9 does), so the ADR 0013 point 3 (c) allowlist for it is empty (#956 item 5). The packet carries nothing but the passage, the filing identifiers and the question: no position, order, decision, price, hypothesis, gold label or review decision (ADR 0013 point 6); req 14's test holds it to that, and so does its only input (a row whose `documents` column came from EDGAR).

4. **The question and the option set, versioned.** One `choice` question per packet, as a versioned object `tradepartner.research.labeling.questions.OptionSet` with `version`, `instructions`, an **ordered** list of `(option, description)` pairs and a SHA-256 over all of it (the `prompt_version` of prospective spec §3). The pilot's proposed set (owner question 1), whose descriptions avoid every store table name as a whole token (req 14):

   | Option | Class | Description the model sees (abridged; the full text is the versioned object) |
   |---|---|---|
   | `merger_or_acquisition` | `terminal` | the company was acquired by or merged into another company; holders received cash or the other company's shares |
   | `going_private` | `terminal` | the company was bought out by insiders, a sponsor or through a cash-out reverse split and stopped being publicly traded, without a separate acquirer absorbing it |
   | `instrument_retirement` | `terminal` | the instrument reached maturity, was redeemed, called, converted or expired (notes, warrants, units, rights, a SPAC trust liquidation) |
   | `redomicile_or_reorganisation` | `continuity` | the same business continued under a new holding company, domicile, legal form or a separation, and holders of the old class hold the new one |
   | `bankruptcy` | `insolvency` | the class was cancelled, or trading ended, because of a bankruptcy or insolvency proceeding |
   | `compliance_delisting` | `removal` | the exchange removed the class for failing a listing standard (bid price, market value, filing delinquency, other), not because of any of the above |
   | `voluntary_withdrawal` | `removal` | the issuer withdrew the class from the exchange by its own decision, to trade over the counter or to deregister, with none of the above as the reason |
   | `exchange_transfer` | `transfer` | the class moved to another national stock exchange and kept trading |
   | `unresolved` | (none) | the filings shown do not state the reason |

   Nine options, two more than ADR 0013's table row A (`exchange_transfer` and `voluntary_withdrawal` split "voluntary delisting or exchange transfer", because the resolver treats them differently; `instrument_retirement` replaces "other", because a closed set without "other" keeps `unresolved` honest). The instructions name the task in one sentence, say the reason must be stated in the text shown, and say to choose `unresolved` otherwise. Option order is fixed for a version; the perturbation probe (req 11) permutes it. Any change is a new version with a new hash; versions tried on `dev` count against the registration's `budget.configurations` (req 10), and the version the sealed `pilot` is scored with is frozen before that score and named in the `TP-` claim (ADR 0013 point 5: never the bars after the fact).

5. **Classes, crosswalk and the deterministic arm, in a pure module.** `tradepartner.research.labeling.crosswalk` holds three registered tables, hashed into `config_json`; changing any is an amendment.
   - **Classes** (a true partition of the eight options, for scoring and display): `transfer` = {`exchange_transfer`}; `continuity` = {`redomicile_or_reorganisation`}; `insolvency` = {`bankruptcy`}; `terminal` = {`merger_or_acquisition`, `going_private`, `instrument_retirement`}; `removal` = {`compliance_delisting`, `voluntary_withdrawal`}.
   - **Crosswalk** (rule answer → consistent options; the shortlist's definition of disagreement):

   | Row | Rule answer (status, relisted same security, successor, Form 15 in window) | Consistent options |
   |---|---|---|
   | 1 | `transferred` | `exchange_transfer` |
   | 2 | `delisted`, same security relisted after the effective day (#820 relisting: CMPR, CG, WELL, Seagate 2021) | `redomicile_or_reorganisation` |
   | 3 | `delisted`, a successor security created (#820 new equity; owner-accepted MTCH) | `bankruptcy`, `redomicile_or_reorganisation` |
   | 4 | `delisted`, Form 15 in the reorganisation window, no relisting, no successor | `merger_or_acquisition`, `going_private`, `redomicile_or_reorganisation`, `instrument_retirement` |
   | 5 | `delisted`, none of the above | `merger_or_acquisition`, `going_private`, `compliance_delisting`, `voluntary_withdrawal`, `instrument_retirement`, `bankruptcy` |
   | 6 | `listed` after the effective day (the line the rule did not end: #921, #943) | none: a disagreement by construction (ADR 0013 table row A) |
   | 7 | `unmatched` (no `delistings` row joins the filing: the rule placed nothing) | none: a disagreement by construction; the model's label is shown as a proposal |

   This refines the partition ADR 0013's table sketched ("successor-bearing" there grouped merger and going private with redomicile; the master's rules put a Form 15 after a merger and a successor only after new equity, so the sets above follow the code). Rows 1 and 2 map to one class each; rows 3 to 5 map to a class set; rows 6 and 7 to none.
   - **Deterministic comparison arm**: the Form 25's `rule_provision` mapped by code: `12d2-2(a)(1)`, `(a)(2)` → {`instrument_retirement`}; `(a)(3)` → {`merger_or_acquisition`, `going_private`, `redomicile_or_reorganisation`, `bankruptcy`}; `(a)(4)` (all rights extinguished, typically by court order) → {`instrument_retirement`, `bankruptcy`}; `(b)` → {`compliance_delisting`, `bankruptcy`}; `(c)` → {`exchange_transfer`, `voluntary_withdrawal`}; anything else → {`unresolved`}. The source of the mapping is the rule's text (17 CFR 240.12d2-2 (a)(1) to (a)(4), (b), (c)), cited in the experiment file. The arm is scored on the same gold items as **coverage** (the set contains the gold option's class) and, where the set is one class, as class accuracy, so the pilot answers whether reading the 8-K adds anything to a field code already has (TC §9; the backlog's B8 question on our own data).

6. **The labeling job: handle first, guard, call, record, register.** `tradepartner research label <slug> --dataset <id> --split <split> [--run <id>] [--accepted-from <date>] [--accepted-to <date>] [--limit n] [--drift-set <dataset id>] [--configurations 1]` (module `tradepartner.research.labeling.job`):
   0. for a `pilot` split only, **before** opening anything, reads the registry (`research_results` of the `departure-reason-probes` registration) and exits 2 with `perturbation probe not passed` unless the latest perturbation run for this option-set hash has verdict `pass`; this check reads no data and calls no model, so it leaves no run row, and the one sealed score is not spent on a refusal;
   1. opens the run through `research.open_run` (or attaches with `--run`), kind `benchmark`, before anything else that reads data (research-registry req 3); a `pilot` split bound to the sealed period needs `--spend-holdout --holdout-reason` on the open and is a spend, once; a second scoring of the sealed period is a flagged repeat (#956 item 6; research-registry req 5). The run reads **no runtime store**: its only input is the bound dataset (`store_max_ingested_at` is null on its row, so research-registry req 8's `store changed during run` cannot fire during a review that lasts days);
   2. with `--drift-set`, runs the drift probe of req 11 under its **own** `robustness` run (its own open, its own guard of step 3, its own records) and closes this run `failed` with `drift probe not passed` before any labeling call unless the probe's verdict is `pass`;
   3. loads the bound rows through `research.load_dataset(handle)`, applies the selectors (acceptance range, `--limit`, in acceptance order), builds every packet (req 3), and **guards** the batch through `tradepartner.research.labeling.spend.guard_batch(handle, requests, settings)`, the one function every call path uses before its first call (probes and the recorder included, req 11, req 7): the estimate is Σ over requests of (state tokens + instructions tokens + criteria tokens, at 4 characters a token) × `research.labeling.price_usd_per_million_input_tokens` × (1 + `research.labeling.estimate_margin`, default 0.25); the guard refuses (the run closes `failed`, message `spend ceiling: <estimate>`) when month-to-date spend + estimate > `research.spend_ceiling_usd_month`, or cumulative spend + estimate > `research.spend_ceiling_usd_total`, or estimate > `research.labeling.batch_max_usd` (default 2.5), where month-to-date and cumulative spend are **computed from every inference record in the research store** (all runs, probes and recordings included), never configured (ADR 0013 point 7; owner decision 2);
   4. calls the model once per packet through `tradepartner.research.models` (req 7) at `research.labeling.requests_per_second` (default 2.0), writing one inference record per attempt as it goes; stops the batch (`failed`, `model id mismatch`) on the first response whose `model` differs from the requested id, and (`failed`, `runaway spend`) when returned `usage.input_tokens` so far exceed twice the estimate for the requests sent; a packet whose attempts end in a timeout after send is recorded with `selected_option = "unresolved"`, `reason = "timeout"`, no probabilities, and is never silently re-sent;
   5. registers the inference records as a dataset version (`departure-reason-inferences`, event column the Form 25 acceptance) and records its id in the result's `exploratory_json`; on a gold-derived dataset (`dev`, `pilot`) scores against the rows' gold columns (req 10) and writes the result; on a frame dataset (`full`, `prospective`) computes the shortlist (req 9) and leaves the run **unfinished** for the review command to finish.
   A batch is **never** scheduled: no timer, no launchd entry, no `collect` source; the command is run by hand (ADR 0013 point 8).

7. **The model client: plain `httpx`, pinned version, everything recorded.** `tradepartner.research.models` is the only module that names the vendor's host (`research.labeling.api_base_url`, default `https://api.typesafe.ai/v1`, declared in `config.py`) and the key's variable name (`TYPESAFE_API_KEY`, read by `config.Settings.typesafe_api_key: SecretStr | None`, in the `secret_values` redaction set `cli_record` and `clean_message` use). **Decision: no SDK for the pilot** (#956 item 1). The call is one `POST {base}/systemone` with `Authorization: Bearer <key>` and the body `{"state": <packet>, "model": <pinned id>, "questions": {"departure_reason": {"type": "choice", "instructions": ..., "criteria": {<option>: <description>}}}}`, over `httpx` (already a runtime dependency), with a timeout `research.labeling.request_timeout_seconds` (default 60), at most `research.labeling.max_attempts` (default 3) attempts per packet, retrying only HTTP 429 and 529 (and a connection error before any byte was sent) with exponential backoff that honours `Retry-After`, never a timeout after the request was sent (it may have been billed; the record says `timeout`; req 6 step 4 says how the packet counts). Reasons for `httpx` over `typesafe-sdk`: the vendor's SDK selects the model at client construction and its quick start pins the moving alias (`TypeSafeClient(model="jev")`), where the HTTP body takes a per-request `model`; the SDK retries 408 and every 5xx by default (`RetryPolicy`, 2 retries, 0.5 s to 5 s), which re-sends a possibly billed request; an optional dependency group would need a guarded import or a CI-only extra for `mypy --strict` and the import scan; and ADR 0013 test (c) is written for exactly this shape. The `research` dependency group is therefore **not created** for the pilot; test (a) still holds the forbidden list (req 12). If a later spec adopts the SDK, it lives in that group, is imported only here with `RetryPolicy(max_retries=0)`, and CI installs the group for the type check only.
   - **Pinned model.** `model` is the versioned id from the registration's `config_json` (`jev-1.13.0` at the time of writing; the vendor's Models page lists `jev-latest` and `jev-preview` as aliases that "can shift when releases ship"). The client refuses to send an alias (`jev-latest`, `jev-preview`, `jev`) and any id not matching `^jev-\d+\.\d+\.\d+$`.
   - **Per-call record** (ADR 0013 point 5): `record_id`, `run_id`, `listing_end_id`, `security_id`, `document_ids` (accessions) and `passage_sha256`, `option_set_version` and hash, `corpus_version`, `model_id_requested`, `model_id_returned` (the response's `model`), `client_version` (this module's version constant), `attempt`, `request_sha256`, `raw_request` (body only; no header), `raw_response`, `selected_option`, `probabilities` (the full map, which the vendor states sums to 1), `vendor_confidence` (stored separately, never substituted: TC §5, `(p_max − 1/K)/(1 − 1/K)` for K options), `input_tokens`, `output_tokens`, `cost_usd` (= `input_tokens` × the price snapshot; the API returns no billed cost, so `research.labeling.price_usd_per_million_input_tokens`, default `0.042`, is the snapshot, with its date in `price_snapshot`), `http_status`, `latency_ms`, `reason` (`ok`, `timeout`, `refused`), `inference_started_at`, `inference_completed_at`, `known_at` (= `inference_completed_at`, UTC, tz-aware; never back-stamped), `source_available_at` (the Form 25's acceptance). Written append-only as JSONL under `research.data_dir/inferences/departure-reason/<run_id>.jsonl` by `tradepartner.research.datafiles` (the one module that resolves `research.data_dir`, besides `research.load_dataset`).
   - **Zero default and the test doubles** (ADR 0013 point 3 (e); #956 item 2). The real client is constructed only when `research.spend_ceiling_usd_month > 0`, `research.spend_ceiling_usd_total > 0` and the key is present; the defaults are `0.0`, `0.0` and `None` in code, and with them `tradepartner.research.models` cannot open a connection (a test monkeypatches `httpx.Client` and asserts it is never constructed). The module takes a `ModelClient` protocol. Tests use two doubles, both in `tests/research/`: `ScriptedModelClient`, a stub the test scripts (responses, 429s, a mismatched model id, a timeout), labelled synthetic in its docstring and never presented as a recording, for every logic and error-path test; and `RecordedModelClient`, which replays the owner's recordings `tests/fixtures/typesafe/<name>.json` **by fixture name** (the test names the recording it wants, so an edit to `packets.py` or `questions.py` does not invalidate it), used by one **contract test** that parses a real response's shape (`model`, `answers.*.{choice, probabilities, confidence}`, `usage`) and checks `vendor_confidence` against the formula. Agents never hand-write a file under `tests/fixtures/typesafe/` (ADR 0008 point 3, last sentence); the contract test is skipped with the reason `owner recordings pending` until the recordings exist, and that skip is the declared stub (plan-shape rule 4).
   - **Recording is an owner task, and a run.** `tradepartner research record-fixtures --dataset <id> --out tests/fixtures/typesafe/` (module `tradepartner.research.labeling.record`, inside `tradepartner.research`, so ADR 0013 test (b)(ii) holds as written) opens a `benchmark` run under the registration `departure-reason-fixtures` (req 10) bound to `departure-reason-fixture-packets` (the hand-built tabular file `tests/fixtures/typesafe/packets/packets.parquet`, which the owner registers with `tradepartner dataset register` first; its eight rows carry `documents` and an expected option, so the recording is a scored run with `n = 8`, verdict `n/a`), reads the packets through `research.load_dataset(handle)` like every run, guards it (req 6 step 3), sends the eight packets with his key, writes their inference records like any run (so the recording's cents are in the spend) and registers them as a dataset version under `departure-reason-fixture-inferences` (never under `departure-reason-inferences`, whose existence blocks the gold session, req 9), and writes the fixture files with the response body only (no header; the key never appears in a response; `clean_message` runs over the file anyway). The fixture packets are hand-built from `tests/fixtures/edgar/` (the KLX Energy 25-NSE, `rights`, `12d2-2(a)(2)`) and seven short synthetic passages, one per non-`unresolved` option, under 1,000 tokens each.
   - **Config of the client** is settings, never a registration field: `research.labeling.api_base_url`, `request_timeout_seconds`, `max_attempts`, `requests_per_second`, `price_usd_per_million_input_tokens`. What the model is asked (`model`, option set, packet limits) is registration (`config_json`), so a run is reproducible from its row and the research store.

8. **Spend: two ceilings from the owner's `.env`, spend computed from records.** `research.spend_ceiling_usd_month` (ADR 0013 point 7) and `research.spend_ceiling_usd_total` (the pilot credit, owner decision 2) are both `0.0` by default in code; the owner sets `RESEARCH__SPEND_CEILING_USD_MONTH` and `RESEARCH__SPEND_CEILING_USD_TOTAL` in `.env` (recommended `10` and `20`, owner question 4). `tradepartner research spend [--month YYYY-MM]` prints month-to-date and cumulative spend from the inference records, by run, with the count of records, and the headroom under both ceilings; it reads the research store and the run rows only. A PR that changes either default or the "cannot connect at zero" test is labelled `hold` (ADR 0013 point 3 (e)). The owner records actual billing on #946 after the first batch and, each month, the research spend beside the running system's $0 (ADR 0005). **Cost estimate for pilot A** (list price $0.042 per million input tokens, output free, vendor Models page read 2026-10-05; billing unverified until the first invoice): the population is a few thousand listing ends (ADR 0013 point 7; the fetch prints the count); at the 8,000-token packet cap plus about 400 tokens of question, 5,000 listing ends are 42 M tokens, **$1.76** (with the 25% margin, $2.21, under the $2.50 batch cap; typical packets, a Form 25 of a few hundred tokens plus one or two 8-K items, will come in well under the cap); the 150-item gold sample is about 1.3 M tokens, **$0.05**, per configuration, so four `dev` configurations on 30 items and one `pilot` score on 120 are **$0.08**; the perturbation probe (five option orders over the 30 `dev` items) **$0.05**; a 100-packet drift baseline and a drift probe before each of twelve later batches **$0.46**; the fixture recording under $0.01. The pilot as registered is therefore **under $3**, about 15% of the credit; the guards in req 6 step 3 and the runaway stop in step 4 are what protect the credit against a repricing, a loop bug or a mis-sized packet, and a 5× misestimate still fits. The corpus is the whole population, so no sampling is needed for cost; sampling in req 10 serves the gold labels.

9. **The human path: shortlist, blind review, review file, fix by PR.** For a batch run, `tradepartner.research.labeling.crosswalk.shortlist(inferences, rows, crosswalk, seed, agreement_sample_size, max_items)` returns every disagreement (the model's option outside the row's consistent set, rows 6 and 7 always), every `unresolved` (including `timeout` records), and `agreement_sample_size` agreements drawn under the seed (default 30, registered), each with its stratum (`disagreement`, `unresolved`, `agreement_sample`) and the agreement sampling rate; items beyond `max_items` (registered in `config_json`, default 200) in acceptance order are marked `deferred`, counted, and carried to the next batch's selector, so the owner's time per batch is bounded. `tradepartner research review --run <id> [--item <n>] [--finish] [--report]` (in `cli`, calling `tradepartner.research.labeling.review`) attaches the unfinished run and pages the shortlist: the passage (the packet text, with the documents' EDGAR archive URLs), then two answers labelled `a` and `b` in an order drawn per item from a seed derived from the run id and the item id (stable on re-display, unknown to the owner), **both rendered in the same form, as class descriptions** (the model's class; the rule's class, or its class set for rows 3 to 5, or "the rule kept the line listed" / "the rule placed no filing" for rows 6 and 7), **with no option name, probability, confidence or attribution shown**; the owner records `a`, `b`, `both_wrong` or `unresolved`, a reason, and the passage he relied on (accession, character offsets on the normalised text, the quoted text's SHA-256). The command attributes after the save (`decided_for` ∈ `rule`, `model`, `both_wrong`, `unresolved`) and appends the record to the **review file** `research.data_dir/reviews/departure-reason/<run_id>.jsonl` (`review_id`, `run_id`, `listing_end_id`, `security_id`, `stratum`, `decision`, `decided_for`, `reason`, `passage_ref`, `reviewer = "owner"`, `code_version`, `known_at` UTC); nothing else writes that file. `--finish` registers the review file as a dataset version (`departure-reason-reviews`), computes the batch metrics of req 10, and writes the run's result; `--report` after `--finish` prints the attributed table. The review command never reads the runtime store and never writes to `store.path`, `events.path` or config, and offers no "apply": **a fix is a PR** under its own issue, by any team, citing the review file's SHA-256, the accession and the owner's decision as the value's source, carrying the filing's `known_at`, with a pinned test as #921 did (ADR 0013 point 4; ADR 0008 point 3). The **labelling aid** (`tradepartner research gold --frame <dataset id> --seed <s> --n 150 [--sheet <path>] [--lock]`, module `tradepartner.research.labeling.gold`; owner decision 3) draws the sample of req 10 from the frame by **seeded random draw only** (reading the registered export by the path given on the command line and refusing when its SHA-256 differs from the row; neither the model's output nor the `rule_*` columns nor the `rule_provision` arm takes any part in choosing cases, so there is no selection bias), refuses to start when any `departure-reason-inferences` version exists (gold is made first; the fixture recording's records are registered under `departure-reason-fixture-inferences`, never under that name), and shows one case per screen built for speed: the Form 25 fields on top (issuer, exchange, class, filing date, effective day, `rule_provision`); then only the code-selected passages of req 3, each headed by its form, **item number and acceptance date highlighted**, paragraphs numbered; no `rule_*` column, no model answer (none exists yet, and the screen has no field for one); the nine options as **one keystroke each** (`1` to `9` in the option set's order, the ninth `unresolved`), `s` to **skip** (the case returns to the end of the queue; a case still skipped at `--lock` is recorded `unlabelled`, counted, excluded from scoring and never replaced, since replacing after reading the text would be selection), `?` for **unsure** (records the chosen option with `annotator_confidence = low`), the passage relied on by **typing the paragraph number** (the aid stores the offsets and the quoted text's SHA-256; no offsets are typed), `o` to print the filings' EDGAR URLs, `b` to go back one case. `--sheet` writes the same per-case rendering as one static HTML file (read-only, no answer fields, no model output) for reading away from the keyboard, with labels then entered by case id at the keyboard. Each label is appended to a working file `research.data_dir/gold/departure-reason/working.jsonl` (`label_id`, `listing_end_id`, `label`, `passage_ref`, `annotator_confidence`, `seconds_spent`, `labeled_at`, `manual_version`); `--lock` writes the content-addressed tabular export (every frame column of the sampled rows, `documents` included, plus `gold_label`, `gold_class`, `passage_ref`, `seed_case`, `unlabelled`) and its split file, registered `--locked` under `departure-reason-gold` with `--event-column form25_accepted_at` and the sealed `pilot` period. **Time per case**: a packet is a Form 25 of a few fields plus at most two or three 8-K items; reading them and pressing a key is one to two minutes for a plain merger or compliance notice and three to four for a reorganisation or a bankruptcy with several filings, so about **1.5 to 2 minutes a case on average: 150 cases are 3.75 to 5 hours**, the dev 30 included and the up-to-five seed cases on top; `seconds_spent` is recorded per case so the retro can replace the estimate with the measurement (ADR 0005).

10. **Evaluation as a registered experiment, bars before data.** Five experiment files under `docs/experiments/` (research-registry req 2; T82's template), merged and registered before the first model call. Common to all: `touches_returns = false`, `confirmatory = false` unless stated, `claims` naming topic 9b's claim ids and B8's, `[multiplicity] method = "none"`, the crosswalk, classes and `rule_provision` tables and the seeds' pre-fix rule answers in the prose and in every run's `config_json`.
    - **`departure-reason-fixtures`** (`kind = benchmark`, `stage = 3`, `provenance = model_historical`, `splits = ["none"]`, dataset `departure-reason-fixture-packets` (the eight hand-built packets with expected options, tabular, event column the KLX acceptance for the real one and the build date for the synthetic ones), `[window]` 2016-01-01 to 2026-12-31, primary `exact_accuracy`, no threshold (verdict `n/a`), `min_clusters = 1`, `budget.runs = 3`): the recording run of req 7.
    - **`departure-reason-pilot`** (`kind = benchmark`, `stage = 3`, `provenance = model_historical` (research-registry req 2 refuses `confirmatory`; ML brief §7), `splits = ["dev", "pilot"]`, `[dataset] name = "departure-reason-gold"`, `[window]` 2016-01-01 to the configuration freeze date, `[budget] runs = 10, configurations = 4`, `seed` published on #963 before the frame is built). **Gold sample** (owner decision 3, 2026-10-05: about 3 to 5 owner-hours): **150 listing ends** drawn from the frame by a seeded random draw stratified by period only (30 from the `dev` period, 120 from the `pilot` period, below), **one per CIK**: within each period the listing ends are permuted under the seed and the first listing end of each not-yet-drawn CIK is kept until the period's count is reached, so the estimand is **one listing end per CIK per period** (a CIK with many listing ends, such as notes, warrants and units, contributes one), with no other stratification and no use of any model output, `rule_*` column or `rule_provision` value in the draw (the crosswalk rows' counts in the sample are reported, not forced); the **seeded error set** is added beside the 150, outside the one-per-CIK rule, scored by `seeded_recall` and **excluded from the accuracy denominator** because it is chosen by issue history, except that a seed's listing end the random draw itself picks stays in the denominator as a random item and counts for `seeded_recall` too (excluding a randomly drawn item would be selection): Valaris (#921; Form 25 2020-09-04), Seagate 2021 and MiMedx 2019 (#943), Sotheby's 2019 (#905), the Match Group 2020 separation (#828, #922); Seagate 2010 is outside the population and is not a seed; each seed's **pre-fix rule answer** is the output of the pre-fix rule function at the fix's parent `code_version` as traced on its issue (#921 and #922 at `f2b5261`, #943 at `ca79641`, #905 at #847's parent), recorded in `config_json` with that commit, and a seed whose Form 25 the frame does not hold is dropped and noted at registration (#956 item 10; #893's rename holes have no Form 25 and are not seeds). **Splits**: `dev` = 30 items drawn from the earliest acceptance span that holds at least 300 frame rows (the boundary date, about the end of 2016, is fixed at registration from the frame's counts); `pilot` = 120 items drawn from after that boundary to the freeze, sealed by that period at `dataset register`; the sealed `pilot` is scored **once** per registration (the spend of req 6). **Primary metric**: `class_accuracy`, the share of `pilot` gold items (gold `unresolved` and `unlabelled` excluded; a `timeout` record counts as wrong) whose model class equals the gold class, `direction = greater`, `threshold = 0.80`, `ci_level = 0.95`, `inference = "Wilson score one-sided 95% lower bound (one item per CIK, unweighted)"`, `n_clusters` = the scored `pilot` items (one CIK each, after the exclusions), `min_clusters = 90` (120 drawn at one per CIK, leaving room for up to 30 gold `unresolved` and `unlabelled` exclusions before the one sealed score is spent on `underpowered`; the scorable count is printed at `--lock` and recorded on #963 before the pilot run opens). **The bars are lower bounds, so the smaller sample makes passing stricter, not looser**: at n = 120 an observed accuracy of 0.85 (102 of 120) gives a Wilson lower bound of **0.789**, which **fails** the 0.80 bar; 0.90 (108 of 120) gives **0.846**, which passes; the smallest passing count is **104 of 120** (0.867, lower bound 0.807; 103 gives 0.798). The sample is therefore sized so that a model right about nine times in ten passes and one right about 85% of the time does not, which is the standard the owner set in question 5. **Secondary (gating through the stop rule, computed by code)**: per-option precision and recall with one-sided 95% Clopper–Pearson lower bounds, gate `precision_lb ≥ 0.60` for every option with at least 20 gold items (fewer: `underpowered`, reported, not gated; at n = 120 most options will be underpowered and the gate will bind on the common ones only); `seeded_recall = 1.0` (every seed on the shortlist under the pre-fix rule answer); `unresolved_share ≤ 0.15` on `pilot`; `unlabelled_share ≤ 0.05` on `pilot` (skipping is a choice the owner makes after reading the text, so a large unlabelled set would bias the accuracy upwards; beside the primary, the **worst-case lower bound** that counts every unlabelled item as wrong is reported, and the `TP-` claim quotes both). **Reported, never gating**: ECE with 15 equal-mass bins, multiclass Brier (summed over classes, not divided by K), classwise reliability, all on the **probability vector**, never on `vendor_confidence` (ML brief §5.5); the `rule_provision` arm's coverage and class accuracy on the same items (`comparison_set`); first-option bias from the perturbation probe; p50 and p90 latency; cost. `stop_rule`: a missed gate is a negative result and closes the task; the option set may be narrowed in a new registration, the bars never lowered after a `pilot` score. `expected_effect`: class accuracy 0.80 to 0.90 (a factual reading of a stated reason, easier than TC's 0.73 on sentiment); the `rule_provision` arm alone covers most `terminal` items and none of the `insolvency`-versus-`removal` or `continuity`-versus-`terminal` distinctions.
    - **`departure-reason-probes`** (`kind = robustness`, `stage = 3`, `provenance = model_historical`, `splits = ["dev"]`, window as the pilot's, `min_clusters = 30`, `budget.runs = 30`). The **perturbation probe** binds `departure-reason-gold` split `dev` (never `pilot`: the sealed items are not read before the score): five fixed permutations of the option order over the 30 `dev` items, primary `flip_rate` (share of items whose selected option changes under any permutation), `direction = less`, `threshold = 0.20`, one-sided 95% upper bound (at n = 30 that passes up to two flips); a verdict other than `pass` means the option set is revised (a new version, within `budget.configurations`) and probed again before the `pilot` score, which req 6 step 0 refuses otherwise. The **drift probe** binds `departure-reason-drift-set`, built in two versions by `tradepartner research probe drift` (module `probes.py`): `--build --frame <id> --n 100 --seed <s>` writes **version 1**, 100 frame rows from the `dev` period (gold labels not needed; `documents` carried; a split file assigning every row `dev`, since the probes registration binds `dev`), and registers it; the first probe run after the freeze binds version 1, labels it, and writes **version 2**, the same rows plus the baseline columns (`baseline_option`, `baseline_probabilities`, `baseline_run_id`, `baseline_option_set_hash`), registered under the same name; every later probe binds the latest version, refuses one without baseline columns, re-sends the same 100 packets at the same pinned id and option-set hash and computes `flip_rate` against the baseline, `direction = less`, `threshold = 0.15`, one-sided 95% upper bound (at n = 100 that passes up to eight flips), with `mean_abs_probability_shift` reported; the labeling job (req 6 step 2) runs it with `--drift-set` before every batch and proceeds only on `pass`. A vendor retirement of the pinned id ends the stream: the next pinned id is a new registration, never a substitute (prospective spec §8).
    - **`departure-reason-batches-historical`** (`kind = benchmark`, `stage = 3`, `provenance = model_historical`, `splits = ["full"]`, `[dataset] name = "departure-reason-frame"`, window 2016-01-01 to the freeze, `min_clusters = 30`, `inference = "Clopper–Pearson one-sided lower bound"`, `budget.runs = 12`) and **`departure-reason-batches-prospective`** (the same with `provenance = model_prospective`, `splits = ["prospective"]`, `[dataset] name = "departure-reason-frame-prospective"`, window from the freeze onward; a later `confirmatory = true` registration on that name, predating its first dataset version, is where a confirmatory record can accrue). Each batch and its review is **one run** (ADR 0013 point 4; #956 item 4: `benchmark` fits, the system being the pinned configuration and the outcome the owner's review decisions, which are human labels on a stratified sample; no new registry kind is needed, and this spec declares that rather than amending the registry spec). Two registrations because `provenance` is a registration field. **Batch metrics** (#956 items 9 and 13): primary `yield` = the share of reviewed `disagreement` and `unresolved` items on which **the rule was wrong**: `decided_for = both_wrong`, or `decided_for = model` on a `disagreement` item (a `model` decision on an `unresolved` item means the filing does not say, which is not a rule error); `direction = greater`, **no threshold** (verdict `n/a`: ADR 0013 point 5 makes yield reported, not gating; the owner decides in the `TP-` claim whether the next batch is worth his time); stratum-weighted **model accuracy** and **rule accuracy** over the batch, each reviewed item weighted by the inverse of its stratum's sampling rate (`disagreement` and `unresolved` 1.0, `agreement_sample` by `agreement_sample_size / n_agreements`), the agreement stratum's lower bound reported separately and the estimates flagged `underpowered` when fewer than 20 agreements were reviewed; `unresolved_share`; `n_reviewed`; `n_deferred`; cost. The batch run binds its **input** frame; its inference records are an **output** dataset version named in the result (a deviation from ADR 0013 point 4's "bound to the batch's inference-record dataset", which cannot exist before the run opens; stated in "Settled").
    All verdicts are recorded by the owner as `TP-` claims labelled exploratory (research program §6). The `pilot` run's `TP-` claim is the pilot's verdict; until it says `pass`, no batch run is opened (ADR 0013 point 5: "no task produces a shortlist for the owner to act on before it has passed").

11. **Probes, guards and provenance honesty.** Every model-call path (`label`, `probe drift`, `probe perturbation`, `record-fixtures`) opens its run first and passes `guard_batch` before its first call; a path with no `RunHandle` cannot call the model, because `models.build_client` requires one. Every packet sent before the freeze is `model_historical` and exploratory forever (research-registry req 2, ML brief §7); the dashboard and every report label it so. Probe records are inference records like any other, under their own run ids, and are never counted in a batch's shortlist or accuracy.

## Risks & domain checks

- **Look-ahead and point-in-time.** The packet holds only filings accepted inside a window around the Form 25, each with its acceptance; the rule answer is computed once, at a fixed `t` recorded on the frame; gold labels are made from the filing text alone, blind to the model and to the rule (the gold screen hides the `rule_*` columns); every record's `known_at` is its completion time and is never back-stamped; a fix carries the filing's `known_at`, never the review's. The model itself may have seen later filings (ML brief §7): every historical result is exploratory by construction, and the honest path to a confirmatory record is the `prospective` frame on Form 25s accepted after the freeze.
- **Survivorship.** The population is the index's Form 25s, so the delisted set is complete by construction; the checks are the count identity and the `delistings`-row join (req 2). The gold sample is a seeded random draw of one listing end per CIK per period (owner decision 3), so its accuracy is an unweighted estimate for that estimand, not for listing ends at large (a CIK with many retired instruments contributes one); the rare crosswalk rows (successor, `listed` after a Form 25, `unmatched`) will be thin or absent in 120 items and their per-option gates `underpowered`, which is reported, and the seeded error set covers the known cases of those rows outside the accuracy denominator.
- **Costs.** Under $3 for the pilot at list price against a $20 credit; two ceilings, a batch cap and a runaway stop in code; spend computed from every record, probes and recordings included; billing reconciled on #946 after the first batch (prospective spec §6: advertised price is never treated as observed cost). The promotional credit's expiry is unknown until the owner reads his account.
- **Order path.** None: tests (b) and (d) prove no import path and no store write; the registry stores numbers; the review command writes only the review file. `tradepartner.execution` is untouched.
- **Secrets.** One key, `SecretStr`, redacted everywhere `secret_values` reaches, read in one module, never in a packet or a record. The recorder is the owner's and runs inside the boundary.
- **LLM inputs.** Filing text is untrusted and the vendor documents that the model "can be steered by injected text": the option set is closed and ours, the instructions are outside the delimiters, and the worst case is one mislabelled passage a human then reads. First-option bias is measured by the perturbation probe before the `pilot` score; dates are supplied by code in words so the model is not asked to compare them; the packet cap keeps the state under the vendor's 32k budget and away from the "large state full of irrelevant detail" failure mode; nondeterminism and silent re-routes are visible through the stored raw response, the returned model id check and the drift probe (vendor determinism is unknown; the 0.15 drift tolerance at n = 100 is a planning value, and a baseline whose own repeat already fails it is a finding that stops the pilot, not a bar to lower).
- **The research store as a temptation.** A directory of plausible labels next to the master; tests (b), (c) and (d) and the dashboard's rule (no label shown) exist for it. Reversible by deletion (ADR 0013 Consequences).
- **Anchoring and blinding's limit.** The review screen shows the two answers as class descriptions in the same form, unattributed and without probabilities, and attributes after the save. The rule's answer is a class or a class set and the model's is one class, so on rows 3 to 7 the owner will often be able to tell which is which; what the blinding buys is that neither answer is marked as the model's and no probability steers him, and that is recorded as the design's accepted limit for a solo owner who also labelled the gold sample. The hindsight check of protocol §6 is not run for a factual label the filing adjudicates.
- **Coverage limits of the frame.** A redomicile's 8-K12B is often filed under the successor's new CIK, outside the issuer-CIK window, so some `continuity` cases will show the model only the Form 25 and the old issuer's 8-Ks and may come back `unresolved`; the `unresolved` share on row 2 is reported per batch. Row 6 (`listed` after the effective day) also holds legitimate cases (one line of a dual listing withdrawn while the other trades), which the shortlist will show and the owner's `rule` decisions will measure; if they flood a batch, the crosswalk gains a sub-row by amendment.
- **Vendor change.** A repricing changes `price_usd_per_million_input_tokens` by a reviewed config change; a retired id ends the stream and a new id is a new registration; a terms change on training or retention is an ADR 0013 Revisit item.
- **Owner time.** 150 gold labels at 1.5 to 2 minutes through the labelling aid is 3.75 to 5 hours before any shortlist, plus up to five seed cases (owner decision 3); the cost is power: an observed accuracy of 0.85 fails the 0.80 lower bound at n = 120 (0.789) where it would pass at n = 300 (about 0.813), which the owner accepted as the stricter side to err on; `max_items` bounds each batch's review; both are recorded as review hours in the retro (ADR 0005), and `seconds_spent` replaces the estimate.
- **Store locks.** The frame build holds one short read of the owner's store after extraction; runs and the review read no runtime store at all; nothing here contends with ingest or the paper window's run beyond that read.
- **Registry reading.** A `pilot` run on the sealed period is a flagged holdout spend on a non-`test` split, which research-registry req 5 allows with `--spend-holdout`; it is not the exploratory run on a sealed `test` split that its open question 4 keeps impossible. T81's tests should pin that reading (a follow-up on the registry plan, not this spec).

## Amendment 2026-10-08 (#1330): the review page writes no store

Owner decision on #1330 (option B, recorded there), found while building T123c. C10 has the page call `lock_gold` and `finish` itself, and both write the research registry through `store.research` on a connection the caller opens. The page lives under `tradepartner.research`, and req 13 (iii) bars that package from importing `store.db.open_for_write`. A Streamlit subprocess cannot borrow the CLI's connection, so the page has no lawful way to open the write. The owner chose to keep req 13 (iii) whole and move the store write out of the page. This section is his later answer. It governs where C10, C12, "Owner decisions 2026-10-06" item 4 ("the lock and the finish run by the page itself"), "Acceptance criteria after this amendment" and the plan's T123c, T124 and T126 lines say otherwise. Nothing else changes.

1. **The page writes only the session's files.** These are the gold working file and the review file, written through `gold` and `review` as before. The page opens no write connection and never calls `lock_gold` or `finish`. Review mode rebuilds its session (`review.build_review_session`, whose `attach_run` reads the registry) on a short-lived `store.db.open_read_only` connection, an allowlisted reader. If the store is locked, the page shows "store busy" with "reload in a moment".
2. **The last answer stops the page.** When the last case is answered or the last item decided, the page shows "done, you may close this tab" and stops the server. A complete session that is not yet locked or finished does the same on any later start. A locked or finished session only displays. The page has no "store busy" retry button.
3. **The launching command locks and finishes.** `tradepartner research gold` and `tradepartner research review --run <id>` (C12, T124) wait for the Streamlit process to end. That may be the page's own stop, Ctrl-C (`KeyboardInterrupt` is caught) or any other exit status. Then they check the session.
   - **Complete session:** the command calls `gold.lock_gold` or `review.finish` on an `open_for_write` connection and prints the count and the hash. For gold, that is the scorable `pilot` count and the export's SHA-256. For review, it is `n_reviewed` and the review file's SHA-256.
   - **Store busy:** a `StoreLockedError`, or `lock_gold`'s `busy` state, prints "store busy" and exits non-zero. Nothing is written to the store, and the working file and the review file are unchanged. The write-once export and split files (gold), or the `finishing` marker (review), may remain, and the recovery flags `--lock` and `--finish` reuse them when they run the same step again.
   - **Partial session** (the owner stopped early): the command prints how many cases or items are open, exits 0 and leaves the session unlocked.
   The command closes any connection it opened to build or resume the session before it launches the page.
4. **The code version comes from the command.** The page may not run `git`, because req 13 (ii) bans `subprocess` under `tradepartner.research`. Review mode therefore takes `--code-version <commit>[+dirty]` after `--`, beside `--session`. The command formats it from `store.registry.code_version`'s `(commit, dirty)`, and the page writes it on every review record. The page refuses review mode without it.
5. **Unchanged.** Every write the page makes is an `on_click` callback that first checks it has not already run, so a rerun writes nothing. The blindness refusal runs at every page start. A partial session is never locked or finished. `--lock` and `--finish` stay recovery flags.

**Acceptance.** This replaces three clauses of "Acceptance criteria after this amendment", Human path bullet: "`finish` runs when the last item is decided"; "the lock runs itself on the last answer … then stops the server"; and "a rerun … after the lock writes nothing" (now: after the last answer).

The page test asserts:
- the last answer shows the done message, calls the server stop and writes no lock or finish marker;
- a complete, unlocked session stops again on a later start;
- a rerun after the last answer writes nothing;
- review mode refuses to open without `--code-version` and writes the given value on its records;
- review mode builds its session on `open_read_only`.

The CLI test (T124) asserts:
- the `research review` argv carries `--code-version` after `--`;
- `research gold` and `research review` lock or finish a complete session after the launcher returns, whether it returns by the page's stop, by Ctrl-C or with a non-zero status, and print the count and the hash;
- on a locked store they print "store busy" and exit non-zero, with nothing written to the store and the working file and review file unchanged;
- on a partial session they print the open count, exit 0 and leave the session unlocked.
