# Spec: Event data, v1 collectors

**Status:** Draft  ·  **Issue:** #306  ·  **Related:** [charter](../charter.md) (Scope, "Deferred beyond the MVP"), [roadmap](../roadmap.md) ("MVP scope"), [ADR 0003](../decisions/0003-data-adapters-local-first.md) (adapters, local-first), [ADR 0005](../decisions/0005-objective-benchmark-stop-criteria.md) (integrity criterion), [ADR 0008](../decisions/0008-llm-role.md) (no LLM), [ADR 0009](../decisions/0009-price-vendor.md) (budget USD 0), [data-foundation spec](data-foundation.md) (req 1 store and lock, req 3 `snapshot_static`, req 6 adapters, req 9 ingest), [backtest spec](backtest.md) (req 8 trial count, req 9 registry), [strategy-lab spec](strategy-lab.md) (req 1 families, family rules, `FAMILY_PARENTS`, fixture marker, quiet intervals), [teams.md](../ways-of-working/teams.md) (owner runs against the real store), research [G2 insider purchases](../research/2026-09-26-g2-insider-purchases.md), [G5 search volume](../research/2026-09-26-g5-search-volume.md), [free-data terms](../research/2026-09-25-free-data-terms.md) (7a EDGAR rate)

## Problem & why now

The system knows prices and a few filing facts. It does not know **what happened** to a company or to the market on a given day: an earnings release, an insider purchase, a bankruptcy notice, an executive order. Every later direction the owner has named needs that record, stamped with when it became knowable:

- new systematic signals (insider purchases: G2 found no post-2010 monthly-horizon test and said only our own backtest can close that gap);
- the Phase 5 LLM memo, whose input packet ADR 0008 requires to be fixed and timestamped;
- context and alerts for held names in Phase 4 ("why is this down 20%?", "a held company filed a bankruptcy 8-K");
- a later picks journal and override review;
- **event studies** ("what happened to prices after events like this?"), which get their own spec after Phase 3 closes (see "Follow-up: event studies" at the end).

**Why now, while the MVP is still in build:** some sources can only be collected going forward. EDGAR is point-in-time by construction (every filing has an SEC acceptance timestamp), so it can be backfilled honestly at any time. The Federal Register can be backfilled with a conservative stamp. News cannot: an archive fetched later is not what was knowable then (handoff §5, D3). Every month news is not collected is a month of evaluation history that can never be recovered. News collection is **new scope**: the charter defers news-text *signals* and the roadmap says "revisit after the MVP runs" for signals; collecting metadata forward is what open question 1 puts to the owner.

This spec is a **side track**. It does not block, and must not slow, the Phase 2–4 critical path: one team builds the collectors in parallel with Phase 4, the collectors write their own file, and the main store's ingest keeps its rate budget and its lock rules (req 6). The two things the collector shares with the rest of the system, the EDGAR pacing lock and short read-only reads of the master, are bounded in req 1 and req 6 so that neither can hold `ingest` or `paper run` for longer than a lock-retry window.

## Users & usage

- **The scheduler** runs `tradepartner collect` on its own interval (`collect.interval_minutes`) on every day, trading or not. It fetches new items from each enabled source, stores them raw, parses them and exits. It opens the main store **read-only, briefly, at the start of a run** (for the security master, req 2), never the broker or the paper account.
- **The owner** glances at the collection card on the data-health page (coverage and last success per source), runs `tradepartner collect --backfill --source S --since DATE` once per source, and later runs event studies under the follow-up spec. Only the owner runs anything against the real store or the real events file (teams.md: agents run on fixtures; owner tasks run on the real data).
- **Build agents** run collectors against recorded fixtures only.
- **Later phases** (Phase 4 ops page, strategy-lab hypotheses, Phase 5 memo, the event-study engine) read the event tables through the as-of API. None of them does so until its own spec says so (req 8).
- **Tests**, on every PR, run parsers on recorded payloads with the network disabled.

## Definitions

- **Event**: one stored record of something that happened, from one source, with `known_at` (when it became knowable to a market participant, tz-aware UTC), `ingested_at`, `source` and `provenance`, as in the data-foundation spec. An event names a **company by CIK** (or none, for a market-wide event such as an executive order), never a `security_id`. Rows are append-only; resolution to securities happens **only at read time** (req 9), so a later ticker change or class split cannot rewrite history.
- **Identity** of a row: (source, accession or document number, and for Form 4 the transaction index within the filing), plus `ingested_at`. Two rows with the same identity except `ingested_at` are versions of one record (a re-parse, req 5); the latest `ingested_at` wins at read time, as `facts_as_of` does.
- **Resolution** (read time, req 9): a CIK resolves to the `securities` rows for that CIK **known at the read's T**, restricted to listings **valid at the event's `known_at`** (`listings.valid_from` and the derived end). Two knowledge times on purpose: which securities and listings exist is read as of T, because pre-2019 tickers rest on `snapshot_static` rows visible only from their fetch time (data-foundation req 3), while whether a listing was live is judged at the event. A CIK with no `securities` row at T is `unknown_cik`. A company event resolves to **every** listing so found (fan-out); the API returns the event once per resolved security with the fan-out count. A Form 4 row also carries a security title: when the CIK has exactly one live listing, the row resolves to it with no flag; when it has more, the title is normalised (case-folded, punctuation and the words "common", "stock", "shares", "par value" and any dollar amount removed) and matched against each `listings.class_title` normalised the same way; one match resolves to that class, otherwise the row fans out and is flagged `class_unresolved`. Both flags are outputs of the as-of API; the counts in `collection_runs` are diagnostic snapshots taken at collect time with the same rule.
- **Event session** E of an event: the first XNYS session whose close is strictly after `known_at`. An 8-K accepted at 16:30 ET on a session belongs to the next session; the same rule handles half-days and holidays through `tradepartner.calendar`. Stored on no row; computed by the as-of API.
- **SEC business day**: a weekday that is neither a federal holiday from pandas' `USFederalHolidayCalendar` (already a dependency through pandas) nor a day in `collect.federal_closures`, a config list of ad-hoc closures (national days of mourning such as 2025-01-09, executive-order closures), maintained by the owner. Exposed by `tradepartner.calendar.is_sec_business_day` and `next_sec_business_day`; never weekday arithmetic in call sites. The Form 4 "late" flag and the Federal Register gap rule use it.
- **Deemed filing date** of an EDGAR filing: the acceptance timestamp converted to ET; at or before 22:00 ET it is that date, after 22:00 it is the next SEC business day (17 CFR 232.13(a)(4), G2). Used only for the "late" flag; never as a stamp.
- **Chunk**: for EDGAR sources one calendar month of accessions per source; for the Federal Register one calendar month of publication dates; for news one collection run. The unit of atomic commit, resume and idempotence (req 3).

## Requirements

1. **Separate events file.** Event tables live in their own DuckDB file (`events.path`), not in `store.path`. Collectors are its only writers. Every other reader (the health card, the as-of API, the future study engine) opens it with the short-lived `read_only=True` rule of the data-foundation spec req 1, attaching it `READ_ONLY` beside the main store. **Lock rules in both directions:** the collector holds the events file read-write only while committing one chunk and releases it between chunks; a reader that holds it open blocks a commit, so the collector retries the lock for `events.lock_retry_seconds` and then exits non-zero with only its `collection_runs` row written (the ingest rule, data-foundation req 9). **Against the main store:** the collector's one read of the master (req 2) uses `open_read_only` with the reader's usual retry for `store.lock_retry_seconds`, closes before any fetch, and never reopens in that run; a writer that starts during that read waits at most the read's duration. **One collector at a time:** `collect` takes a single-instance lock file under `collect.raw_dir` for the whole run; a second `collect` exits non-zero at once with a message naming the holder's pid and start time.
2. **Sources, v1.** Each source is an adapter behind one `EventSource` interface (thin raw fetch + pure parser, as ADR 0003 and data-foundation req 6), with a fixture twin. At the start of each run the collector reads the security master once (req 1): every CIK in `securities`, delisted names included, is its company list; a filing by a CIK outside it is stored with its CIK and counted `unknown_cik`, never dropped, and resolves later if the master learns the CIK (Definitions, Resolution).
   - **(a) EDGAR 8-K and 8-K/A**: accession, CIK, form, item numbers, acceptance timestamp. `known_at` = the submissions `acceptanceDateTime` (`provenance = filing`). The collector finds new 8-K accessions in the EDGAR daily index (forward) or the quarterly `form.idx` (backfill), then **fetches the submissions JSON itself**, per CIK with new accessions, older pages included when the accession is not on the first page, and stores those payloads under `collect.raw_dir` as its raw record; the `items` string and the acceptance come from them. It does not read ingest's stamps cache (a reduced per-CIK file without `items`, on ingest's schedule) and it fetches no primary document in v1 (no consumer yet; a follow-up adds them with a size measurement). An accession the submissions JSON does not carry an acceptance for is not stored and is counted `unstamped`, never dated from the index.
   - **(b) EDGAR Forms 4 and 4/A**: one row per reported non-derivative transaction: reporter CIK, reporter role (director, officer and title, 10% owner), transaction code, `transactionDate`, `deemedExecutionDate` when present, shares, price, shares owned after, the security title, `dateOfOriginalSubmission` for a 4/A, and the **late** flag: deemed filing date (Definitions) later than the second SEC business day after `deemedExecutionDate`, or `transactionDate` when there is none. Accessions come from the quarterly `form.idx` (backfill) and the daily index (forward), both fetched through the existing raw client's HTTP layer with two new index functions; the XML primary document is fetched per accession into `collect.raw_dir` (never `edgar.cache_dir`, so the budget of req 5 sees it). `known_at` = the submissions `acceptanceDateTime`, stamped exactly as `EdgarFilingSource._stamp` stamps index rows, from the same per-CIK submissions payloads (a) fetches; a row with no acceptance time is not stored and is counted `unstamped`, never dated from the index or the XML. G2's point-in-time notes apply: never the transaction date, never the deemed filing date.
   - **(c) Federal Register presidential documents and rules**: document number, type (executive order, proclamation, memorandum, rule, proposed rule), agencies, title, abstract, signing and publication dates, raw JSON cached. Identity is the document number; a document seen by both forward collection and backfill keeps the **earliest** stamp. `known_at`: forward collection = first fetch time (`provenance = snapshot`); backfill = **the close of the first XNYS session on or after the publication date** (the late rule; a session close is always later than the roughly 06:00 ET publication, so no backfilled stamp precedes public availability). Backfill **skips** any document whose late-rule stamp would be later than the current time, counts it, and picks it up on the next run, so `known_at ≤ ingested_at` always holds.
   - **(d) News metadata**: **only if the owner decides so on open question 1.** Headline, source, URL, source-stated publication time. This spec's own rule, in the spirit of ADR 0008: **no field a model at the source computed** enters the store, so no tone, sentiment, theme or entity tags; the raw payload keeps them for a later spec to reconsider. Never full article text. `known_at` = our fetch time (`snapshot`), always, and the row stores `stamp_resolution_minutes` = the `collect.interval_minutes` in force at the fetch. The source's publication time is stored as evidence and is never used as a stamp.
3. **Backfill.** `collect --backfill --since DATE --source S` for (a), (b) and (c) only; `--source news` with `--backfill` is refused before any request. Chunks are atomic, resumable and idempotent (data-foundation req 9): a failure commits nothing from that chunk, earlier chunks stand, a rerun resumes from the last committed chunk, and a completed chunk rerun changes nothing. Form 4 backfill defaults to `collect.form4_backfill_start = 2016-01-01`, matching price history; the owner may pass `--since 2013-01-01` to build the three prior years G2's opportunistic-insider classifier needs. The first collector task measures one quarter of Form 4 fetches and records the measured rate and the projected full-backfill duration in the plan before the owner starts it.
4. **Append-only, amendments as new rows.** Nothing is updated in place. An amendment is its own row with a nullable, **inferred** `amends_accession`: for a Form 4/A, the original is the Form 4 by the same issuer CIK and reporter CIK whose filing date equals `dateOfOriginalSubmission`; one match links, none or several leave the link null and count `amendment_unmatched`. An 8-K/A is stored as its own event with `amends_accession` null in v1 (no source links it, and an 8-K/A usually adds items rather than replacing them); it **never supersedes** the original. As-of reads return every row with `known_at ≤ T`, the latest `ingested_at` per identity; an amendment and its original are both returned, each with its own `known_at`.
5. **Raw kept, within a budget.** Every parsed row points at a raw payload on disk (content hash, fetch time), so a parser fix can re-parse history without re-fetching: `collect --reparse --source S` rebuilds the parsed rows of a source from the cache, network disabled, as new rows with a new `ingested_at` and the **original `known_at`** (the acceptance time, or for a snapshot the fetch time recorded on the raw pointer); the latest `ingested_at` per identity wins at read time (Definitions). Raw bytes are never sent anywhere else. The raw cache has a size budget, `collect.raw_size_budget_gb`: before each fetch the collector checks the cache size and **halts when it is at or above the budget**, non-zero, after its `collection_runs` row; the chunk in progress is not committed, earlier chunks stand, and the health card shows the fill. The first collector task measures one quarter of Form 4 XML and sets the default from that measurement.
6. **Pace and terms.** EDGAR requests use the existing raw client and User-Agent. The 10 requests per second limit (free-data terms 7a) is enforced **across processes**: the raw client's limiter (`edgar_raw._RateLimiter`) gains a lock file under `edgar.cache_dir` holding the wall-clock time (`time.time()`, comparable across processes; `time.monotonic` is not) of the last request. Each wait takes the OS file lock, reads the timestamp, computes its sleep, writes its own planned request time and **releases the lock before sleeping**, so the lock is held for microseconds and never across a request; acquisition has a timeout of `edgar.lock_timeout_seconds` after which the caller proceeds at the configured interval and logs it. `ingest`, `collect` and a manual backfill thereby share one budget, `edgar.requests_per_second`, which stays at its current value. The Federal Register is paced by `collect.federal_register_min_interval_seconds` with the same mechanism under `collect.raw_dir`. Each new source's terms (storage, redistribution, rate) are recorded in the free-data terms report **before its adapter merges**; the Federal Register line is the first task of the plan.
7. **Health and failure.** Each `collect` run writes a `collection_runs` row per source (started, finished, status, items fetched, items parsed, quarantined, `unstamped`, `unknown_cik`, `class_unresolved`, `amendment_unmatched`, skipped-for-stamp, last `known_at` seen, raw bytes added). Per-item parse failures are quarantined with the raw pointer and the error, counted, never dropped silently (the T11h rule, #263). The data-health page gets a collection card: per source, last success, items per day over the last 30 days **by the ET date of `known_at`** (so a backfill does not pile onto its ingestion day), **gap days** (a day with zero items whose trailing 30-day median of items per day is above zero; for EDGAR sources only SEC business days are gap candidates, for the Federal Register only federal business days, for news every day), quarantined count and raw-cache fill against the budget. `health --check` warns on a source whose last success is older than `collect.max_age_hours`. **Non-blocking:** a collector failure of any kind, lock, network, parse or budget, never blocks `ingest`, `paper run` or a backtest. The collector shares exactly two things with them, the EDGAR pacing lock (held for microseconds, req 6) and the one bounded read of the master (req 1); it holds no other lock they need, and no code path of theirs imports it (req 8). It needs no quiet interval.
8. **Boundaries**, each a case in the tree-wide AST test pattern of `tests/execution/test_boundaries.py`:
   - No module under `backtest/`, `execution/` or `dashboard/` (other than the health card's own module), and none of `ingest.py`, `backfill.py`, `universe.py` or `gap.py`, imports the `collect` or `events` package or names an event table in SQL; `cli.py` may import `collect` lazily inside the `collect` command function only.
   - Every `duckdb.connect` call under `collect/` and `events/` passes `read_only=True`, except in `collect/writer.py`, whose connect call's first argument is an attribute chain ending in `events.path`; every `ATTACH` string literal under `events/` and `dashboard/` contains `READ_ONLY`.
   - The LLM boundary of ADR 0008 point 1 is added as a case by the same task if no such test exists on main at the time (none does at drafting): no module under `src/` imports an LLM SDK.
9. **As-of API.** `events_as_of(conn, T, kinds, cik=None)` and `insider_transactions_as_of(conn, T, cik=None)` over an attached read-only connection: rows with `known_at ≤ T`, latest `ingested_at` per identity, resolved per Definitions (securities known at T, listings valid at the row's `known_at`), the fan-out count and the `unknown_cik` and `class_unresolved` flags on each returned row, and the event session E from the calendar. Pure over the connection; no caching across calls.

## Acceptance criteria (testable)

Stamps and revisions
- [ ] Given recorded submissions, Form 4 and Federal Register payloads, when parsed, then every row has a tz-aware UTC `known_at` equal to the submissions `acceptanceDateTime` (EDGAR) or the stamping rule (Federal Register), and `known_at ≤ ingested_at` holds for every row of every fixture.
- [ ] Given an accession present in the index but absent from the submissions payloads, no row is stored and `unstamped` counts 1; the index date is never used.
- [ ] Given a Form 4/A whose `dateOfOriginalSubmission` matches one Form 4 by the same issuer and reporter, `amends_accession` links it; matching none or two, the link is null and `amendment_unmatched` counts 1. As of a time between the two acceptances only the original is returned; as of after, both rows, each with its own `known_at`. An 8-K/A is returned beside its original, never in its place.
- [ ] Given a Federal Register document published on Good Friday (a federal business day and an NYSE holiday), its backfill `known_at` is the close of the following Monday's session. Given a backfill run at 10:00 ET on a publication date, that day's documents are skipped, counted, and stamped by the next run after the close.
- [ ] Given a document collected forward at fetch time t and later seen by a backfill, its stored `known_at` stays t.
- [ ] Given news collection (if enabled), then no news row has `known_at` earlier than its fetch time, each row carries `stamp_resolution_minutes`, and a payload with tone, sentiment, theme or entity fields stores none of them while the raw payload keeps them.
- [ ] Given a parser change and `collect --reparse`, the new rows are produced from the cache with the network disabled, keep the original `known_at`, carry a later `ingested_at`, and `events_as_of` returns the new row and not the old.

Collection mechanics
- [ ] Given an 8-K accession in a fixture daily index, the collector fetches that CIK's submissions payload, follows to an older page when the accession is not on the first, stores the payload under `collect.raw_dir`, and stores the `items` and acceptance from it; no primary document is requested (asserted on the recorded transport).
- [ ] Given a Form 4 for a CIK with one live listing at its `known_at`, the as-of API resolves it to that listing with no flag; with two listings and a title normalising to one `class_title`, to that class; with two listings and a title matching neither, to both with `class_unresolved`; given a CIK absent from `securities` at T, the row is returned with `unknown_cik`, and once a fixture adds the CIK's `securities` row it resolves without any change to the events file.
- [ ] Given a listing that became known (`snapshot_static`, fetched in 2019) after a 2016 event but before the read's T, the 2016 event resolves to it; read at a T before the listing was known, it is `unknown_cik`.
- [ ] Given a transaction dated Wednesday and accepted the following Monday 09:00 ET, the row is late; accepted Friday 21:59 ET, not late; accepted Friday 22:01 ET, late (deemed filed Monday). Given a `deemedExecutionDate` two days before `transactionDate`, the deadline counts from the deemed date. 2025-01-09 is not an SEC business day.
- [ ] Given a payload that fails to parse, then it is quarantined with its raw pointer and error, counted in `collection_runs`, and the rest of the chunk commits.
- [ ] Given a backfill interrupted mid-chunk and rerun, then no row is duplicated and none is missing; a completed chunk rerun writes no row. `collect --backfill --source news` exits non-zero before any request.
- [ ] Given a raw cache at the budget, the next run halts non-zero before its first fetch with its `collection_runs` row written, the chunk in progress is not committed, and earlier chunks stand; the Form 4 XML fetched by the collector lands under `collect.raw_dir` and is counted in the cache size.

Locks, pace and isolation
- [ ] Given a reader holding the events file for longer than `events.lock_retry_seconds`, `collect` exits non-zero with only its `collection_runs` row; given a reader that closes within the window, it completes.
- [ ] Given a running `collect`, a second `collect` exits non-zero at once naming the holder.
- [ ] Given two processes making EDGAR requests through the raw client at once, every pair of consecutive request times across both, read from the recorded transports, is at least 1/`edgar.requests_per_second` apart; the same for the Federal Register pacing. Given a lock file held past `edgar.lock_timeout_seconds`, the caller proceeds at the configured interval and logs the timeout.
- [ ] Given a main-store writer that releases within `store.lock_retry_seconds`, `collect` completes; given one that holds past it, `collect` exits non-zero with only its `collection_runs` row. Given `collect` mid-run between its master read and its fetches, an `ingest` chunk commit and a `paper run` write both complete without waiting on it.
- [ ] The boundary test fails on a fixture module under `collect/` (other than `writer.py`) that connects without `read_only=True`, on `writer.py` connecting to a path other than `events.path`, on an `ATTACH` literal under `events/` without `READ_ONLY`, and on a module under `backtest/`, `execution/`, `ingest.py`, `backfill.py`, `universe.py` or `gap.py` that imports `collect` or `events`.

Health and API
- [ ] The collection card shows a gap on a fixture SEC business day with zero 8-Ks between days with items, no gap on the weekend or on 2025-01-09, items per day counted by the ET date of `known_at` on a backfilled fixture, and the raw-cache fill; `health --check` warns on a source whose last success is older than `collect.max_age_hours`.
- [ ] Given a CIK whose ticker changed between two 8-Ks on the fixture, `events_as_of` resolves each event to the listing valid at its own `known_at`, and an 8-K accepted at 16:30 ET gets the next session as E, including across a holiday and a half-day.

## Out of scope

- The event-study engine, the registry migration and the study page (follow-up spec, below).
- 8-K primary documents and any filing text; 10-K and 10-Q text and diffs ("lazy prices"); company exposure maps. Each is a follow-up once v1 runs and the size is measured.
- Any LLM use: reading filings, classifying events, extracting exposures (Phase 5, ADR 0008).
- Any signal, hypothesis or order that uses an event. That goes through strategy-lab or backtest specs; news-derived signals need an ADR first (charter).
- Social media and search-volume collection (charter deferral; G5 graded search attention NOT SUPPORTED in large caps).
- Full news article text, intraday prices, paid data of any kind.
- Alerts from collected events. They need the Phase 4 alert machinery and its own requirement in the paper-trading spec.

## Data / interfaces

- **Files:** `events.path` (DuckDB, gitignored), raw cache under `collect.raw_dir` (submissions payloads, Form 4 XML, Federal Register JSON, news payloads), the single-instance lock file and the Federal Register pacing file under it, the EDGAR pacing lock file under `edgar.cache_dir`.
- **Event tables** (all with `known_at`, `ingested_at`, `source`, `provenance`, `raw_sha256`, `raw_fetched_at`): `filings_8k` (+ `filings_8k_items`), `insider_transactions`, `federal_register_documents`, `news_items` (only if enabled), `collection_runs`, `collection_quarantine`. Schema versioned on its own (`events_schema_version`, starting at 1); no change to the main store's schema or `TABLE_NAMES`.
- **Main store:** one short read-only read of `securities` per run for the CIK list; `securities` and `listings` read by the as-of API through the caller's connection. No write, no migration.
- **CLI:** `tradepartner collect [--source edgar_8k|edgar_form4|federal_register|news|all] [--backfill --since DATE] [--reparse] [--dry-run]`.
- **As-of API:** `events.asof.events_as_of(conn, T, kinds, cik=None)`, `insider_transactions_as_of(conn, T, cik=None)`.
- **Config keys:** `events.path`, `events.lock_retry_seconds`, `collect.interval_minutes`, `collect.sources`, `collect.raw_dir`, `collect.raw_size_budget_gb`, `collect.form4_backfill_start` (default 2016-01-01), `collect.federal_register_min_interval_seconds`, `collect.federal_closures` (list of dates), `collect.max_age_hours`, `edgar.lock_timeout_seconds`. `edgar.requests_per_second` is unchanged and becomes cross-process.
- **Calendar:** `tradepartner.calendar` gains `is_sec_business_day` and `next_sec_business_day` over pandas' `USFederalHolidayCalendar` plus `collect.federal_closures`. No new dependency.
- **Raw client:** `edgar_raw` gains the daily-index and quarterly `form.idx` fetch functions and the cross-process limiter; both used by ingest's existing paths unchanged.
- **Env vars:** none for EDGAR (existing User-Agent) and the Federal Register (no key). A news source may add one to `.env.example`.
- **Scheduling:** one more launchd job, `collect`, at `collect.interval_minutes`. It writes only the events file and needs no quiet interval (req 7). The runbook of T22 gets its plist.

## Risks & domain checks

- **Look-ahead through stamps.** The biggest risk is a stamp earlier than true public availability. The rules are: acceptance time for EDGAR, from the submissions payload only; fetch time for anything forward-collected; the late rule for Federal Register backfill, with the skip so no stamp lands in the future. Late stamps bias later studies toward "priced in", the safe direction. Executive orders are usually public at signing, days before Federal Register publication; the row keeps both dates so a study can say which it measures.
- **Look-ahead through resolution.** Reading securities as of T and listings as of the event is the same two-clock rule `facts_as_of` and the universe already follow; it means a backfilled 2016 event is unresolved until the master learns the listing, which is honest, and resolved afterwards without touching the events file.
- **Survivorship.** Events for companies that later delisted must resolve to their securities. CIK-first storage, the master's full CIK history including delisted names, and read-time resolution handle that. An unknown CIK is kept and counted, never dropped.
- **Store contention.** Solved by the separate file, the chunked commit, the lock-retry in both directions, the single-instance lock, and the bounded master read. The cost is a second file to back up.
- **Terms and rate.** EDGAR is covered by the existing research and the cross-process lock. The Federal Register (US government, public API) and any news source need a terms line before merge (req 6).
- **Disk growth.** Measured before it is assumed: one quarter of Form 4 XML and submissions payloads sets `collect.raw_size_budget_gb`; the collector halts at the budget rather than filling the disk. 8-K documents are deferred until measured.
- **Backfill duration.** Form 4 volume is large (hundreds of thousands of filings per year, an estimate to be replaced by the first task's measurement); at the shared EDGAR rate a full backfill runs for days and shares the budget with the nightly ingest. The owner starts it knowing the projection, and it resumes across reboots.
- **Order path / secrets / LLM.** None touched. `safety-reviewer` is not needed unless a news source adds a key. `quant-auditor` reviews the stamping rules, the resolution rule and the as-of API.

## Follow-up: event studies (a separate spec, after Phase 3 closes)

The first draft of this spec carried an event-study engine. Two reviews on PR #307 (spec-critic and the owner) found the same registry defects, and the engine is deferred to its own spec, to be written once Phase 3 has closed (T45b) and the strategy-lab's `family_rules` and `FAMILY_PARENTS` exist. That spec must satisfy, at minimum:

- **Migration.** `trials.hypothesis_id` is NOT NULL and `kind` has an inline CHECK, so a study trial needs a staging-table rebuild of `trials` in one transaction (the `corporate_actions` version-4 precedent), at the next free schema version at merge time, with a row-for-row copy test and the owner's store copied before the pull.
- **Counting.** A study's family lives on `studies.family`; `family_sharpes`, `family_holdout_spends`, `list_trials` and the trials page resolve the family through both `hypotheses` and `studies`; N and V come from separate row sets (V reads `in_sample` trials only); `TrialHandle` carries `study_id`; a test proves N moves when a study trial completes.
- **Families.** A study belongs to the family of the hypothesis it could inform (`earnings`, `insider`, never `momentum` for those two), each added to `HypothesisFamily` and `FAMILY_PARENTS` in code. Strategy-lab req 1 makes a sweep file a new family's first registration; the follow-up spec must **amend that requirement** so a study file may be a family's first registration, fixing its `family_rules` (holdout, `in_sample_start`, the forbidden-prefix keys, no holdout overlap with its parent chain) exactly as a sweep does; otherwise a study reads the family's existing rules and is refused when they disagree. The holdout is never read from live `Settings`.
- **Holdout.** Events whose widest window would touch the family's frozen holdout are **dropped and counted**, not a reason to refuse the run; windows before `in_sample_start` likewise. A study never spends a holdout.
- **Diagnostic studies** (fills timing, Form 25 pre-delisting paths) get their own literal, `diagnostic`: exempt from `FAMILY_PARENTS` and `family_rules` like `oracle`, but unlike `oracle` **allowed on the real store**, counted in no family's N, limited at registration to a closed list of non-event selection sources; the fills timing study belongs with T70 in the paper-trading spec.
- **Engine semantics.** Window [a, b] return defined as close(E+a−1) to close(E+b); the post-exit abnormal return and the missing-bar rule defined; one measurement clock (`data_cutoff` = the close of the last session of the widest window over the selected events) and one selection clock (each event's `known_at`); the look-ahead harness gains truncation of the events file; market-wide events excluded from v1 studies; standard errors clustered by event date with the overlap of long windows either clustered by month or stated as a limitation on the page; `run_study(store_path=...)` refuses a store without the fixture marker; quiet intervals apply.
