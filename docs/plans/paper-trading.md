# Plan: Paper trading and journal (Phase 4)

**Spec:** [specs/paper-trading.md](../specs/paper-trading.md)  ·  **Status:** Draft

## Approach (short)

Build the contracts first, then the pure parts, then the wrapper in three slices, then the run in four, then the surfaces. Broker types and [ADR 0007](../decisions/0007-clock-failures-halt-path.md)'s Task A (`SystemFaultError`, `ClockError`, the clock wrap) come first because every later task imports them; the config section and the journal schema next, so no later task touches `config.py` or `schema.py`; then the ledger, decision-state, risk, reconciliation, lot-ledger, alert and collection functions, each pure over journal rows and testable on synthetic inputs; the kill switch's derived state; the wrapper as core (clock pre-check, allowlist, halt path, replay), sells phase and buys phase; resume and outcomes; the tracking run as core (lock, staleness, collection, reconciliation, marks), plan-and-trade, forced exits and stop runs, and its no-look-ahead suite; the window lifecycle, the tracking comparison and the exit-criteria check; the CLI; the two pages; the docs the owner gates; and two owner tasks that bracket the paper months. The spec's wrapper (reqs 3 to 5) is deliberately several tasks, as its author asked: T60, T60b, T60c, T59 and T61 each carry a named part of it and its acceptance list is split among them by name.

**What may start while Phase 3 runs.** Phase 3 still has T42 (CLI), T45 and T45b (owner) open. Any task whose dependencies are all ticked on `origin/main` is claimable the moment this plan merges (teams.md): T46 (on T20), T47 (on T30), T49 (on T31) and T68 (docs) immediately; T46b, T48, T49b next; then the pure lanes (T50 to T59) in dependency order, the wrapper and the run after them. Only T67 waits for Phase 3's T42, T70b for Phase 2's T22, and T71 for T45b. Starting early is deliberate: the wrapper is tested against `FakeBroker` and the run against the fixture store, neither of which needs the owner's store or a paper account, and the owner's recording (T48b) gates only the Alpaca adapter (T48c) and everything downstream of it (T67 through the broker factory, T71).

**Owner gates, and where they sit.** These are recorded on #247 (2026-09-27, all fourteen recommendations accepted) and are sentences on the task lines, never in a `Depends on:` segment, because `scripts/team.py` reads only `T..` ids there. (1) [ADR 0010](../decisions/0010-phase-4-risk-rules.md), the risk-rules record (#254, merged as #256, Accepted), is the record T50, T54 and T60 to T60c cite: it names every `risk.*` key with its default, amends ADR 0007 point 6 to per-phase validation and fixes the attempt-numbered id derivation, so those tasks reference the keys by name and their tests pin what the ADR says. The recording task (T48b) appends the dated amendment the ADR asks for. (2) The ADR 0005/0006 amendment for `paper.tracking_rule = residual` and the six timing keys (#247 Q4, Q14) are one docs task, T70, that waits for Probe 3's report (#182, owner-run the week of 2026-09-28) and must merge before `paper start` (T71). (3) The dashboard-technology ADR (#247 Q1) is T68 and gates the operations page (T69). (4) The owner records paper responses with paper keys (T48b) before the Alpaca adapter (T48c). (5) The phase entry gate is the owner's `gap_signoff` row on H1's in-sample trial ([ADR 0009](../decisions/0009-price-vendor.md) point 3), written by T45b; T71 depends on T45b and `paper start` enforces the row.

Design choices, all from the spec: only `execution.wrapper.RiskGatedBroker` calls `submit` or `cancel` ([ADR 0003](../decisions/0003-data-adapters-local-first.md) rule 7; an AST test in T50 holds it, and `cli.py` gets its broker from `execution.brokers.build_broker`, so no module outside `execution/` imports an implementation); rejection is an allowlist, `SystemFaultError` first, everything else halts, and the halt writes the `kill_switch` row before anything else (ADR 0007); the switch state is derived from every earlier run's result, per window; every `orders` row precedes its submit and every attempt is sized for the remainder, so a crash cannot double an order; every limit is a named `risk.*` key ([ADR 0010](../decisions/0010-phase-4-risk-rules.md) point 1) read from the window's frozen values, never live `Settings`, checked before each phase's first submit (point 2) with the id derived from the journal (point 3); the plan is the engine's own `plan` function at close(T_i) under a `kind=tracking` trial, so every engine read sits under a trial id ([ADR 0005](../decisions/0005-objective-benchmark-stop-criteria.md) check 4) and the paper-equals-backtest oracle catches drift; no LLM anywhere, and the override form is the dashboard's only write and is never blocked ([ADR 0008](../decisions/0008-llm-role.md)); the journal is append-only in the DuckDB store, written through `store.journal` like `store.registry`; `known_at` is the shared clock's reading, broker instants live in their own columns.

**Schema version.** The store is at version 4 (#108). T49 takes **version 5** for `JOURNAL_TABLE_NAMES`, additive from 2, 3 or 4; if a fact-table change merges first and takes 5, T49 takes the next number and says so in its docstring, as T31 did when #83 took version 2. The `paper_window_stops.state` set includes `abandoned` from the start (#247 Q13).

**Dependencies.** None new: `alpaca-py` is already a runtime dependency, `osascript` is a subprocess and SMTP is the standard library, so no task touches `pyproject.toml` or `uv.lock`. The Phase 4 config keys are all added in T47 with the spec's defaults; the six timing keys are placeholders until T70 sets them from Probe 3, and `alpaca.quantity_decimals` and the two reconciliation tolerances are set by T48b.

Package layout: `src/tradepartner/errors.py`; `src/tradepartner/execution/{__init__,ids,ledger,plan,risk,reconcile,lots,alerts,collect,switch,wrapper,reconcile_run,resume,outcomes,run,window,report,check,ops,brokers}.py`; `src/tradepartner/adapters/{alpaca_trading_raw,alpaca_broker}.py`; `src/tradepartner/store/journal.py`; `src/tradepartner/dashboard/{ops_page,override_page}.py`; `docs/runbooks/scheduling.md`; tests under `tests/execution/`, `tests/adapters/`, `tests/store/`, `tests/dashboard/`, `tests/lookahead/test_paper_invariance.py`, with `tests/fixtures/alpaca/paper/` recorded by the owner.

## Rollback

The journal tables are additive: the fact and registry tables are never touched. To roll back T49 on a store that reached version 5: `paper stop --reason` first if a window is open (the run flattens the account through the wrapper; never by hand), unload the paper plist, then drop the `JOURNAL_TABLE_NAMES` tables and `DELETE FROM schema_version WHERE version = 5` by hand, because a reverted `init_schema` raises `SchemaVersionError` on a version it does not know (`store/schema.py`); write that command in the revert PR. The paper account keeps whatever the last `paper stop` or `abandon` left, listed in `residues_json`; the owner resets it at Alpaca if needed and records it on the issue. Config and the broker factory are removed by reverting T47 and T48c; the plist is unloaded with one command (runbook). No new dependency was added, so `pyproject.toml` is untouched.
