# Plan: Paper trading and journal (Phase 4)

**Spec:** [specs/paper-trading.md](../specs/paper-trading.md)  ·  **Status:** Draft

## Approach (short)

Build the contracts first, then the pure parts, then the wrapper in slices, then the run in slices, then the surfaces. [ADR 0007](../decisions/0007-clock-failures-halt-path.md)'s Task A (`SystemFaultError`, `ClockError`, the clock wrap) is the first task because it is the contract every later task imports; the broker types and the scripted fake next; the config section and the journal schema, so no build task after them touches `config.py` or `schema.py`; then the ledger, decision-state, risk, reconciliation, lot-ledger, alert and collection functions, each pure over journal rows and testable on synthetic inputs; the kill switch's derived state and the run lock; the wrapper as core (clock pre-check, allowlist, halt path, replay), phase machinery, sells phase, buys phase, and re-attempts; reconciliation-with-explanations and resume; outcomes; the tracking run as core, marks-and-lapses, plan step, trade step, forced exits and stop runs, then its no-look-ahead suite and its crash-and-resume suite; the window lifecycle in two tasks, the tracking comparison in two, the exit-criteria check; the CLI; the two pages; the docs the owner gates; and two owner tasks that bracket the paper months. The spec's wrapper (reqs 3 to 5) is deliberately many tasks, as its author asked: T59 to T61b each carry a named part of it, and its acceptance list is split among them by name.

**What may start while Phase 3 runs.** Phase 3 still has T42 (CLI), T45 and T45b (owner) open. Any task whose dependencies are all ticked on `origin/main` is claimable the moment this plan merges (teams.md): T46 (on T20), T47 (on T30), T49 (on T31) and T68 (docs) immediately; T46b, T48, T49b next; then the pure lanes in dependency order, the wrapper and the run after them. Only T67 waits for Phase 3's T42 and T71 for T45b (T70b's wait on Phase 2's T22 was removed on 2026-09-30, #388). Starting early is deliberate: the wrapper is tested against `FakeBroker` and the run against the fixture store, neither of which needs the owner's store or a paper account, and the owner's recording (T48b) gates only the Alpaca adapter (T48c) and what is built on the factory or runs against the account (T67, T71); the buys sizing's cash read is a declared stub on T60b (spec req 2's cash clause; #388).

Design choices, all from the spec: only `execution.wrapper.RiskGatedBroker` calls `submit` or `cancel` ([ADR 0003](../decisions/0003-data-adapters-local-first.md) rule 7; an AST test in T50 holds it, and `cli.py` gets its broker from `execution.brokers.build_broker`, production-only, so no module outside `execution/` imports an implementation and no setting can swap one in); rejection is an allowlist, `SystemFaultError` first, everything else halts, and the halt writes the `kill_switch` row before anything else (ADR 0007); the switch state is derived from every earlier run's result, per window; every `orders` row precedes its submit and every attempt is sized for the remainder, so a crash cannot double an order; every limit is a named `risk.*` key ([ADR 0010](../decisions/0010-phase-4-risk-rules.md) point 1) read from the window's frozen values, never live `Settings`, checked before each phase's first submit (point 2) with the id derived from the journal (point 3), while the run-time `paper.*` and `alpaca.*` keys are passed as `settings`, never through `frozen`; the plan is the engine's own `plan` function at close(T_i) under a `kind=tracking` trial, so every engine read sits under a trial id ([ADR 0005](../decisions/0005-objective-benchmark-stop-criteria.md) check 4) and the paper-equals-backtest oracle catches drift; no LLM anywhere, and the override form is the dashboard's only write and is never blocked ([ADR 0008](../decisions/0008-llm-role.md)); the journal is append-only in the DuckDB store, written through `store.journal` like `store.registry`; `known_at` is the shared clock's reading, broker instants live in their own columns.

**Schema version.** The store is at version 4 (#108). T49 takes **version 5** for `JOURNAL_TABLE_NAMES`, additive from 2, 3 or 4; if a fact-table change merges first and takes 5, T49 takes the next number and says so in its docstring, as T31 did when #83 took version 2. `paper_window_stops.state` is `{requested, closed, abandoned}` from the start (#247 Q13; T64b amends the spec's Data section to match).

**Dependencies and config.** No new dependency: `alpaca-py` is already a runtime dependency, `osascript` is a subprocess and SMTP is the standard library, so no task touches `pyproject.toml` or `uv.lock`. The Phase 4 config keys are all added in T47 with the spec's defaults. ## Rollback

The journal tables are additive: the fact and registry tables are never touched. To roll back T49 on a store that reached version 5: `paper stop --reason` first if a window is open (the run flattens the account through the wrapper; never by hand), unload the paper plist, then drop the `JOURNAL_TABLE_NAMES` tables and `DELETE FROM schema_version WHERE version = 5` by hand, because a reverted `init_schema` raises `SchemaVersionError` on a version it does not know (`store/schema.py`); write that command in the revert PR, and the copy the owner took before the first pull of T49 is the fallback. The paper account keeps whatever the last `paper stop` or `abandon` left, listed in `residues_json`; the owner resets it at Alpaca if needed and records it on the issue. Config and the broker factory are removed by reverting T47 and T48c; the plist is unloaded with one command (runbook). No new dependency was added, so `pyproject.toml` is untouched.
