# Plan: Strategy interface (strategies as registered objects)

**Spec:** none; the governing document is [ADR 0014](../decisions/0014-strategies-as-registered-objects.md) (size M, development-process "Right-size the ceremony": an ADR for the hard-to-reverse part, the schema CHECK and the paper path, and this plan for the build order)  ·  **Status:** Approved (owner, by merging PR #1075; the six owner decisions of 2026-10-06 are in the ADR)  ·  **Issue:** #1074  ·  **Related plans:** [backtest](backtest.md) (T85 to T85f; T85e's line is amended by this PR), [strategy-lab](strategy-lab.md) (T97, T98, T98b, T100)

## Approach (short)

**Spike first, then planned; size M, not L.** The planner spike of 2026-10-06 (ADR 0014, Context) put a trivial second strategy through `engine.run`, `run_hypothesis`, the T40 invariance suites and the paper `plan_rebalance` step on the fixture store: 13 tests, +31/−9 lines in four source files, no schema change, the engine core untouched. It stopped at exactly one boundary, the exclusion reason, which lives in `Plan`, a `NOT NULL` count column and the paper `signals.reason` CHECK. Everything else it found was bookkeeping (nine lines of family tables) or silent (the missing dispatch, the momentum fallbacks, the mandatory MTUM, the unread cadence). So this plan is **four build tasks**, each the smallest change that fixes one finding, plus one amendment to an existing task: the dispatch seam is **T85e's job**, not a new task, because T85e is the first PR that has to dispatch at all and the spike showed that a `signal_for(family)` inside the engine without the family threaded in from `run_hypothesis` and `plan_rebalance` would be a seam that dispatches nothing (every caller still momentum: `cli.py:823`, `execution/run.py:1824`, `execution/report.py:891`). Making T85e the seam keeps one seam; a second task that rewrote T85e's dispatch would leave two for a while and edit `engine.py` twice. The amendment (recorded in the backtest plan's "Amendment 2026-10-06 (#1074)" note) adds to T85e: the family parameter on `engine.run` and `engine.plan`, passed from `run_hypothesis` and `_plan_at`; `signal_for` in a new leaf module `backtest/strategies.py` rather than inside `engine.py`; one `Plan.counts` mapping in place of six named plan fields (T85d's six `RebalanceRow` columns filled from it by name); and owner decision 2's `PAPER_FAMILIES` gate.

**Order, from the spike.** (1) The seam (T85e, after T98 and T98b as the backtest plan already orders it, so the family dispatch is written once over the cadence-aware signal call). (2) Beside each other, on disjoint files: the generic exclusions and counts (T127, the one schema boundary, after T85d so it migrates the six columns rather than racing them, owner decision 6) and the family registry with the fallbacks removed (T128). (3) Per-family benchmarks (T129) after T128 (the benchmark is a registry attribute) and after the lab's T97 (the one period-key rename edits the same `metrics.py` and `results.py` lines; two renames in flight is what the lab spec forbids). (4) The proof: B4 `combined` through the registry (T130), which by ADR 0014 point 6 must touch none of `execution/`, `store/`, `engine.py`, `run.py`, `results.py` or `hypothesis.py`; the PR body shows the diff's file list as its evidence.

**The latent cadence bug** (spike: `schedule.rebalance_cadence` and `schedule.signal_anchor` frozen and hashed but read nowhere; a `week_end` registration ran monthly and wrote `ok`) is the strategy-lab plan's T98 (engine, holdout and run path at cadence) and T100 (`paper start` refuses non-monthly). This plan does not fix it; every task here that touches `engine.run` sits after T98 by dependency (T85e → T127), so the seam and the cadence loop are never edited at once.

**Identity pins in every task.** `H1_FINGERPRINT` and `TWIN_FINGERPRINT` (`tests/backtest/test_frozen_defaults.py:182-186`) are asserted unchanged by T128 and T130 directly and by T127 and T129 through the existing suites they run; the H1 fixture's metric keys and values are asserted unchanged by T129; the momentum fixture plan's `signals` rows are asserted byte-identical by T127. A task that moves any of these stops and asks.

**Line numbers** below are at `d08d116` (2026-10-06) and are re-verified by the implementer at claim time; T85c, T85d, T98 and T77b are in build and move them.

**Plan shape numbers** (development-process.md, "Plan shape"; `uv run python scripts/team.py graph --ref ''` on this branch, 2026-10-06). ## Rollback

Every task but T127 is code only: tables of values, signatures and pins, reverted by reverting the PR. T127's schema version is additive (a new table; a CHECK that only widens; `signals` rebuilt with every row copied) and cannot be un-shipped, but a store at that version serves every earlier read and write; reverting T127's code while keeping the version leaves the counts table unread and the widened CHECK harmless. `PAPER_FAMILIES` keeps paper on momentum throughout, so no paper window is planned by a strategy this plan adds.
