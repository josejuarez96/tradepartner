# Plan: Strategy lab (sweeps as families of trials, cadence as a hypothesis parameter)

**Spec:** [specs/strategy-lab.md](../specs/strategy-lab.md) (Accepted by the owner on 2026-10-05, #931; open questions 2, 8 and 11 decided on #809, the rest standing defaults)  ·  **Status:** Draft  ·  **Issue:** #933

## Approach (short)

Docs first, pure modules next, the store and the one driver after, the surfaces last. Two docs tasks record what the spec says other documents must say (the Phase 3 and paper spec amendment notes, the roadmap line, the sweep template: T91; ADR 0012 superseding ADR 0006's Cadence section and the charter line: T92). Then the pure parts over explicit inputs, each its own file: config keys and the code tables (T93), the cadence schedule and calendar helpers (T94), the signal anchor (T95), the frozen-key defaults and the fingerprint (T96), the quiet intervals (T106), the sweep-file parser and grid (T102), the lab DDL as functions on a fixture (T101), the price read's session-range filter the daily cadence needs (T99). Then the store-facing parts: the period-key rename with the deflated Sharpe in annual units and schema version P (T97), the engine, holdout and run path at cadence (T98) with the parametrised suites (T98b), the lab registry API (T103), registration with every refusal (T104), `run_many` and the `summary` detail level (T105), the sweep runner (T107), the pure report (T108), promotion and retirement (T109), the holdout spend rules (T110). Then the surfaces: the `sweep` and `lab` CLI (T111), the trials-page families card and sweeps table (T112), the agent and runbook docs (T115), and `paper start`'s cadence refusal (T100). The lab migration (T113) is the one task sequenced by the spec's req 1, after T45b; the owner's measurement run and first sweep (T114) close the plan. The spec's design stands unchanged; the plan-level choices are the four below.

**1. One rename PR, atomic against T45b.** The spec's open question 2 (b) requires the metrics-key rename (req 8) to land wholly before H1's first real-store trial or wholly after it, never across it. **T45 is ticked (#328) and T45b has not run** (`team.py status` on 2026-10-05: ready, unclaimed, owner; STATUS: it follows the backfill rerun and `health --check`), so the "before T45b's real-store run" reading applies today and T97 is the first code task the owner should see merged. T97 is therefore **one PR** that renames the keys, converts V and SR* to annual units, writes `sharpe_unit`, and ships schema version P with the row-inserting migration: the writer, the readers (`family_sharpes`, the backtest page) and the migration cannot be split without a period where new trials are written in one vocabulary and read in another, which the spec forbids ("nothing reads them afterwards"). That PR is about 550 lines, two fifths of it renames inside `tests/backtest/test_metrics.py`; the size is stated here as the reason the 400-line guide is exceeded once. Because it is one PR, T45b can never straddle the rename: if the owner runs T45b before T97 merges, the rename lands wholly after it and the migration inserts H1's trial's `*_period` rows (its DSR unchanged, acceptance "Migration identity"), which the rule equally allows. Nothing else in this plan is ordered against T45b except the migration (choice 3).

**2. The lab DDL lands as functions before the version bump, so every lab task but the migration can merge before T45b.** The owner's store migrates at its first writing job after any `CURRENT_SCHEMA_VERSION` bump merges, so a version that creates `pre_lab_hypotheses` and `family_rules` before H1 is registered there would mark nothing and leave H1 outside the pre-lab set (spec, open question 2, the migration's ordering). T101 therefore adds `store/lab_schema.py` with `apply_lab_schema(conn)` (the seven lab tables, `store_markers`, the two `CHECK`-enum rebuilds) and a `lab_store` test fixture that applies it on a fixture store, with **no version bump**; every lab task is built and tested on that fixture, and `sweep register` on a store without the tables raises `LabNotInitialised` (exit 2) until T113 bumps the version and runs the same function plus the population of `pre_lab_hypotheses`, `hypothesis_fingerprints` and `family_rules`. The `trials` and `trial_results` columns every trial writes (`detail_level`, `data_vintage`, `code_tree_sha256`, `sharpe_unit`) travel with T97's version P instead, because `results.write_results` writes them on every trial from T97 on.

**3. Schema versions.** `CURRENT_SCHEMA_VERSION` is 11 on `main` today. Two lab versions, both additive from whatever is current at merge time: **P** (T97: the four columns, the `*_period`, `n_periods`, `periods_per_year`, `turnover_annual` and `sharpe_annual_excess_spy` rows inserted for every existing trial, old rows kept) and **L** (T113: `apply_lab_schema` plus the three population steps). The research registry's T80 and the backtest spec's T85d also take "the next free version at merge time"; whichever lands later takes the number after, and none edits another's DDL. Each adds the previous version to `_check_read_only`'s accepted list so a read-only open of an unmigrated store keeps serving every non-lab read. **When the owner's store migrates:** P at the first writing job after T97 merges (an `ingest`, `backfill`, `backtest` or the paper window's run), additive and harmless; L at the first writing job after T113 merges, which `Depends on: T45b` keeps after H1's registration and run. The backtest spec's decision 13 (B3-2 (a), owner, 2026-10-03) also orders T85f (B3 registered and run pre-lab) before T113; T85f is not yet in a plan file, so that order is stated on T113's line and is **not enforced by `team.py`** (open question 1 below).

**4. Files, not steps (plan-shape rule 1).** The spec's Interfaces section names `backtest/lab.py` for the runner, the report, promotion, retirement and the quiet-interval arithmetic, and `store/registry.py` for the lab's registry functions. One file for all of that would be a six-task chain on one module, so the plan splits by file: `backtest/quiet.py` (pure, T106), `backtest/sweep_report.py` (pure over rows, T108), `backtest/promotion.py` (T109), `backtest/lab.py` (the runner only, T107), `store/lab_registry.py` (T103, new; `family_sharpes` stays in `registry.py` where T97 edits it) and `store/lab_schema.py` (T101). Public names are the spec's. One key the spec implies but does not list, `lab.seconds_per_variant_default` (per cadence; the "plan's measured figure per cadence when none exists" of req 2, as config rather than a code constant per the code standards), is added by T93 with placeholders and set from T114's measurements by a size-S issue (rule 4, the stub declared on T106's line).
