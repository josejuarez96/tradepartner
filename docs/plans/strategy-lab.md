**1. One rename PR, before T45b.** The spec's open question 2 (b), decided by the owner on #809, says the metrics-key rename (req 8) **lands before H1's first real-store trial**. **T45 is ticked (#328) and T45b has not run** (`team.py status` on 2026-10-05: ready, unclaimed, owner; STATUS: it follows the backfill rerun and `health --check`), so the decision applies as written: T97 is the first code task the owner should see merged, and owner item 2 asks him to wait for it before running T45b. T97 is **one PR** that renames the keys, converts V and SR* to annual units, writes `sharpe_unit`, and ships schema version P with the row-inserting migration: the writer, the readers (`family_sharpes`, the backtest page) and the migration cannot be split without a period where new trials are written in one vocabulary and read in another, which the spec forbids ("nothing reads them afterwards"). That PR is about 550 lines, two fifths of it renames inside `tests/backtest/test_metrics.py`; the size is stated here as the reason the 400-line guide is exceeded once. **2. The lab DDL lands as functions before the version bump, so every lab task but the migration can merge before T45b, and a store without the lab tables keeps the Phase 3 rules.** The owner's store migrates at its first writing job after any `CURRENT_SCHEMA_VERSION` bump merges, so a version that creates `pre_lab_hypotheses` and `family_rules` before H1 is registered there would mark nothing and leave H1 outside the pre-lab set (spec, open question 2, the migration's ordering). T101 therefore adds `store/lab_schema.py` with `apply_lab_schema(conn)` (the seven lab tables, the two `CHECK`-enum rebuilds), `is_lab_initialised(conn)` **by table presence**, and a `lab_store` test fixture that applies it on a fixture store, with **no version bump**. Every lab task is built and tested on that fixture. **The fallback is a rule every lab-aware task carries and tests on a plain `fixture_store`:** when `is_lab_initialised` is false, `hypothesis register`, `holdout.decide` and `backtest` behave exactly as Phase 3 (T104c, T110), and `sweep register`, `sweep run`, `sweep report`, `lab status` and the page's lab card refuse or say "lab not initialised" (`LabNotInitialised`, exit 2; T104, T107, T108, T111, T112). The owner's version-P store therefore runs H1 under the Phase 3 rules until T113 bumps the version, runs the same DDL function and populates `pre_lab_hypotheses`, `hypothesis_fingerprints` and `family_rules`. The `store_markers` table is the one lab table a plain fixture store does have: `tests/conftest.py` creates it and writes the `fixture` row on every fixture store from T101 on (the real store never gets the row; the table arrives there with L), so `run_hypothesis(store_path=...)`'s refusal (T110) and `run_sweep`'s (T107) read `has_fixture_marker`, which is false on a store without the table or the row, and every existing fixture-store test keeps passing. The `trials` and `trial_results` columns every trial writes (`detail_level`, `data_vintage`, `code_tree_sha256`, `sharpe_unit`) travel with T97's version P, because `results.write_results` writes them on every trial from T97 on.
