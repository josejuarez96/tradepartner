## Approach (short)

**Validated first, then planned.** A read-only sample test against the real vendor ran before this plan (two runs of 308 calls at the pinned `jev-1.13.0`, $0.036; the amendment's evidence lines E1 to E14; #1016 commits the summaries). It settled the spec's load-bearing assumptions: the population is about 11,150 listing ends, not 5,000 (E1); the whole pilot costs about $1 at list price against a $40 ceiling (E2, C1); the Form 25's own notice exhibit resolves 82% of listing ends and the nearest 8-K lifts coverage to 95% (E3, E4), so the passage is one notice plus at most one 8-K, the 8-K read first where one exists and the notice alone otherwise (C2, the rule the evidence scored); answers are stable on repeat and under a reversed option order (E6), so the drift probe is ADR 0013 point 5's at its smallest, twenty fixed packets re-sent before each batch as a `robustness` run beside the model-id stop (C5); the probabilities sit at 1.0, so calibration stays a reported number and nothing more (E7, C6); and the final answer was right on 15 of 16 cases an agent labelled blind (E10). The build is therefore **ten build tasks of size M in total**, not the body's fifteen: the boundary tests first and alone (T118, ADR 0013 point 3 and req 1); then the config, secret, client and the one scripted double (T119) and the option set with its crosswalk (T121) beside each other; then, beside each other, the EDGAR corpus fetch outside `tradepartner.research` (T120), the packets and the scoring (T121b) and the frame build that computes the rule answer at a recorded `t` (T122); then the job (T123) and the review logic (T123b) beside each other, then the review page on the logic (T123c); then the CLI and the three experiment files, the terms line, the charter sentence and the roadmap item (T124, class B). The owner's items are two tasks at the edge: the keys and the seven recordings (T125), then the real corpus, frame, gold, pilot and first batch (T126).

**What the pilot measures that the spike could not.** The spike never touched the owner's store. The pilot's actual output is the **disagreement rate between the model's label and the master's rule answer** (the crosswalk of spec req 5) over the whole population, and the shortlist it yields: that needs the rule answer computed from the owner's store at a fixed `t` (T122's frame build, run by the owner after T45b's real-store run per ADR 0013 point 9's roadmap line), then one `full` batch (T126). The gold score (150 blind labels, the Wilson bars of owner decisions 3 and 5) stays the gate before that batch (ADR 0013 point 5); E10 suggests it will pass but is sixteen items chosen for disagreement and labelled by an agent, not a score. The spike's 150 sampled accessions are excluded from the gold draw so that "before any model output exists" holds for every scored item (C10, owner question 7).

**Numbers that matter for the build.** The 4-characters-per-token estimate ran 1.5 to 1.7× low (E9): `chars_per_token` defaults to 2.5 and the pre-call estimate is replaced by the returned usage per record, so the mid-batch spend stop (C4) does not fire late. One whole-population batch under C2 is about 7,250 B calls (the 65% with an 8-K) plus about 4,300 A calls (the rest, and B's `unresolved`), about 11,500 calls, about 1.6 hours at `requests_per_second = 2.0` (E8: p50 latency 175 ms, so the pace is ours, not the vendor's), about $0.85; the corpus fetch is about 35,000 EDGAR requests, about an hour at the configured `edgar.requests_per_second` (default 9; the spike paced at 4, about 2.5 hours), once, then cached (E13, C11). Nothing here schedules anything (ADR 0013 point 8).

**Boundary by construction, then by test.** `tradepartner.corpus` imports the EDGAR adapter and nothing from `tradepartner.research`; `tradepartner.research.labeling` reads the corpus file by path and the runtime store through read-only readers only, in `frame.py` alone; `tradepartner.research.models` is the one module that names the vendor host and the key and is imported only by `job.py`; the review page (C10) is a Streamlit script inside `research/labeling/`, launched by `cli` and bound to localhost, drawing only what `review.py` hands it and writing only through it, so the dashboard still imports nothing from `tradepartner.research` and nothing writes the gold working file but `gold.py` (T131, #1177) or the review file but `review.py`.
