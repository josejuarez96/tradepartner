# Plan: Known-answer index validation

**Spec:** [specs/index-validation.md](../specs/index-validation.md)  ·  **Status:** Draft  ·  **Issue:** #1598

## Approach (short)

Sliced by file (development-process.md, "Plan shape", rule 1): one config task, one store task (the four tables and their writers in a new leaf `store/validation.py`, not in `registry.py`), one pure task (`backtest/validation.py`, every number and the report text computed over frames handed in), then the one driver that composes them (`backtest/validation_run.py`, the reads and the record), then its look-ahead and engine-parity suite as its own task (T184g, so neither PR passes ~400 lines), then the CLI, the runbook and the owner's first run. The driver never calls `engine.run`, never takes a `TrialHandle`, and reads through the as-of API with one short-lived read-only connection per step, exactly as `StoreProvider` does; `StoreProvider`, `engine.py`, `registry.py`'s trial writers and the frozen key set are not edited, so H1's, the TWIN's and COMBINED's fingerprints and the paper path stay byte-identical (the existing pins prove it on every PR). The owner's decisions on #1598 (full window with the guard; never a trial) are the spec's reqs 4 and 5; the pass bars are his after the first report (spec open question 6), so T184f records them or leaves them unset.

**Validate before building:** the orchestrator's read-only feasibility notes on #1598 (equal weight only in `portfolio.py`, no no-signal selector, the engine's handle requirement, RSP not stored, `market_cap` from total shares) are the spike; the design routes around each rather than widening the engine. No further spike precedes T184b to T184d.

**Numbers** (`team.py graph` before this amendment: the longest open chain is T114 → T160 → T161 → T162 → T163 → T163b, six, with 19 tasks at depth 1 and 8 at depth 2; after it the longest chain is unchanged, this plan's longest is five, {T184, T184b, T184c} → T184d → T184g → T184e → T184f, its depth-1 tasks are T184, T184b and T184c (22 at depth 1 overall), its depth-2 task is T184d (9 overall), and no task of it enters another plan's chain). Files shared with open tasks of other plans: `src/tradepartner/config.py` (T147, T163b, T170b, T170d, T171c, T171d, T172e, T181, T183: each adds its own keys; T184 adds the `validation` section last in `Settings`, after `health`, and whichever lands later merges main first), `src/tradepartner/store/schema.py` (T146, T172b, T183: each its own tables; T184b takes the next free schema version at landing and says so in its docstring), `src/tradepartner/cli.py` (T171c, T172e: T184e adds one `add_typer` line; the commands live in the new `cli_validation.py`), `.env.example` (T147, T163b: disjoint variables). Inside this plan, `src/tradepartner/config.py` and `tests/test_config.py` are named by T184 and by T184f (only if the owner sets the bars; disjoint keys, and T184f lands long after T184), and `backtest/validation_run.py` by T184d and T184g (T184g adds tests only and edits the driver only if a seeded case fails); otherwise no file is named by two tasks except the fragments and this plan's ticks.

**Schema version.** The store is at version 24. T184b takes **version 25** for `VALIDATION_TABLE_NAMES`, additive; if another migration merges first and takes 25, T184b takes the next number and says so in its docstring (the paper plan's T132 precedent).

**Dependencies.** None new: polars, duckdb, typer and the Alpaca price source are already runtime dependencies. No task touches `pyproject.toml` or `uv.lock`.

## Rollback

Additive tables only: drop the four `VALIDATION_TABLE_NAMES` tables and `DELETE FROM schema_version WHERE version = 25` (or the number T184b took) by hand, written in the revert PR, because a reverted `init_schema` raises `SchemaVersionError` above its own version. The `validation` config section, `cli_validation.py` and the two `backtest/validation*.py` modules are removed by reverting their PRs; nothing else reads them. The reference series is a copy of vendor data and is refetched by one command. No scheduled job is added.
