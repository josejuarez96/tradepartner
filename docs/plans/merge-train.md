# Plan: Merge train

**Spec:** [specs/merge-train.md](../specs/merge-train.md)  ·  **Status:** Draft

## Approach (short)

One script, `scripts/merge_train.py`, in the shape of `scripts/ready_pr.py`: pure functions over data first (records, eligibility, order, run classification, bisect arithmetic, the mergeable prefix, comment text), then a `Runner` protocol with a `ShellRunner` over `git` and `gh` and the `build`, `merge`, `status` and `prune` commands, so every rule in the spec is unit-tested on a fake runner and the one real run is the owner's. The CI change is one line in the workflow (`push.branches` gains `train/**`), independent of the script. The process wiring (review prefixes, the `ask` rule) and the docs (git-workflow, teams, development-process, CLAUDE.md rule 1, the ruleset file) are their own tasks because they touch files no other task here names. The owner's task, activating the ruleset and running the first real train, gates nothing: it is the edge.

No LLM anywhere in the path, no new dependency (`git`, `gh`, the standard library), no config key (constants with flags, as `ready_pr.py`), nothing under `src/`.

**Plan shape numbers** (development-process.md, "Plan shape"; from `uv run python scripts/team.py graph --ref <this branch>` on 2026-10-01, this plan's tasks only): longest open chain **4** PRs (T72 → T72b → T75 → T75b, the last the owner's); depth 1: T72, T73; depth 2: T72b; depth 3: T74, T75; depth 4: T75b (owner). Files named by more than one open task: `scripts/merge_train.py` and `tests/test_merge_train.py`, by T72 and T72b only, the declared chain below. No file here is named by an open task of another plan (checked against `docs/plans/{data-foundation,backtest,paper-trading}.md` on `main` 1327d96: none names `ci.yml`, `ready_pr.py`, `settings.json` or the ways-of-working docs).

**Lanes.** `scripts/merge_train.py` (with `tests/test_merge_train.py`) is edited by exactly two tasks in sequence, T72 then T72b: the pure core and the driver that composes it (plan-shape rule 1, a declared chain of two). Every other task has its own files. T73 may run beside T72. T74 and T75 wait for T72b (T75 also for T73) because they describe or gate the real commands. T75 also waits for the owner's answer to the spec's Open question 1 (the ruleset variant), which `team.py` does not enforce; it may land with variant (a) and a note if the answer is still pending.

**Owner items, ordered by what they unblock:** (1) the answers to Open questions 1 to 3 of the spec before T75 writes the docs (1 shapes the ruleset file, 2 the CLAUDE.md wording, 3 the default order in T72, which ships with ascending PR number unless told otherwise); (2) T75b: the `gh api` POST of the ruleset, the `train/smoke` push (AC14), the first real batch (AC15, AC16).

## Rollback

Everything is additive to the process and nothing touches `src/` or the store. To undo: revert T73 (the `train/**` trigger) and T75 (docs, ruleset file) in one PR; delete any `train/*` branches (`merge_train.py prune`, or by hand); deactivate the ruleset (`gh api -X DELETE repos/josejuarez96/tradepartner/rulesets/<id>`, owner only: agents may not run `gh api -X DELETE`); the local records under `data/merge_train/` are gitignored and can be deleted. `ready_pr.py` keeps working as before throughout, so PRs can be merged by hand at any point.
