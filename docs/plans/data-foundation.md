# Plan: Data foundation (Phase 2)

**Spec:** [specs/data-foundation.md](../specs/data-foundation.md)  ·  **Status:** Draft

## Approach (short)

Build inside-out: config and calendar; the store and its as-of API with the truncation-invariance harness; the fixture universe; fixture adapters and the security master; the no-look-ahead suite; then the real adapters against fixtures the **owner records once**; then universe, gap, ingest, health, CLI, page, and close-out. CI never needs network or secrets.

Design choices: DuckDB file, raw OHLCV, read-time adjustment ([ADR 0003](../decisions/0003-data-adapters-local-first.md), [0004](../decisions/0004-tooling-adopt-avoid.md)); universe rules as config with a guarded SIC setting ([ADR 0006](../decisions/0006-universe-and-cadence.md)); **Streamlit** for the dashboard (spec req 11; Marimo reconsidered at the Phase 2 retro); **Typer** for the CLI. Fetch and parse are separate in every real adapter, so parsers are tested on recorded raw JSON and no HTTP-mocking library is needed.

**All runtime dependencies are added in T1** so no two tasks touch `pyproject.toml`/`uv.lock`: `pydantic`, `pydantic-settings`, `exchange_calendars`, `typer`, `duckdb`, `pyarrow`, `polars`, `edgartools` (exact pin), `alpaca-py` (exact pin), `streamlit`. Per-module `ignore_missing_imports` overrides for libraries without stubs are set in T1. `bt` and metrics libraries are Phase 3.

Package layout: `src/tradepartner/{config.py, calendar.py, store/{schema,db,asof,master,classify}.py, adapters/{__init__,prices,filings,broker,fixture_prices,fixture_filings,fake_broker,alpaca_prices,edgar}.py, universe.py, gap.py, health.py, ingest.py, cli.py, dashboard/health_page.py}`; `tests/conftest.py` owns the fixture-store loader.

## Verification

End to end, on a clean checkout:
1. `uv run pytest` green with no `.env`, including the truncation-invariance tests and the broken-adapter negative tests.
2. With the owner's `.env`: `uv run tradepartner ingest --source all --backfill --since <date from T2>` completes (runtime recorded); then `uv run tradepartner ingest --source alpaca` after the settle delay shows `rows_added = 0` on the second run (EDGAR may add rows as filings arrive; the run row explains any delta).
3. `uv run tradepartner health --check` exits 0; its numbers match a direct DuckDB query pasted alongside.
4. `uv run tradepartner dashboard` shows the same on the data-health page (screenshot).
5. Five consecutive scheduled `ok` runs (T18 evidence).
6. `data-validator` report attached to the T19 PR.

## Rollback

The store is a single file: delete it and re-run `ingest --backfill` to rebuild from sources (fixtures are checked in; EDGAR and Alpaca are re-fetchable). The scheduled job is a launchd plist the owner installs by hand and unloads with one command (runbook). No migrations touch anything outside the store file. Dependencies are removed by reverting T1.
