# Plan: Research-experiment registry

**Spec:** [specs/research-registry.md](../specs/research-registry.md) (every open question decided on #810, PR #877)  ·  **Status:** Draft  ·  **Issue:** #901

## Approach (short)

Store first, then the API that is the only way to write it, then the file parser, then the surfaces: the schema and additive migration (T80); the append-only `store/research.py` with the two `RunHandle` constructors and the one dataset reader (T81); the pure experiment-file parser with its template and fixtures (T82); the `experiment` and `dataset` CLI groups (T83); the one edit to the backtest's N and the backtest spec's req 8 amendment (T83b); and the read-only research view (T83c). The spec's design choices stand unchanged: the registry lives in the runtime store so N is one query (Q1), research data live content-addressed under `data/research/` and are reached only through `load_dataset` (Q2, req 3), every evaluated configuration of a return-touching run adds one to N (Q3), sealed means sealed with no flag (Q4), there is no import path of any kind (Q5, req 12 dropped), code computes `verdict` from the interval (Q6), and a closed trial's `trial_equity` export is an ordinary dataset version (Q7 (d)). ADR 0008 holds by construction: nothing here calls a model, and req 13's isolation test is T83's `tests/test_no_forbidden_imports.py` scan.

**Schema version.** The spec's req 1 wrote "whichever plan lands first takes 9 and the other takes 10" when `CURRENT_SCHEMA_VERSION` was 8; on `main` today it is 10 (the Phase 4 journal and price-quality migrations landed since). T80 takes **the next free version at merge time**, additive, and the strategy-lab plan (not written) takes the one after whichever lands later, as req 1 intends; neither edits the other's DDL.

**No LLM, no new dependency, one config key** (`research.experiments_dir`, T82), no env var, nothing under `execution/`. Agents build and test on fixture and temp-file stores only; the first real registration, every holdout spend and every budget amendment are the owner's, on his store, after the plan is built.

**Plan shape numbers** (development-process.md, "Plan shape"; computed from the task lines below, `uv run python scripts/team.py graph --ref <this branch>` reprints them once the file is on a branch): six tasks, no owner task; longest open chain **4** PRs (T80 → T81 → T82 → T83); depth 1: T80; depth 2: T81; depth 3: T82, T83b, T83c; depth 4: T83. Files named by more than one task in this plan: none (`research/experiment.py` is written by T82 and only read by T83). Files shared with open tasks of other plans, from `team.py graph` on `main` d2304bd (2026-10-04): `src/tradepartner/cli.py`, named by the open T67 and T84c (paper-trading, `paper` commands), T77b (data-foundation) and T90 (the lot-ledger comparison), and by T83 here. T83 adds two new command groups (`experiment`, `dataset`) that touch none of theirs, so plan-shape rule 3's disjoint-parts clause applies: whichever lands later merges `main` first. No other file here is named by an open task of any plan (`schema.py`, `registry.py`, `results.py`, `backtest_page.py`, `app.py`, `docs/README.md`, `docs/specs/backtest.md` and `tests/test_no_forbidden_imports.py` checked).

**Lanes.** T80 → T81 → T82 → T83 is the one chain (each task adds new files or edits a file the previous one left; `cli.py` is edited once, by T83). T83b and T83c start when T81 merges and run beside T82 and T83 on disjoint files: T83b in `backtest/results.py`, `dashboard/backtest_page.py` and `docs/specs/backtest.md`; T83c in a new `dashboard/research_page.py` and `dashboard/app.py`. Three windows is the useful maximum once T81 is in: T82 (then T83), T83b, T83c.

**Owner items, ordered by what they unblock:** none before the build. After T83 merges, the owner's store takes the migration at its next writing command (req 1), and the owner registers the first experiment file; after T83b, the backtest page shows N with its research share. The agreement run of the annotation pilot (protocol §10 step 6) waits for T81 and T83, never the other way round (req 12, dropped: no interim log).

## Rollback

Every change is additive. The research tables and `trial_results.n_research` stay once the migration has run (schema versions are append-only and never reverted in place); with T81 to T83c reverted they hold no rows and nothing reads them, and the backtest's N falls back to the Phase 3 computation (`family_run_count` absent, `n_research` NULL). Reverting T80 alone before any store has migrated is a plain revert. No scheduled job, no data file outside the store and no config key other than `research.experiments_dir` is added; `docs/experiments/` files are inert until registered.
